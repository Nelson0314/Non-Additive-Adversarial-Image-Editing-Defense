## DEC-021 · 原生 APA 重現：換 reward 之後把注意力項正規化回 cross-entropy 的量級

- **背景**：使用者 2026-08-12 要求「連階段二也完全照 APA 原生做法跑一次」，
  變因為階段一（原生 LoRA vs 本專案 z*/decoder）× 架構（DDIM vs BDIA），
  階段二一律走 dual-path + L∞ 球投影，**唯一替換是 reward**
  （分類器 cross-entropy → Lo et al. 式(5) 的注意力抑制損失）
- **問題**：官方 APA-GC 的 reward 是 `CE − 10·MSE(z_0, z̄_0)`，兩項同量級，
  那個 MSE 是有作用的保真煞車。注意力抑制損失是 16 層注意力圖在遮罩區內的
  L1 **總和**，量級差三個數量級——實測 `r_attn` 455–1588 對 `fid_pen`
  0.15–0.71，**比值 1000–2000 倍**，該煞車在換 reward 之後等於被關掉。
  症狀只在數值上：訓練跑得完、L∞ 球照樣綁住幅度，只是失真遠大於原文
- **決定**（使用者裁決）：把 `R_attn` 除以它自己在第 0 次迭代的絕對值，
  使該項由 −1 起步；`fidelity_lambda` **維持官方的 10.0 不動**。
  旗標 `NativeStage2Config.normalize_attn_reward`，預設開啟
- **為什麼不是直接放大 λ**：那樣要挑一個 6.6×10⁴ 量級的數字，沒有出處也
  無法對照回原文；正規化 reward 則讓官方的 λ=10 逐字保留，偏離只有一處
- **為什麼正規化常數取第 0 次迭代而非固定值**：`r_attn` 的絕對值隨影像的
  注意力質量而變（遮罩大小、主體佔比），固定常數會讓不同影像拿到不同的
  有效權重，而那個差異不會有症狀。常數整輪共用，不逐迭代重算——逐迭代
  重算會讓該項恆為 −1、梯度尺度被抹平
- **地位**：這是相對 APA 原文的**第三個有記錄偏離**（另兩個是 reward 本身
  的替換、以及不做 diffusion augmentation），論文須載明
- **同批一併修正的兩個實作偏離**（不是決策，是缺陷）：階段二的 CFG 由
  誤用的 7.5 改回官方的 1.0；反演由「完整反演到 z_T 再完整去噪」改為
  官方 APA-GC 的淺噪聲帶（50 格排程只執行前 11 格、T_a=10）。
  三批實測的 `fid_lpips`：0.51–0.82（原始）→ 0.50–0.71（修 CFG）→
  0.42–0.48（再修噪聲帶），APA 原文 Table 3 為 0.23–0.25

## DEC-025 · 2026-08-19：本輪為頻率實驗，加性 baseline 全部擱置

- **研究目標改版**（使用者於 2026-08-18 轉述指導者意見）：紋理重相位在像素
  空間上雖非加性，但它保留幅度譜、只旋轉相位，本質是頻域的重參數化，
  **不算狹義的非加性**。因此主軸由「非加性 vs 加性」改為
  **「頻域／相位方法，及其抗淨化能力」**。動機是既有防護擾動多為高頻擾動，
  會被 JPEG、resize、模糊等常見壓縮抹平
- **`mist` 的預算未與其他 baseline 對齊，待重測**：FND-055 的七張平均裡
  `mist` 的 LPIPS 0.6234、DISTS 0.1667，是紋理重相位（0.1893／0.0349）的
  3.3 倍與 4.8 倍。它跑在自己論文的原生 ε=16/255 上，與其餘條件不在同一個
  失真水位，**故「輸 mist 0/7」這個讀數不可解讀**。對齊預算之後必須重測；
  在那之前不得以該比較下任何結論
- **加性 baseline 本輪一律擱置，不進頻率實驗的報表**：`photoguard_c`／
  `mist`／`dia_r`／`add`／`apa_weak` 五者退出本輪。既有數據（`runs/s0817`）
  全部保留備查，只是不出現在這一輪的比較裡。理由：本輪要回答的是「頻域
  方法之間誰比較抗淨化」，混入未對齊預算的像素加性方法只會稀釋結論
- **新 baseline 改由頻域方法組成**，來源是 `docs/reference/SURVEY_2026-08-18_frequency.md`
- **淨化算子縮到五個**（使用者指定）：`blur`／`crop`／`jpeg`／`freqpure`／
  `gridpure`。前三個已實作；後兩個是本輪新增，且是 survey 結論 2 指出
  「針對性最強、目前完全沒測」的兩個

## DEC-026 · 2026-08-19：本輪的對照組要回答四個「會不會只是……」

FND-060／061 之後，紋理重相位的優勢有四個平庸解釋還沒被排除。本輪把每一個
都配上一個對照組並實作完成，判準是**在同一個失真上比淨化後的淨增益**。

| 平庸解釋 | 對照組 | 出處 | 狀態 |
|---|---|---|---|
| 只是頻域**加性** | DCT-Shield | arXiv:2504.17894 | 已跑（FND-058／061／062） |
| 只是**頻譜比較低頻** | BlurGuard | arXiv:2511.00143 | 已實作，待跑 |
| 只是**非加性頻域操作**這個類別 | AdvDrop | arXiv:2108.09034 | 已實作，待跑 |
| 只是**同失真的隨機相位** | `phase_rand` | Galerne TIP 2011 | 已跑（FND-061） |

- **BlurGuard 是其中最急的一個。** 它只用一個後處理（對已求得的雜訊做逐區域
  高斯模糊，模糊強度由「加了模糊雜訊之後影像的分箱功率剖面不變」這個條件學
  出來）就換到抗淨化。若本方法的優勢只來自能量落在較低頻，它會打平——那樣
  「切塊、轉相位、保留幅度」整套構造就沒有貢獻
- **AdvDrop 的方向與本方法相反**：它靠丟資訊（逐區塊逐頻格的可學量化表），
  本方法一點能量都不丟、只重排相位。它也修正了新穎性主張——「非加性的頻域
  操作」不是首創
- **三者的實作都由公開原始碼逐行對照**，不是照摘要寫。過程中查到四項摘要層級
  看不到、且照抄會量錯的事實，全部由測試釘住（見各模組 docstring）
- **BlurGuard 的遮罩必須由 SAM 產生**，本專案不提供替代分割；`segment_anything`
  與檢查點在遠端到位之前跑不了它

**2026-08-19 追加第四個 baseline：DiffusionGuard**（arXiv:2410.05694, ICLR 2025）。
它不回答上表的任何一個「會不會只是」，而是補另一個缺口：**現有的三個強
baseline 沒有一個是為抗淨化設計的**，而主軸已經改成抗淨化。它的新意在損失
（在最高噪聲的時間步上最大化 UNet 噪聲預測的範數），不在參數化，故本專案把
損失獨立出來，可以配上任何參數化包括相位臂。

**它是移植不是重現**：原文的威脅模型是 inpainting，9 通道 UNet 讓影像與噪聲
各佔一組通道；img2img 下影像只能經 SDEdit 的起始 latent 以 `√ᾱ_{t₀}` 加權
混入（strength 0.7 時是 0.287），且 mask-augmentation 這個主要新意之一完全
沒有對應物。`modified_from_paper` 由 `__post_init__` 強制為真，設 False 會拋。

## DEC-027 · 2026-08-19：加入「針對淨化最佳化」的路徑，但不是 min-max

- **現況**：本專案的抗淨化全部是**事後量測**——先做防禦，再看過了淨化剩多少。
  擾動從來不知道自己會被壓縮
- **FND-061 顯示「知道」值多少**：DCT-Shield 在 JPEG 下勝紋理重相位
  （淨增益 +0.519 對 +0.135），而它沒有做任何 min-max——它只是把擾動長在
  JPEG 的量化格點上。同一個方法在高斯模糊下淨增益只剩 +0.010，因為模糊不吃
  那套格點
- **裁決**：在 `run_param_pgd` 加一個可選的 `transform` 掛勾，讓損失可以在
  「防禦圖過一次可微分淨化算子」之後計算。作法取自 MetaCloak-JPEG
  （arXiv:2604.18537）：直通估計的 JPEG ＋ 品質由 95 降到 50 的課程排程
- **這不是 min-max，也不打算是**。淨化算子在此固定、已知、可微，我們只是在
  複合函數上做一般的 PGD。真正的 min-max 需要對淨化參數做內層最佳化，成本高
  一個數量級，且 2026-08-13 已否決
- **預設關閉**：`transform=None` 時行為與加入此參數之前逐位元相同，有回歸測試
  釘住。**回傳的永遠是防禦圖，不是被淨化過的防禦圖**——後者等於我們自己先幫
  攻擊方壓縮了一次，抗淨化的讀數會失去意義
- **待驗證**：課程排程的端點 95→50 有出處，但**衰減形狀（線性）是本專案指定**
