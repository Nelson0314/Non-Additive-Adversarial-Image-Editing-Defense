## 二、D1 不通過：等失真下比現行量化交付弱四成

把三個 transpose 點內插到 `ours_ph_q` 的錨點 **DISTS 0.0928**：

    位移 = 0.2506 + (0.2924 − 0.2506) × (0.0928 − 0.0777) / (0.1024 − 0.0777)
         = 0.2761

對上 `ours_ph_q` 在同一個失真上的 **0.4615**——**只有 60%**。

判準 D1 逐字寫著「等失真下的未淨化位移**沒有高於**同失真的量化交付點，
第 3.1 節那條預測就是錯的」。它不但沒有高於，還低了四成。

**要撤回的那條預測**：`runs/dct_phase_design/README.md` 第 3.1 節主張
`post_int` 的可行集**就是**交付集、沒有事後投影，所以現行做法為交付付出的
那 21%（未淨化位移 0.7012 → 0.5561）不該存在。**該主張已被否證。**
消掉投影損失並沒有換來位移，換到的是一個更小的可行集。

四個 DCT 點的**擋下全部是 0/10**，而 `ours_ph_n` 在更低的失真（0.0497）上是
7/10。這一格不是「差一點」，是不同的量級。

## 三、D2 不通過：配對規則分不開，「保長」那句話沒有實證支持

`zigzag`（0.0768／0.2484）與 `transpose`（0.0777／0.2506）在幾乎同一個失真上
差 **0.9%**，遠在雜訊裡。

判準 D2 逐字寫著「兩者在等失真下分不開，則『保長只有在兩軸價錢相同時才有
感知意義』這句話沒有實證支持，論文不可以那樣寫」。

這一格是**事前排好的對照組**，不是事後找的。它否證的是設計文件 1.4 節的
唯一依據——配對規則的選擇（轉置對徑向頻率相同、量化階幾乎相同）在效果上
量不出價值。**若將來重提這個參數化，不可以再用「保長在感知上有意義」當理由。**

## 四、為什麼弱——容量，不是最佳化沒收斂

三個互相一致的讀數指向同一件事：

1. **75% 的合格配對是零向量。** `ceiling.csv` 的 `zero_pair_frac = 0.7538`
   ——交付品質 0.85 的量化把大部分高頻係數清成 0，而**旋轉零向量還是零向量**。
   28 對 × 64×64 區塊名目上有 11.4 萬個自由度（Y 通道），實際帶得動的約
   四分之一。現行方法在 32×32 STFT 上是 59 萬個。
2. **L∞ 反而更高。** `dct_rot_t15` 的 L∞ 是 0.7047，而 `ours_ph_q` 在**更高**
   的 DISTS 上只有 0.3608。少數還活著的大係數被轉了很大的角度，失真集中成
   稀疏尖峰——這正是「可用的位置太少」的症狀。
3. **最佳化本身沒有壞。** θ = 1.5 的天花板（`ceiling.csv`，紋理閘、內插）
   約 0.175，實際達成 0.1024，用掉 **58%**。這與位移場那一格（用掉 6–29%
   且與隨機遊走無法區分，見 `runs/ip2p_warp/DIAGNOSIS.md`）是不同的死法：
   **那邊是最佳化沒動，這邊是動了但可行集太小。**

**隨機對照已跑完，第 3 點成立。** `dct_rot_rand11`（同角度上界 θ=1.1 的隨機
旋轉，不最佳化）是 DISTS 0.0865／位移 0.1867；把最佳化那條曲線內插到同一個
失真得 0.2655，是隨機的 **1.42 倍**。

這一格很重要，因為它把本參數化與位移場**明確區分開**：位移場那邊最佳化過的
**比同半徑隨機的還弱**（`opt_r24` 的 0.0495 對 `warp_rand` 在 radius 8 就有
0.1875），也就是最佳化沒有買到任何東西；這裡最佳化買到了 42%。
**最佳化沒有壞，是可行集太小。** 兩者的下一步不同：位移場要修更新規則，
這裡修更新規則不會有幫助。

## 五、還開著的路（都要新的理由才值得花機時）

- **提高交付品質**（QD 0.95 而不是 0.85）會讓 `zero_pair_frac` 下降、可用配對
  變多。但那同時把交付推向「攻擊方壓得比我們狠」的那一側，而現行方法的優勢
  正好在低品質壓縮——**方向相反**，要先想清楚要的是什麼。
- **不要求保長**，改成在 DCT 域做一般的受約束擾動。那就是 DCT-Shield，
  不是新方法。
- **配對跨區塊而不是區塊內**。沒有量過，但 8×8 區塊不重疊這一點正是本設計
  「失真可精確預測」的來源，跨區塊會把它拿掉。

## 六、重跑

```bash
bash scripts/dct_rotate_sweep.sh "<卡號>" "dct_rot_t08 dct_rot_t11 dct_rot_t15 dct_rot_zz11"
```

**抗淨化沒有跑，也不建議跑。** 判準 D1 寫著「不通過就不必再往抗淨化走」——
未淨化位移只有對照組的 60%、擋下 0/10，淨增益的分母在那個高度上不具鑑別力。
