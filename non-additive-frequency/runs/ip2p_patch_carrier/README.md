# 衣物載體：把補丁的支撐交集一層 ATR 人體解析的衣物類別

補丁族原本的支撐是主體遮罩的補集，含牆面與地板，於是學出來的花紋貼在牆上，
讀起來是一塊壞掉的區域。這一批把支撐再交集一層語意載體
（`src/defense/carrier_mask.py`，`mattmdjaga/segformer_b2_clothes`，ATR 18 類），
花紋止於衣物輪廓。

**只有 `task_attr_mod_color_6205` 一張。** `task_attr_mod_color_11699` 的
`person` 是登記的主體，衣服全部落在受保護核心內（合法載體 0.0000），
`PatchParam.reset` 會拋錯——那不是缺陷是事實。

設定：`image_guidance` ＋ 主體加權、`--patch-placement complement --radius 0.05`、
6000 步跑滿（六格全部 `stop_reason = max_steps`）。與
`runs/ip2p_patch_direct/ig_comp_subj` 只差載體與內容旋鈕。

## 三件量到的事

- **梯度買到 3.7 倍**：同支撐下最佳化 0.2732 對隨機 0.0737。
- **載體不額外收費**：8.61% 面積拿到 0.273，與既有的面積曲線（5% → 0.224、
  10% → 0.31，`runs/ip2p_patch_direct/`）落在同一條線上。支撐形狀不規則、
  且緊貼主體，都沒有讓效果打折。
- **交集之前與之後的面積都要看**：載體本身 0.2315，交集後只剩 0.0861，
  差的那 62% 是落在受保護主體裡的衣服（現行遮罩把右邊那尊整個算成主體）。
  兩個數分別是 `carrier_area` 與 `patch_area` 欄。

## 看圖看到的（結論不可只看讀數）

- 花紋落在左邊那尊的吊帶褲上，止於衣物輪廓，讀起來是布料而不是壞掉的區域。
- **主體遮罩的邊界從那件吊帶褲中間穿過去**，於是花紋停在一條垂直硬邊上。
  那是遮罩形狀造成的，不是載體造成的。
- **六格的編輯圖裡工具箱全部變成紅色。** 位移抬起來的來源是整片背景被染紅、
  以及花紋原封不動穿過編輯，不是主體被保住。
