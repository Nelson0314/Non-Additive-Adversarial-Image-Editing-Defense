等失真比較為什麼還沒有

一個量過的限制，以及它對這一頁的直接後果。

沒有哪一個失真指標鎖得住其他

主表那條線把十個 baseline 的原生 eps 縮到 LPIPS 都對上 colour_curve_ours 的 0.3344。錨收到 1.11× 之後，PSNR 仍然散 8.33 dB、ΔE00 散 2.96×。

本頁這一側從另一個錨量到同一件事：貼著 ΔE00 16 上限的六格，錨只有 1.009×，PSNR 散 8.98 dB。

所以「等失真」一定要指名等哪一個指標，並把其餘三個的離散度一起報。 單報一個就等於沒有錨。

PSNR 散不散，由求解時綁的約束寫在哪個域決定

PSNR = −20·log₁₀(rms)
PSNR 全距 = 20·log₁₀(rms 倍率)   ← 恆等式

所以「PSNR 散多少」與「rms 散多少」是同一個問題，逐臂對數字是重述不是 驗證。有證據力的是分界落在哪裡：

像素域 L2／L∞（PGD 撞邊界）rms 倍率 1.00–1.10，PSNR 全距 0.01–0.85 dB。 量化／DCT 係數域 1.65、1.96 → 4.36、5.87 dB。 ΔE00（本頁全部的臂）1.38–4.48 → 2.81–13.03 dB。

分界乾淨、沒有中間值。所以不在載體的形狀，在預算寫在哪個域： 係數域與知覺域的預算都不約束 pixel rms。

「求解時綁的約束」不是「事後對齊用的錨」

主表那十列是在 LPIPS 上對齊的，而它們同條件內的 PSNR 仍然一致——夾住 rms 的是 求解端的 L∞／L2，LPIPS 只是事後用來決定倍率的目標，沒有進損失、 沒有約束任何東西。

正確的說法是：求解時綁 rms 類約束的方法，同條件內 PSNR 自然一致； 綁知覺類約束的方法不會。 不是「在 rms 類的錨上對齊 PSNR 就會跟著」。

本頁的臂全部在求解時綁 ΔE00，所以它們的 PSNR 隨影像內容散開是預算種類的 必然，不是實作的缺陷。

三個臂對齊不了

inpaint_bg 與 inpaint_outside_face 的重繪區是生成 出來的，那塊像素與原圖沒有對應關係，ΔE00 與 PSNR 在那裡量的是「換掉多少畫面」 而不是「擾動多大」。

style_affine 的旋鈕是 guided filter 的 radius／ eps，不是擾動幅度。

主表那邊有一個同型的：diffvax 是前饋式，給 --eps-scale 會直接停住。這幾個只能以「無預算」那一類並列。

生成濾鏡

一、直接交付 SDEdit 的輸出會把人換掉

strength 0.35 下八張的 FaceNet 餘弦是 0.26–0.76，三張低於 0.55； 降到 0.15 仍有一張在門檻下。換人之後位移很高，但那個高不是免疫—— 分母保護的是另一個人。

失真那幾欄完全看不出這件事：style_random 的 PSNR 是 22.6–25.4， 比 colour_curve_ours 的 16.67 還「乾淨」。

生成濾鏡

二、把生成模型當濾鏡設計器，不當算圖器

只取 SDEdit 輸出的低頻色彩位移場套回原圖，結構逐像素留在原圖。 SDEdit 原始輸出的身分餘弦是 0.007–0.32，經轉移交付的是 0.66–0.97。

高斯低通與單通道 guided filter 兩個版本（style_filter、 style_filter_guided）以臉框分區求解，產物有邊界，已移除。

生成濾鏡

三、photorealism prior 才是那一族的正解

style_affine 解三通道的局部仿射色彩轉移：每個視窗解一個 3×3 矩陣加位移，使 A·x + b 最接近 SDEdit 的輸出。輸出因此被限制成 輸入的局部仿射函數——邊只能是輸入的邊乘一個係數，不會長出新結構。

單通道導引只約束了一個純量，跨通道的色彩混合仍自由；三通道一起解才是 Luan 等的 photorealism prior 與 PhotoWCT 平滑後處理在做的事。

正則化階梯上兩個方向同時變好：radius/eps 由 24/0.005 到 48/0.05， 身分由 0.679 升到 0.762，能用掉的整圖預算也從 10.44 升到 11.40。

分區預算

四、全域曲線做不到分區，除非預算改分在色度上

全域曲線的定義就是「同一個輸入色階，任何位置同一個輸出」。給臉一道緊上限， 只會讓整條曲線被那道上限綁住。

curve_dual_chroma 把預算分在色度上， 接縫在構造上不存在。代價看得到——man_00 整圖只到 ΔE00 7.44 （臉那道把整條曲線綁住了），其餘七張才到 12–16。

分區預算

五、分膚色的正確軸是色相，不是通道強度

curve_dual_chroma 的瓶頸在載體：逐 RGB 通道的曲線分不開膚色與 背景，兩者在通道值上大量重疊。

ab_warp 把映射改到 CIELAB 的 (a,b) 平面（7×7 錨點的 RBF 位移場 ＋ 單調亮度曲線）。膚色在那裡是一塊緊緻區域，臉那道上限只釘住它附近 的錨點。映射仍然全域，接縫在構造上不存在。

man_00 的可用預算由 ΔE00 7.44 升到 11.77，整體 LPIPS 也比 curve_dual_chroma 低（0.283 對 0.318）。切到「色度平面」那一層 可以看到位移場避開了哪一塊。

不碰受保護區

六、身分不是被保住，是根本沒被碰過

兩個 inpaint_* 把受保護的區域完全不送進模型，重繪只發生在 它之外，最後逐位元合成回去。kept_bitexact_frac 逐張驗證， 八張全部 1.0，身分餘弦 0.9898–1.0000。

那一欄不是 1.0 就代表合成寫錯了，它存在就是為了讓那件事有症狀。

不碰受保護區

七、inpainting 的 prompt 要描述場景，不可以描述媒材

第一版寫 vintage film photograph，模型照字面畫了一個實體相框 把臉框在中間；background 那批則只糊出灰白暈與暗角。

原因：inpainting 的 prompt 描述的是整張結果影像，媒材詞會變成物件。 這與 SDEdit 相反——SDEdit 是往既有影像上加條件，媒材詞會變成色調。

改成「主體在某個場景裡」帶季節、光線與顏色（交付用 autumn）， 加反向 prompt 擋相框與第二個人。那一批整個作廢重跑。
