# 衣物載體擴增到十二張影像

先前只有 `task_attr_mod_color_6205` 一張，「只夠決定方向、不足以支撐結論」。
這一批把同一組設定（`runs/ip2p_patch_carrier/clothes_plain`：載體 clothes、
`complement`、`image_guidance` ＋ 主體加權、6000 步跑滿）跑在十二張新影像上，
外加同幾何不最佳化的對照。

影像怎麼挑的、主體怎麼登記的見 `runs/carrier_survey/README.md` 與
`data/carrier_catalogue.yaml`。**主體名詞是看圖登記的顯著非人物件，不是從
攻擊指令推的。**

## 看圖看到的：與瑪利歐那張質上不同

`task_attr_mod_color_6205` 上的失效模式是「工具箱照樣變紅、背景整片染紅」
——攻擊成功而位移由背景撐起來。**這一批十二張沒有重演那個模式**：
編輯防禦圖的輸出是**褪色、鬼影、結構溶解**，而編輯原圖是乾淨成功的編輯。
逐張確認過，例如

- `123744`（cushion → black）：編輯原圖是黑坐墊、藝伎完整；編輯防禦圖**只剩
  黑枕頭，藝伎整個消失**。
- `202962`（bottle → brown）：編輯防禦圖霧化鬼影，**瓶子沒有變成棕色**。
- `193600`（snowy scene，位移 0.325 是較低的一格）：編輯防禦圖泛白霧化，
  但人與手機仍可辨識——**這一批裡最弱的一格**。

## 兩張不可解讀的

`obj_swap_rand_mask_401099`（pizza，倍率 0.79）與 `obj_remove_657585`
（frisbee，0.99）上，未最佳化的雜訊拿到與最佳化相同甚至更高的位移。
`657585` 的**編輯原圖本身就把畫面裡的人換成另一個人**，該影像上編輯不穩定，
讀數量到的不是防禦的效果。

## 一個候選解釋，證據不足以支撐

支撐面積 ÷ 主體核心面積在瑪利歐上是 0.18（十三張裡最小），而該張正是唯一
沒有出現輸出毀壞的。但把十三張放在一起，該比值對主體區位移的
Pearson r 只有 **0.451**（n=13），支撐面積單獨是 0.492、主體面積單獨是
−0.382。**相關性不足以支撐機制主張**，記在這裡是為了讓後續有東西可查。

## 核心不變量

在四張新影像上逐位元核對：主體核心與整條羽化帶的最大差都是 **0**，核心外
最大差 249–255。`dist_subject`（0.011–0.168）比瑪利歐那張（0.012）高，
那是 LPIPS 感受野把支撐邊緣的花紋算進加權平均，不是主體被動到。
