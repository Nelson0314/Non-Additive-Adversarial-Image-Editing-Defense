網格間距與那張臉

顏色載體上「自然」與「有效」直接對立，三個獨立量測都指向同一個根因。 換成低頻平滑的取樣位移場之後，防禦出現了——最強的設定在 25 格裡穿透 21 格，勝過顏色線的 18 格。但取捨沒有消失，只是換了一根軸： 決定產物壞不壞的是控制網格的間距，不是位移的大小。 同一張照片上，32 px 間距走 21.5 px 就把五官拉散，85 px 間距走 26.8 px 仍是一張自然的照片。自然度那一關只能由眼睛判定——三道自動門檻都已經 被最佳化鑽過，所以這一頁把圖和數字擺在一起，判斷留給你。

臉內的仿射約束是開關不是旋鈕

它把臉框內的位移壓回「該框內最佳的全域仿射」。過渡帶從 0 加寬到 64 px， 臉框位移中位只從 1.8 動到 2.0 px；把上限從 1.0 放寬到 2.0 px，位移剛好加倍； 整個拿掉，位移直接跳到 17–21 px。一個平滑的場要移動臉、又要接回背景， 那個接合就發生在框內——所以框外的過渡帶救不了它。

決定壞不壞的是間距不是幅度

同一張照片（114555）：16×16 網格（間距 32 px）走 21.5 px，五官被拉散；6×6 網格（間距 85 px）走 26.8 px，是一張自然的照片。 間距小於臉的尺度時，位移可以在一張臉之內變化，五官被相對拉扯； 間距大於臉時，整張臉落在兩三個控制點之間，被整體改形而不是被撕開。

兩層讀數要分開看

防禦圖本身

在原圖主體框的固定座標上量防禦圖相對原圖的人臉餘弦，偵測器不參與。 這一層回答「這張照片還是不是這個人」。位移場把臉推動之後，同一個座標的 裁切會取到稍微偏掉的區域——所以這個數字同時是座標錯位的上界。 旁邊的「偵測器重找臉」空白，代表防禦圖上已經偵測不到臉。

編輯輸出

攻擊者用 InstructPix2Pix 加一句從未進入最佳化的指令編輯之後， 判準三項的軟極小。分母是同一格的未防禦編輯，所以 1.0 代表防禦完全沒有作用。 指令那一項（dir_norm）照算照報但不進軟極小—— 三種寫法都在圖上被推翻過。

一個載體可能在第二層很強，只是因為第一層已經把照片毀了。 margin_64_norigid 就是這樣：21/25，而它的防禦圖上 有一張偵測不到臉。

來源

不是亂數種子——載體初始化是零場，每一次抽樣都走明確的 Generator 與明確的種子。是 GPU kernel 的非決定性： repo 裡沒有任何地方設決定性旗標，而 bf16 下的 conv 與 attention 會依當下的 負載選不同的演算法。

後果

任何「某設定是 N/25」的敘述都不可靠，跨批次的對照全部作廢。 同一批次內的比較仍然有效，因為它們共用同一次的 GPU 條件——上面那張表就是。 所以每一批都要自帶對照，不可以借別批的。

同一設定重跑不會得到同一張圖

coarse_margin_96 與 grid_06 的設定逐欄相同，兩批之間沒有改過程式。逐像素平均差 24.7 / 255， 代理身分項 0.408 對 0.502，而我對這兩張的自然度判斷相反。

來源不是亂數種子——載體初始化是零場，每一次抽樣都走明確的 Generator 與明確的種子。是 GPU kernel 的非決定性： repo 裡沒有任何地方設決定性旗標，而 bf16 下的 conv 與 attention 會依當下的 負載選不同的演算法。

總計也會變，格數低的時候尤其明顯。兩對同設定的獨立重跑： coarse_margin_96 對 grid_06 是 13 對 13；flow_08 對 obj_baseline 是 5 對 1。格數低時格子擠在門檻 附近，重跑就會翻。所以個位數格數之間沒有順序可言，而 0 對 21 這種差距是實的。

為什麼離開顏色

三個互相獨立的量測指向同一個根因：顏色載體的防禦力全部住在空間不均勻裡， 而空間不均勻正是人眼判定不自然的那個東西。

結構上的理由

全域顏色映射可逆、保住每一條邊與每一道梯度，人臉幾何原封不動， 而身分嵌入主要吃幾何與紋理。而且這類映射對擴散模型的 VAE 完全是 in-distribution——每一張調過色的照片都長這樣，防禦沒有地方可以躲。

幾何為什麼不同

「一張自然的照片」不約束那張臉長什麼形狀：觀看者手上沒有原圖。 而平滑本身正是自然的來源——低頻位移場就是鏡頭畸變、輕微透視與視差在做的事。 於是平滑性與防禦力同向，不像顏色那樣反向。

三道約束

會讓 warp 露餡的東西都寫得成約束，而且都不在臉的中央。

產生防禦圖的腳本讀到設定檔裡有任何 instruction 或 prompt 鍵就拒絕啟動，測試釘住這一條。 指令只存在於評估的設定檔，所以每一句對防禦而言都是 held-out。
