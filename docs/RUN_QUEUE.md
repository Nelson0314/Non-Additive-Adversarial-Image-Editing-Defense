# 待跑清單

**全部在 NYCU BASIC lab 跑。** 卡是多人共用的，**每卡最多 2 個 process**
（`OPERATIONS.md`，第 3 個實測會 OOM）；所有派工腳本都內建
`bash scripts/free_cards.sh --assert "${DEVS[*]}" || exit 3`，指定的卡上只要有
別人的 process 就拒絕啟動。**卡號一律由參數給。**

順序是按「能改變結論的程度」排的，不是按成本。

單價（實測）：一次編輯 **46.8 秒**，故「一個條件 × 一張影像 × 一個算子」
＝ 3 種子 × 46.8 s ≈ **140 秒**；防禦一個十張工作點 **60–85 分鐘**。

**四個算子四種結局，三列已定案、一列收尾中。**

| 算子 | 結局 | 證據 |

## 第一優先 · 三支純 CPU 探針，全部不花機時

**這三支任一支的結果都可能直接關掉一條路。** 與 `--coarsen` 那次同模式：上機前
的 CPU 檢查否證了機制，省下整批 GPU 時間。

### ~~1a. 整併設計甲的天花板~~ — **已跑，設計甲否決，並撤回一項歸因**

`scripts/dct_action_ceiling.py`，十張。等殘差 RMS 下限制在非零支撐上**反而貴
1.47–1.70 倍**，L∞ 也更高。**先前把飽和歸因於「能量被丟進原本是零的格子」是
錯的**——最便宜的定價取向恰恰把 80% 的能量放進那些格子。決定價錢的是目標頻率
的知覺代價。

而定價取向雖然在天花板上便宜 1.4 倍，**最佳化之後與均勻打平（1.00–1.03）**。
**教訓**：天花板量的是隨機方向，最佳化本來就會挑方向，隨機方向的排序不保證
轉移。

### ~~1b. 整併設計丙的天花板：保長的整數位移~~ — **不必做，已由結構事實併掉**

保長映射把係數向量送到等長的向量，兩者**必定張成一個平面**，在那個平面上它
就是一個旋轉。所以「一般的保長整數位移」買不到新的可行集，與二維旋轉是同一族。
真正的自由度只有目標方向怎麼選，而那三種都試過了（見上）。

### ~~1c. 模糊那一欄的可贏上界~~ — **已跑完，該欄結案**

`scripts/blur_band_ceiling.py`，十張、σ=1。事前判準是「最佳帶對現行工作帶的
比值低於 3 則結案」，**實測 1.54**（能量模型 2.23）。

存活率與編碼器敏感度是兩條**方向相反且都很陡**的曲線（跨帶分別差 250 倍與
三個數量級），乘積在整個頻域上是平的，極大值落在本方法**已經在用**的
0.884–1.061，只高 1.54 倍。**模糊底下沒有好的頻帶可以搬。**

證據與四項保留見 `runs/fixedpoint_blur/README.md`。

## 第二優先 · 多品質集成損失 ＋ 單一格點交付

**這是抗淨化那一側唯一還沒試、而且有文獻依據的機制。**

Shin & Song 的核心結論是**單一品質會過度特化**，而我們的 `--deliver-jpeg 0.85`
正是單一品質；症狀在資料上看得到（jpeg75 的 0.4370 掉到 jpeg30 的 0.2087）。
MBRS（ACM MM 2021）用「每個 mini-batch 隨機選真實／模擬／無失真」拿到同一個
效果。

**集成只能放在損失上，交付仍是單一格點**——放到交付上就是已否決的
`--purify-aware`（那三個變體把 JPEG 放進迴圈卻交付未壓縮的圖，量化格點的性質
完全沒拿到）。零件已實作：`purify_aware.make_eot_jpeg_transform`，**從未接上
交付**。

**事前判準**：QD 0.85 的交付下，jpeg30 的淨增益要高於現行的 0.1072，且 jpeg75
不得掉超過 10%。

**成本**：抽樣版每步成本幾乎不變（不是 K 倍前向），三個防禦點約 3.5 GPU-h，
抗淨化約 5.8 GPU-h。

## 第三優先 · 階段二擴到十張（**待裁定**）

篩選批三張已跑完（防禦 ＋ 抗淨化），四條事前判準都過：安全繩一次都沒觸發、
模糊與裁切兩欄一起升、贏過「只多跑步數」的對照、帳算得平（保守點賺 0.0327、
賠 0.0031）。等失真校正之後真正賺到的是**模糊 +9.2%、裁切 +5.6%**。

**要一起讀的兩件事**：(a) n = 3，幅度只有 5–9%；(b) **那兩欄本來就擋不下來**
——模糊 σ1 的空白地板 0.1559 是我們最好淨增益 0.0986 的 1.6 倍，裁切 10% 是
3.4 倍。

**還有一個已知缺陷要先修**：安全繩綁的是**訓練損失的增益**，不是實際位移。
兇那一點守住了 0.9495（沒觸發），但未淨化位移掉了 6.1%。要擴到十張的話應該
先把檢查換成綁在位移的代理上。

**成本**：防禦三點 ＋ 抗淨化，約 7 GPU-h。
