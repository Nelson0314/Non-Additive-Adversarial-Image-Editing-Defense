## 1. 架構總則

三條，違反其一即視為設計錯誤：

1. **`generator.py` 依能力分派，不比對條件名稱。** 新增注入位置只需提供
   `pixel_residual` / `eps_hook` / `emb_residual` / `patches_model` 其中之一。
2. **N 從 3 擴到 150 只能改一個設定值。** 任何寫死三張影像的地方都是缺陷。
3. **未校準的對象直接拋出。** 不沿用、不內插、不退回預設值。先驗實驗十次事後診斷
   都是同一句話：「一個為某個對象校準的值被沿用到另一個對象上，而且沒有症狀」。

## 3. 模組介面

### 3.1 現行介面

`ResidualModule` 以「能力」而非「型別」對外表達：

```
pixel_residual(x01)      像素側，回傳防禦圖
eps_hook(ts, steps)      去噪側，回傳逐步修改預測噪聲的 hook
emb_residual(emb)        條件側，回傳文字嵌入的殘差
patches_model()          φ 直接改動模型本身（site W 的 LoRA 走這條）
```

N1／N2 用 `pixel_residual`，完全落在現行介面內。

### 3.2 APA 移植是現行介面唯一沒處理過的組合

N3 同時需要 **LoRA（`patches_model`）** 與 **latent 注入（`eps_hook`）**，
而現行 `generator.generate()` 的檢查是「四種能力至少提供其一」，並未禁止同時提供兩種——
但也從未有模組這樣做，因此路徑未被驗證過。

**處置：新增 `CompositeResidual`**，不改 `generator.py`。

```
CompositeResidual(members=[WeightLoRA(...), LatentResidual(...)])
  pixel_residual  → None（無成員提供）
  eps_hook        → 串接各成員的 hook，依序套用
  emb_residual    → 串接
  patches_model   → 任一成員為 True 即 True
  enable/disable  → 廣播到全部成員
  parameters()    → nn.Module 自動聚合，optimize.py 不需要知道有幾個成員
```

三項必須由測試釘住的不變量：

1. 全部成員 φ = 0 時，輸出與模組不存在**逐位元相同**。
2. `disable()` 廣播到全部成員後，輸出與模組不存在**逐位元相同**。
3. 兩階段的參數群要能分開取用：階段一只更新 LoRA、階段二只更新 latent。

> **修訂紀錄。** before：第 2 條寫成「`disable()` 後 LoRA 的 forward hook 必須真正移除」。
> after：改為上述的逐位元等同。
> 原因是讀 `site_weight.py:120-127` 後確認該實作停用時 hook 仍註冊，
> 但原樣回傳同一個 `output` 物件，已經逐位元等同——原文把「性質」寫成了「手段」，
> 而那個手段並非達成該性質的必要條件。
>
> `WeightResidual.remove()` 存在的理由是另一件事：hook 註冊在 SD 的模組上，
> 模塊被垃圾回收不會移除它們，殘留的 hook 會污染共用同一個 `SDWrapper` 的
> 後續實驗。故 `CompositeResidual` 必須把 `remove()` 廣播下去，
> 這是第 4 條不變量。

4. `remove()` 廣播到全部成員，且事後 `unet` 上不殘留任何 hook。

### 3.3 `base.py` 需擴充的一項

新增 `param_groups() -> Dict[str, List[Parameter]]`，預設回傳 `{"default": list(self.parameters())}`。
`CompositeResidual` 覆寫為 `{"stage1": LoRA 參數, "stage2": latent 參數}`。
理由：APA 是兩階段，`optimize.py` 必須能只優化其中一組，而現行只有
`module.parameters()` 這一個入口。

## 4. baseline 實作層

五篇 baseline 共用同一個 PGD 骨幹，各自只提供損失。**換 baseline = 換一個損失函式**，
不是各寫一支腳本。

```
src/baselines/
  __init__.py      REGISTRY: name -> BaselineSpec
  pgd.py           PGD 骨幹（由 linf_attack.py 擴充而來）
  photoguard.py    diffusion attack（complex），targeted 到 x_target
  mist.py          textural + semantic 融合，w = 1e4
  dia.py           DDIM 軌跡（DIA-R 與 DIA-PT）
  advpaint.py      self- + cross-attention 擾亂，mask 設為全圖
  promptflare.py   cross-attention decoy（BOS token），mask 設為全圖
```

`BaselineSpec` 記錄的欄位——**這些直接來自原論文，是可查詢的事實，不得由程式猜測**：

| 欄位 | PhotoGuard-c | Mist | DIA | AdvPaint\* | PromptFlare\* |
|---|---|---|---|---|---|
| `eps_inf` | 16/255 | 17/255 | 0.05 | 0.06 | 12/255 |
| `steps` | 200 | 100 | 20 | 250 | 400 |
| `step_size` | — | 1/255 | — | 0.03 遞減 | 2/255 |
| `needs_target_image` | 是 | 是 | 否 | 否 | 否 |
| `needs_mask` | 否 | 否 | 否 | **是（本輪設全圖）** | **是（本輪設全圖）** |

`*` 標記的兩篇經本專案改寫為全圖 mask，`BaselineSpec` 需帶 `modified_from_paper=True`
與改動說明字串，報表自動在該列加註，避免報告寫成原論文設定。

**原生 ε 與 τ_LPIPS 的關係**：baseline 先以其原生 ε 訓練一次，再以射線縮放落到四個 τ 上。
故「原論文設定」與「同 τ 比較」兩組數字都有，不互相取代。

## 5. 訓練流程

五段。每段的產物落盤後即可獨立重跑後續段落。

```
段 0  前置校準
      ├─ SDEdit strength 掃描 → 選定 strength
      ├─ 編輯有效性過濾 → 選出 3 張（3 個不同子任務）
      ├─ 逐條件學習率校準 → 寫入 calibration.yaml
      └─ SDXL cross-attn 層清單與正規化常數 → 寫入 calibration.yaml
      產物：runs/<批次>/calib/

段 1  訓練（每條件每影像一次，在最大 τ = 0.35 上）
      ├─ N1/N2：Adam + plateau 停止，上限 250 步
      ├─ N3：階段一（LoRA）→ 階段二（latent），各自的步數與 lr 分開校準
      └─ B1–B5：PGD，步數照原論文
      產物：runs/<批次>/<條件>/<影像>/phi.pt + train.csv

段 2  射線縮放（無 GPU 訓練，只有前向）
      └─ 對每個 φ 沿參數射線二分搜尋，落在 τ ∈ {0.05, 0.10, 0.20, 0.35}
      產物：<影像>/phi_tau{τ}.pt + fidelity.csv（含 L∞/PSNR/SSIM/NIQE/銳利度）

段 3  淨化與編輯評測
      ├─ 對每個 (條件, τ, 淨化算子, 種子) 產生 x_def → purify → SDEdit
      ├─ φ=0 的同淨化對照每 (影像, 淨化, 種子) 只算一次，跨條件共用
      └─ 兩個條件共用逐元素相同的評測噪聲，逐種子相減
      產物：runs/<批次>/grid.csv

段 4  產圖與報表
      └─ compare.html（主判準）、RESULTS_<批次>.md
```

**斷點續跑**：每段以 `grid.csv` 的已完成列為準，重跑時跳過已有列。
判斷「已完成」用的是產物是否存在**且**其設定雜湊與當前設定相符，不只看檔名。

**φ=0 對照的共用是硬性要求**（段 3 第二列）。它不依賴條件也不依賴 τ，
若每個條件各算一次就是 9 倍的重複計算。

## 6. 校準表的程式化

先驗實驗重複十次的缺陷是「那個值為誰校準」只寫在註解裡、程式讀不到。
本輪把它寫成程式可讀的表：

```
runs/<批次>/calib/calibration.yaml
  strength:      {value: ..., calibrated_for: "SDXL-1.0-base@1024,g=7.5,steps=50"}
  lr:
    N1:          {value: ..., calibrated_for: "site_S,g=32,SDXL@1024"}
    N2:          {...}
    N3_stage1:   {...}
    N3_stage2:   {...}
  attn_norm:     {layers: [...], calibrated_for: "SDXL-1.0-base"}
  stop_tol:      {edit_shift: 1e-4, attn_div: 1e-5}
```

讀取介面 `src/utils/calibration.py`：

```
get(key, context) -> value
  context 不符 calibrated_for 時 raise，不回傳預設值、不內插
```

**學習率不可跨條件共用**：參數量綱逐位置不同（位移像素 vs 像素值 vs latent 值），
Adam 每步位移約等於 lr，同一數值代表三種步長。先驗實測位移場與加性的校準值相差 12.5 倍。

**同一條件的不同設定不可合併統計**：例如把控制點 32 與 128 平均成一個「位移場」數字，
那個平均正好抹掉要量的效應且輸出看起來正常。處置是由執行紀錄自動比出各次執行間
真正動到的設定鍵，作為分組依據。

## 7. 執行效能設計

現行設計估 25 GPU 小時。以下七項削減，目標降到 **6–8 GPU 小時**。
括號內是預期倍率，**全部須由段 0 的實測微基準取代，不得以估計值寫進報告**。

| # | 措施 | 預期 | 說明 |
|---|---|---|---|
| 1 | **fp16 autocast**（UNet + 兩個 text encoder） | **1.8–2.5×** | V100 是 sm_70，有 fp16 tensor core、**無 bf16**。這是最大的單一槓桿，且現行程式預設 fp32（`sd.py:29`），等於完全沒用到 |
| 2 | **VAE 維持 fp32** | 無加速，為正確性 | SDXL 原生 VAE 在 fp16 下會溢位產生黑圖。**不換 fp16-fix 權重**，理由見 §7.1 |
| ~~3~~ | ~~SDPA attention~~ | **0×，撤回** | `AttnProcessor2_0` 在 torch 2.x 下**已是 diffusers 預設**，這項節省早已吃到，不得重複計算。`attention.py:113` 用 forward pre-hook 自行以 `get_attention_scores` 重算分佈，不依賴 processor，故兩者本來就相容 |
| 4 | **評測批次化**：5 個種子一批送入 UNet | 2–3× | 50 步 × 5 次 → 50 次 batch-5。CFG 使有效批次翻倍，32 GB 下需實測上限 |
| 5 | **逐條件步數照原論文 + plateau 停止** | 1.3–1.5× | 現行一律 250 步。實際上 DIA 20 步、Mist 100、PhotoGuard 200；N1/N2/N3 用停止準則，上限 250 |
| 6 | **完整淨化掃描只在 τ ∈ {0.20, 0.35}**，另兩點（0.05、0.10）只跑 identity | 1.75× | 主表評測由 4τ×7 淨化降為 2τ×7 + 2τ×1。兩個完整點都落在 N3 可達的區間內（`DESIGN` §3.2） |
| 7 | **φ=0 對照跨條件共用** | 消除 9 倍重複 | 見 §5 段 3 |

削減後的估算（**V100 單卡**）：

| 階段 | 現行 | 削減後 |
|---|---|---|
| 前置校準 | 8 h | 約 2.5 h |
| 訓練 | 5.6 h | 約 2.5 h |
| 主表評測 | 7.4 h | 約 2 h |
| 掃描組評測 | 3.2 h | 約 1 h |
| **合計** | **25 h** | **約 8 h** |

> **修訂紀錄。** before：約 6.5 h。after：約 8 h。
> 原因是原估把 SDPA 算成 1.2–1.4× 的新增節省，但它是 diffusers 在 torch 2.x 下的預設，
> 該加速已經內含在 25 h 的基線裡。撤回重複計算。

### 7.1 架構不變的稽核

使用者 2026-08-05 要求：**調整的必須限於訓練與比較方法，模型架構除非不得已否則嚴格遵照。**
逐項稽核如下。

| 改動 | 類別 | 判定 |
|---|---|---|
| SD v1.4 → **SDXL 1.0 base** | 攻擊方模型版本 | ✅ 使用者指示；SDXL 本體為 stock 權重與 stock 架構，未改動 |
| **fp16 autocast** | 數值精度，非架構 | ⚠️ 允許，但**必須在段 0 驗證 fp16 與 fp32 的結果一致性**——PGD 的梯度品質對精度敏感，若兩者結果不一致則退回 fp32 並重估耗時 |
| ~~SDXL VAE 換 `sdxl-vae-fp16-fix` 權重~~ | **換權重＝改模型** | ❌ **撤回。** 攻擊方必須是 stock SDXL。VAE 一律維持原權重、fp32 執行 |
| SDPA attention processor | 數學等價實作 | ✅ 已是預設，且 `attention.py` 的 pre-hook 不依賴它 |
| AdvPaint／PromptFlare 的 mask 設為全圖 | 方法設定，非架構 | ✅ 不得已（威脅模型為無 mask 的 SDEdit），已標 `modified_from_paper=True` |
| APA 階段二 reward 替換 | 不得已（抗編輯場景無分類器） | ✅ 理由與 before/after 已記於 `DESIGN` §4 |
| N1／N2 的 loss、射線縮放、淨化算子 | 我們自己的方法與比較方式 | ✅ 不受此約束 |
| LoRA 掛在 UNet cross-attention 線性層 | 防禦方模組 | ✅ APA 原論文即如此，且以 forward hook 實作，SD 權重張量從頭到尾未被寫入 |

**結論**：撤回一項（VAE 換權重），新增一項驗證要求（fp16 vs fp32 的等價性）。
其餘改動全部落在訓練與比較方法內。

## 7.2 硬體：V100 與 RTX 5090

| 項目 | Tesla V100-SXM2 32GB（TWCC） | RTX 5090 |
|---|---|---|
| 架構 / 計算能力 | Volta，**sm_70** | Blackwell，**sm_120** |
| 顯存 | 32 GB HBM2 | 32 GB GDDR7 |
| 顯存頻寬 | 900 GB/s | **1,792 GB/s（約 2.0×）** |
| FP16／BF16 tensor | 125 TFLOPS | **209.5 TFLOPS（約 1.68×）** |
| **bf16** | **不支援** | **支援** |
| 最低 PyTorch | cu118 即可 | **torch ≥ 2.7 + CUDA 12.8**；cu118 會以 `no kernel image is available` 直接失敗 |

**哪張快：RTX 5090，預期約 2–2.5×。** 擴散模型的 UNet 迴圈同時吃算力與頻寬，
5090 在兩者上分別是 1.68× 與 2.0×，取其混合。若 V100 上是約 8 GPU 小時，
5090 上預期 **約 3.5–4 小時**。

**5090 的三個實質好處**：

1. **bf16 可用**。這直接解掉 §7.1 那個問題——SDXL VAE 在 bf16 下不會溢位（bf16 的指數位與 fp32 相同），
   **不需要換任何權重就能全程半精度**。V100 上因為只有 fp16，VAE 必須留 fp32。
2. 單人獨占，沒有排隊，迭代快。
3. 32 GB 與 V100 相同，批次化的上限不會變差。

**5090 的三個必須先處理的問題**：

| # | 問題 | 處置 |
|---|---|---|
| 1 | **現行 TWCC 的 conda env 是 torch cu118，在 5090 上直接失敗** | 另建一個 env：torch ≥ 2.7、cu128。**不可沿用 `/work/nelson0314` 的 wacv env** |
| 2 | 兩張卡的數值行為不同（V100 fp16 vs 5090 bf16） | 同一批實驗**不可跨卡混跑**。若要換卡，整批重跑，並在 `env.json` 記錄卡別與精度 |
| 3 | 575 W TDP、消費級散熱 | 8 小時連續負載需確認散熱與電源；本輪工作量下風險低 |

**建議**：若 5090 隨時可用就用 5090，時間減半且 bf16 讓精度處理更乾淨。
**但兩張卡不可混跑同一批**——精度路徑不同，會變成無法歸因的變因。

**不採用的加速手段與理由**：

- **降解析度到 768²**：SDXL 的訓練解析度桶在 1024² 附近，768² 低於其面積，
  輸出品質會劣化。攻擊方必須是 stock 模型，把攻擊方調弱等於在防一個較弱的攻擊。
- **改用 SDXL-Turbo 或減少去噪步數到 4–8 步**：改變威脅模型。DIA 已實測步數會改變攻擊強度，
  這是要回報的敏感度變因，不是可以拿來省時間的旋鈕。
- **降種子數 5 → 3**：可省約 40% 評測時間，但 n 是本專案已知的假陽性來源
  （n = 1 曾產生 24 格假陽性）。留作備案，非預設。

## 8. SDXL 移植的具體改動點

| # | 位置 | 改動 | 風險 |
|---|---|---|---|
| 1 | `sd.py:29-39` | `StableDiffusionPipeline` → `StableDiffusionXLImg2ImgPipeline`；`dtype` 由 fp32 改為 fp16 autocast | 中 |
| 2 | `sd.py` 文字編碼 | SDXL 有**兩個** text encoder，需回傳 `prompt_embeds` 與 `pooled_prompt_embeds`，並組 `added_cond_kwargs`（`text_embeds` + `time_ids`） | **高**——`emb_residual` 的介面要決定作用在哪一個嵌入上 |
| 3 | `attention.py` | cross-attention 層清單改由 SDXL 的 UNet 掃出；只在 2× 與 4× 下採樣層 | **高**——既有正規化常數全部作廢，必須重新校準 |
| 4 | `sd.py` VAE | SDXL VAE 的 `scaling_factor` 不同，且 fp16 溢位 | 中 |
| 5 | BDIA 反演 | 排程與 σ 不同，需重新驗證來回誤差 | 中 |
| 6 | `site_latent.py` | latent 由 64×64×4 變為 128×128×4（1024² / 8） | 低 |
| 7 | `site_weight.py` | LoRA 目標層名稱與數量改變 | 低 |

第 2 與第 3 項是本輪的主要工程風險。兩者都必須在段 0 以測試釘住行為，
不得在段 1 才發現。
