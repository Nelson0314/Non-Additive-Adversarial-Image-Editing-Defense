## 1. 今天修掉的 7 個缺陷

全部只在 **GPU 的 bf16 路徑**上出現，本機 CPU 全程 fp32 測不到。段 0 是它們
的第一次曝光——這正是先跑段 0 的價值。

| # | commit | 症狀 | 根因 |
|---|---|---|---|
| 1 | `2db910d` | 段 0 `calibrate_precision_equiv` OOM | bf16 與 fp32 兩份 SDXL 同時常駐，24 GB 放不下。加 `SDWrapper.offloaded()` 先把本批權重搬到 CPU |
| 2 | `a30b63d` | `SiglipTokenizer requires protobuf` | `environment.yml` 漏列 `protobuf`／`sentencepiece`（後補 `lpips`、`blobfile`） |
| 3 | `69c6da4` | — | `Purifier('impress').available` 只檢查 `sd`，漏掉預設後端要的 `lpips` 套件。缺它會在第 285 格才炸 |
| 4 | `8106b16` | 段 0 N2 探測 `Input type (float) and bias type (c10::BFloat16)` | `piq.ContentLoss.forward` 第一行是 `self.model.to(x)`——把 VGG 轉成第一個引數的 dtype 再算第二個。**且該轉換是持久的** |
| 5 | `b2c2864` | 段 0 N3 `CalibrationMismatch` | `_probe_align_lr` 建了臨時校準表卻拿原本的 `res` 呼叫 `optim_config`；`_probe_lr` 本來就對，只有這支漏了 |
| 6 | `f07c2a8` | N3 `expected mat1 and mat2 to have the same dtype` | LoRA 的 A／B 是 fp32、骨幹是 bf16。**轉輸入不降參數精度**：φ 就是 A／B，bf16 只有 8 位尾數，降精度的症狀是「跑得完但學不動」 |
| 7 | `e3da254`／`710dd70` | `piq.ssim` 與 `jpeg_real` 的 `.numpy()` 拒收 bf16 | 同一家族。改在**邊界**一次處理，不逐個指標補 |

### 由此確立的三條明文規則（改動前先讀）

1. **`DefenseObjective` 的每一個度量都在 fp32 上算**，不論骨幹跑什麼精度，
   新增度量時輸入一律先 `.float()`。理由不只是相容：`lpips_rel` 是綁定的
   保真約束，而段 2 的射線縮放解的是**同一個 τ** 且走 fp32 的 `MetricSuite`。
   兩者在不同精度上算，訓練期滿足的 τ 與對齊期解出的 τ 就是兩個不同的量。
2. **`Purifier` 對呼叫端 dtype 中性**：`_run` 進來轉 fp32、出去轉回原 dtype。
   多數算子要經 numpy／OpenCV，那裡沒有 bfloat16。
3. **可訓練參數留 fp32，凍結骨幹走半精度**，轉的是輸入不是參數。

## 2. 依實測改掉的 3 個參數

### 2.1 `--warp-max-disp` 由 1.5 改為 8.0

段 0 回報 `covers_train_tau: false`。實測位移場可達的 LPIPS：

| `max_disp` | bird_03 | cat_02 | dog_03 | 三者最小 |
|---|---|---|---|---|
| **1.5**（程式預設） | 0.1091 | 0.2182 | 0.1544 | **0.109** |
| 5.0 | 0.3099 | 0.4946 | 0.3918 | 0.310 |
| **8.0**（採用） | 0.3914 | 0.5579 | 0.4641 | **0.391** |
| 20.0 | 0.4845 | 0.6164 | 0.5446 | 0.485 |

留在 1.5 的後果不是精度差一點，是**主表空掉**：τ=0.20 有兩張圖到不了、
τ=0.35 三張都到不了，段 2 會在那些格拋出。

量測用的是 **R**（高斯隨機位移），這不是保守起見——R 本身就是格點裡的一個
條件，必須自己達得到 τ=0.35。`max_disp` 是硬上界不是損失權重，放寬它不會
讓防禦白白變強，實際失真仍由段 2 的射線縮放固定在 τ 上。

### 2.2 `strength` 維持 0.6，不採納段 0 建議的 0.8

段 0 依 Δsiglip 挑 0.8（0.6 為 0.0265、0.8 為 0.0818）。**人眼判讀推翻它**：
在 strength 0.6 下三張圖的編輯都是徹底的語意置換。

| 影像 | prompt | 0.6 下的結果 | Δsiglip |
|---|---|---|---|
| `bird_03` | *a butterfly* | 鳥整隻變成昆蟲形體，複眼、觸角、翅膀俱全 | +0.059 |
| `cat_02` | *a dog* | 貓變成白色長毛犬，姿態毛質全換 | +0.040 |
| `dog_03` | *a cat* | 臘腸犬長出黃綠色豎瞳與鬍鬚，口鼻改成貓的 | +0.024 |

**Δsiglip 嚴重低估編輯幅度**——`dog_03` 的 +0.024 對應一次完整的物種置換。
依 `RUNBOOK` §0.4「判準以人眼為主、數值指標為輔」，維持 0.6；
`strength.recommended` 只作記錄，不驅動設定。

這同時確認了威脅模型成立：攻擊真的有效，不是在防禦一個不存在的攻擊。

### 2.3 `--shared-tokens` 由 0（BOS）改為 76（末位 PAD）——**最重要的一項**

段 1 一開跑，N1 的損失就是 `loss=1.0000`、`|g|=3e-06`，四十步不動。
L_def ＝ `1 − shared token 的注意力質量`，恆為 1 表示質量恆為 0。實測 SDXL
70 層 `attn2` 的平均 token 質量：

| token | 空 prompt（訓練用） | `"a cat"` |
|---|---|---|
| **0（BOS）** | **7.2e-06** | **5.6e-06** |
| 1 | 0.0960 | 0.2230 |
| 2 | 0.2841 | 0.1994 |
| **76（末位 PAD）** | **0.0159** | **0.0048** |

原因也量到了：**BOS 的嵌入 L2 範數是 1193，其餘 token 只有 24–37**，差 32
到 48 倍。那是 CLIP 文字編碼器的 massive-activation 現象——BOS 是個高範數的
暫存槽，不是被 attend 的對象。PromptFlare 的 `L_CA` 對 M^BOS 施力在 SD v1.x
上成立，**換到 SDXL 不成立**。

質量為零時 `1 − mass` 坐在它的**最大值**上，梯度為零。這與已移除的
`untargeted` 模式（`LOGIC_CHECK` A1）完全同型，而 A1 涵蓋先驗實驗 59 個
批次的 100%——因為「損失不動」在 log 上看起來只是「還沒開始降」。

處置有三層：

1. 改打 token 76（使用者 2026-08-06 裁決）。兩端都是索引固定且不承載語意，
   故都 prompt-free；只有末位 PAD 真的被 attend。
2. `optimize.MIN_SHARED_MASS = 1e-3`，第 0 步就檢查起點質量並拋出。門檻落在
   兩個實測值中間（7.2e-06 與 4.84e-03），相差三個數量級，不是需要調的旋鈕。
3. `shared_tokens` 補進 `RunConfig`／`loss_params()`／CLI（`9890ce1`）。
   它決定 N1 攻擊哪一格，卻原本不在 `config_hash` 裡——改了值舊格會被續跑
   判定視為完成而靜默沿用，正是 A7 點名的缺陷型態。

**修正後的實測**：`loss=0.9844`（mass 0.0156，與量到的 0.0159 吻合）、
`|g|≈2e-04`，是先前的 **70 倍**。

## 4. 待辦與已知風險

### 4.0 【最優先】`lr.N1` 必須在 token 76 的目標上重新校準——**段 0 正在重跑**

改用 token 76 之後 N1 的梯度活了（`|g|` 由 3e-06 升到 2e-04，70 倍），

### 4.1 `lr.N1` 與 `lr.N2` 落在候選格點的端點

`lr_grid` 是 0.0001／0.001／0.005／0.02／0.1。N1 挑到最小值、N2 挑到最大值，
兩者都代表「格點用完了」而不是「資料選出來的」。

程式的 docstring 已載明這個探測只跑 12 步、偏好大 lr，且過大的 lr 會在正式
訓練被 `stop_require_feasible` 揭露。**處置是看段 1 的實際軌跡**：

- N2 若在 lr=0.1 下發散或 hinge 長期無法滿足 → 該值太大。
- N1 若在 lr=0.0001 下 250 步仍幾乎不動 → 該值太小，要往下擴格點重跑段 0。

`lr.N1` 這一項今天的校準是在**壞掉的 BOS 目標**上做的（質量恆為 0），
**那個值沒有意義，必須在 token 76 上重新校準**。段 1 若顯示 N1 學得太慢，
第一件事就是重跑段 0。

### 4.2 `stop_tol.shared_mass = 0.0`

同一個原因：段 0 探測時 N1 的監看量從頭到尾沒動，`_pick_stop_tol` 因此算出 0。
容差為 0 表示平台停止實質上不會觸發，N1 會跑滿 250 步。不是錯誤，但那個值
同樣是在壞掉的目標上算的。

### 4.3 N3 的重建誤差

段 0 的對齊探測顯示 N3 在對齊**之前**的重建誤差是 LPIPS 0.7325 / PSNR 19.57 dB
（純 VAE 來回的下限是 0.1434 / 27.51 dB；差額來自 APA 走完整生成路徑）。
12 步把它壓到 0.50，正式訓練有 200 步。

**風險**：若 200 步壓不到 τ_train = 0.35 以下，N3 的保真約束在起點就不可行。
處置手段是 `--exact-inversion`（BDIA 精確反演，文件記其把 latent 來回誤差降
5 個數量級）。**先看段 1 的 N3 三格實測，不要預先開。**

## 5. 這一輪的判準（別忘了要證什麼）

| 層級 | 主張 | 判定式 |
|---|---|---|
| **主** | 非加性**抗淨化**勝過加性 | 同一 τ 下，非加性的淨化後絕對防禦效果高於全部 baseline |
| 次 | 抗編輯持平或小輸 | **兩條同時成立**：(a) ≥ 0.85 × 最佳 baseline；(b) > 同失真隨機對照 R |
| 三 | 保真受控 | 同 τ 下報**全部**指標，不挑選 |

移除 IMPRESS 之後，主張一由 **DiffPure**（強淨化）＋ **JPEG 兩點**＋
**blur 四點**的強度掃描承擔，由 `test_抗淨化仍有強淨化與強度掃描` 釘住。

`compare.html` 是**主要產出物**，每一格都必須有影像可看。判讀順序見
`RUNBOOK` §8。
