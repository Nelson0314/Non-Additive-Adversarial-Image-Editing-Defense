## 2. 不要再用 `effect_siglip` 當主判定

```
effect_siglip = SigLIP(對照側編輯, prompt) − SigLIP(防禦側編輯, prompt)
                └──── 兩張不同的圖 ────┘      └── 同一個 prompt ──┘
```

三個獨立的理由（實測依據見 `RESULTS_2026-08-08` §8、§9.2）：

1. **它把「圖變怪了」和「類別被改掉了」放進同一個數字。** 實測未防禦的輸出
   會變成塑膠或木雕質感——分數大幅移動，而那隻狗根本沒變成貓。
2. **它在平均一個雙峰變數。** 攻擊本身逐 seed 成敗不定，變異主要來自成功／
   失敗兩堆的混合比例，不是來自防禦。
3. **判準 `mean ≥ 3σ` 在它上面不可達。** 防禦效果的上限就是攻擊本身的效果量，
   而 3σ 在三張圖中有兩張超過該上限，**完美防禦也通不過**。增加 seed 無效
   （n 縮小的是 SEM，判準用的是 σ）。

仍然要報它，作為與 PhotoGuard／DIA／PromptFlare／DiffVax 的 CLIP 欄對照，
但**不可作為「防禦有沒有用」的判定**。

---

## 3. 改用：類別 margin

```
margin(y) = SigLIP(y, 目標類) − SigLIP(y, 原類)
編輯成功 := margin(y) > 0
```

**同一張圖對兩個 prompt**，畫質與風格的變化同時影響兩項而抵消。符號就是判定，
與人眼做的事一致。

| 來源 | 取法 |
|---|---|
| 目標類 | 逐格 `metrics_*.json` 的 `prompt` |
| 原類 | 同檔的 `group`（bird／cat／dog），組成 `"a {group}"` |

**跑法**（只做 SigLIP 前向，不跑 SDEdit、不佔 GPU 排程）：

```bash
python scripts/class_margin.py --batch runs/<批次>_merged \
    --images <影像…> --device cuda:0 --out runs/<批次>_margin.csv
```

### 3.1 起跑前必做的校準檢查

**原圖的 margin 必須明顯為負**（原圖就是原類）。階段一實測
−0.0713／−0.0575／−0.0613，決策邊界在零是對的。

**若某張圖的原圖 margin 為正或接近零，該影像的判定無效**，要換圖而不是
調門檻——那表示 SigLIP 對那組類別對本來就分不開。

### 3.2 兩個會靜默出錯的地方

- **對照側（`control/`）不寫 `metrics_*.json`**，其 `purify_kind` 只能落回
  目錄名。用 `purify_kind == "identity"` 篩選會**漏掉整個對照側**，而對照側
  是分母。一律用目錄名 `purify_dir`。
- **淨化算子同時作用於兩側**，故未防禦的失敗率逐算子不同（階段一：identity
  5/15、blur_2 9/15）。拿 identity 的對照去比 blur 的防禦側，會把淨化本身的
  效果算到防禦頭上。**對照要逐算子重取。**

## 4. 三層一起報，不要挑一層

階段一實測到：**同一批資料，三個判準給出三個相反的結論**
（`RESULTS_2026-08-08` §11.4）。

| 層 | 量 | 對齊 |
|---|---|---|
| 1 位移 | PSNR↓ SSIM↓ VIF_p↓ FSIM↓ LPIPS↑ MSE↑ | DAYN Table 1、DIA、PhotoGuard、AdvPaint、PromptFlare |
| 2 語意 | ΔCLIP／ΔSigLIP（連續）＋ **margin 判定** | 四篇的 CLIP 欄；判定對齊 SIFM 的 ISR 語意分支 |
| 3 感知劣化 | ΔNIQE、銳利度比 | SIFM 的 ISR 劣化分支 |

```bash
python scripts/eval_protocols.py --batch runs/<批次>_merged \
    --margin runs/<批次>_margin.csv --out runs/<批次>_protocols
```

**第 3 層特別不可省。** 階段一實測 `mist` 在聯集判準下由 4/15 跳到 13/15，
**那 9 格增量全部來自劣化分支**，且門檻提高就完全消失。少了第 3 層，
「靠把輸出弄糟撐起來的免疫」會被計入成績。

## 5. 抗淨化的判定：現況與怎麼判

```
retention        = effect(某淨化) / effect(identity)
retention_usable = (mean ≥ 3σ)          # 分母跨 seed 的均值與標準差
```

**判定本身沒有壞，壞的是它的前提。** 分母是 identity 上的效果，而階段一那個
效果落在雜訊裡，故比值不可解讀，`scripts/purify_advantage.py` 至今
**五次拒絕出表**。

> **在 identity 上先有可測的效果，是談抗淨化的前提。**
> 這與「抗淨化效果不好」是兩件不同的事，不可混用。

### 5.1 第二階段要先確認的事

**跑完段 3 之後，先只看 identity 那一格。** 若該格的防禦效果仍與零無法區分，
抗淨化就不必再算——直接去處理前提（見 §6），不要硬跑判定腳本再被拒絕一次。

### 5.2 可用的描述性作法

分母不可用時，改用 margin 的失敗數直接比，不取比值：

```
Δ(某淨化) = 該條件的編輯失敗數 − 對照的編輯失敗數      # 負值＝比不防禦更差
```

階段一的結果：N1 在 18 個算子裡 10 個更差、2 個持平、6 個更好；但 15 個樣本
下 ±1／±2 只是一兩格。**只讀 |Δ| ≥ 4 的格**——那些格全部落在「更差」，
而且恰好是 `adverse_cleaner`、`diffpure`、`crop_resize`，也就是 DIA 與
DiffVax 真正在測的三個算子。

## 6. 兩件會讓第二階段重蹈覆轍的事

### 6.1 影像選取的兩端都要設限

`editable_filter` 的門檻是 **`0.0`**，等於沒有過濾。兩端都會出問題：

| 端 | 症狀 | 階段一的例子 |
|---|---|---|
| 攻擊太弱 | 效果等於噪聲，量到的只能是雜訊 | bird_03 的攻擊效果 0.0237 = 記載的噪聲標準差 |
| 攻擊太強 | 每個 seed 都成功，該影像沒有鑑別力 | cat_02 全部條件（含未防禦）都 5/5 |

**兩端都要設限，且在段 0 的選圖階段處理**——那裡本來就會掃全部影像，成本最低。

### 6.2 inpainting 的讀出量要只在遮罩內算

`ip3` 的遮罩涵蓋率是 0.20–0.40，即攻擊只重畫兩到四成的畫面。
**對整張圖算 SigLIP，訊號會被稀釋 2.5–5 倍而噪聲不變**，讓本來就緊的判定
更不可能通過。

inpainting 的結構優勢在於「生成內容必須與未遮罩的脈絡一致」，其症狀是
**遮罩邊界的不連續**與**遮罩內容與脈絡矛盾**，不是整張圖的對齊度下降。

建議改量：只在遮罩內計算 margin，另加跨遮罩邊界的接縫不連續度。
**兩側的編輯輸出都逐格落盤，故可在既有產物上重算，不必重跑 GPU。**

`effect_siglip` 最實際的好處——判定與訓練目標終於是同一個量。
