# AdvDrop 重現（2026-08-21）

論文：Duan et al., *AdvDrop: Adversarial Attack to DNNs by Dropping Information*,
ICCV 2021（[arXiv:2108.09034](https://arxiv.org/abs/2108.09034)）。
程式碼：[github.com/RjDuan/AdvDrop](https://github.com/RjDuan/AdvDrop)。

本專案要把它當「非加性頻域」的對照組，故先在**它自己的威脅模型**上重現，
再移植到 IP2P 編輯防護。

## 資料與設定

| 項目 | 論文 | 本專案 |
|---|---|---|
| 資料 | ImageNet 2000 張，**只取已被正確分類者** | 同一條規則，200 張，來源是 HF 鏡像 `mrm8488/ImageNet1K-val`（官方 ILSVRC 需授權，token 不得入庫） |
| 前處理 | 未載 | Resize(256) → CenterCrop(224)，torchvision 慣例 |
| 目標模型 | ResNet-50 | torchvision `IMAGENET1K_V1`，實測乾淨正確率 0.781（官方 top-1 76.13%） |
| 未定向步數 | 50 | 同 |
| 定向步數 | 500 | 同 |
| `q_init` | 1（§3.1） | 同 |
| 約束 | `‖q − q_init‖∞ < ε`，ε ∈ {20, 60, 100} | 同 |
| 更新步長 | 式 (7) 是 sign 更新，**隱含 1** | **必須放大到 4–8 才重現得到**，見下 |

**論文與官方程式碼不一致**：正文寫 `q_init = 1`、ε 掃到 100（表由 1 往上長），
官方 `infod_sample.py` 的簽章預設卻是 `q_size = 10`、`factor_range = [5, 10]`、
初始值 10（由 10 往下走）。可動區間差一個數量級、方向相反。本專案兩種模式
都保留（`AdvDropSpec.bounds()`），重現用論文模式。

## 兩個未重現的欄位

### 步長：論文自己寫的更新規則達不到它報的數字

式 (7) 是 `q' = q + sign(∇q L)`，隱含步長 1。但 50 步 × 步長 1 走不到 ε=100
的區間——實測量化表平均只推到 7.86（上界 101），未定向成功率 0.325。
步長 4 → 0.960，步長 6/8 → 1.000。**必有一個未載的細節**（步長、或 α 退火
端點）。本專案把步長開放成參數並逐列記下。

ε=20 是唯一補不上的一格：約束在 q=21 就 binding，步長加到 6 反而掉到 0.835。

### JPEG-30：追了四個假設，只補回一半

| 設定 | JPEG-30 成功率 |
|---|---|
| RGB ＋ 4:2:0（PIL 預設）、步長 8 | 0.280 |
| RGB ＋ 4:4:4 | 0.320 |
| YCbCr ＋ 4:2:0 | 0.330 |
| **YCbCr ＋ 4:4:4** | **0.440** |
| YCbCr ＋ 4:4:4 ＋ 步長 12 | 0.515 |
| YCbCr ＋ 4:4:4 ＋ 步長 24 | 0.560（LPIPS 已到 0.285） |
| 論文 | **0.826** |

已排除的解釋：

- **成功率的定義**：`f(x')≠y` 與 `f(D(x'))≠f(D(x))` 兩種都試，後者只高約
  0.09（它自動扣掉「JPEG 自己就把 12% 的乾淨影像分錯」那一塊）。
- **攻擊強度不足**：同一組設定下無防禦 1.000、Bit-6 0.985–1.000 都對上了。

還沒排除的：影像尺寸、他們的「JPEG-30」是否指 libjpeg 品質 30、
以及 Shin et al. 那個 JPEG 防禦的確切實作。

空白地板（乾淨影像過 JPEG 之後被翻掉的比例）：品質 95 → 0.010、75 → 0.070、
50 → 0.100、30 → 0.120、10 → 0.430。扣掉地板後，我們的 AdvDrop 在 JPEG-30
下的淨貢獻只有 +4 個百分點。
