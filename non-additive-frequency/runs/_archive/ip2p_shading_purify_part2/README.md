# 低頻乘性明暗場的抗淨化

`runs/ip2p_shading/README.md` 結語留下的問題是：

> 「它能不能提高抗淨化，尤其是模糊與裁切那兩格，要另外跑一批才知道，
> 本檔沒有答案。」

這兩個目錄就是那一批。**只讀已存的防禦圖，不重跑防禦**
（`scripts/phase_retention.py`，派工在 `scripts/purify_shading_field.sh`）。

## 為什麼分成兩個目錄

`runs/ip2p_shading` 的十三張裡有三張（`task_env_weather_246440`、
`task_env_weather_63722`、`task_obj_add_40931`）**已經不在
`data/omniedit150`**（資料集現為 147 張）。防禦圖不入版控、資料集入版控，
兩者會分岔。第一批五個 process 各自跑滿六張、花掉一小時，才在第七張同時以
`KeyError` 中止；`phase_retention.py` 現在會在載入模型之前就把整份清單對照
資料集並一次列出缺的。

- `part1` = 先跑完的六張。
- `part2` = 補跑的四張（資料集裡還在的十張扣掉 part1 那六張）。

兩批的協定、程式與種子相同，影像集合不相交，故分析時把兩個目錄一起餵給
`retention_table.py` 即可，不會有重複的格。

六個算子、三種子。地板那一格的防禦圖就是原圖。

| 空白地板 | 0.1802 | 0.3140 | 0.0000 | 0.0000 | 0.2369 | 0.1143 |
| **淨增益** | | | | | | |

## 保留率：與相位族並排

把每一欄的淨增益除以自己的未淨化欄（**這個比值只用來讀形狀，不進任何主張**；
比值在分母塌陷時不可解讀，主讀數是上表的絕對值）：

| | 未淨化 | jpeg75 | jpeg30 | blur σ1 | blur σ2 | crop |
|---|---|---|---|---|---|---|
| 明暗場 `opt_r020`（本批） | 0.1094 | 46% | 19% | 31% | **50%** | **81%** |
| 相位族 `ours_pg_n`（`runs/ip2p_matched_headtohead`） | 0.537 | 40% | 11% | — | — | 77% |

**絕對量級差 4.9 倍，形狀卻不差。** 明暗場的未淨化位移只有相位族的五分之一，
但它在 JPEG 兩欄與裁切欄的保留比例都不低於相位族，模糊 σ=2 那一欄是 50%——
相位族在該欄的能量存活率只有 0.061（`scripts/phase_shift_heatmap.py`）。

`runs/ip2p_shading/README.md` 的判定（「作為獨立方法無望」）不因這一批改變：
它的位移在等失真下只有相位族的 22%。這一批補上的是**它的衰減形狀**，
而那個形狀與「低頻載體不受模糊與裁切影響」這個構造預期一致。

## 等失真對隨機的比較：**做不成，且不外插**

`scripts/purify_matched_table.py` 在兩個失真軸上都回報 `out_of_range`。
原因是可用列篩選（`effect(identity)` 低於三倍標準差者排除）之後，
四條曲線共有的影像只剩四張，而在那四張上兩族的失真範圍**不相交**：

| | DISTS | LPIPS |
|---|---|---|
| `opt_r010` | 0.0168 | 0.0133 |
| `opt_r020` | 0.0393 | 0.0359 |
| `rand_r010` | 0.0501 | 0.0473 |
| `rand_r020` | 0.0866 | 0.0925 |

最佳化的上界 0.0393 低於隨機的下界 0.0501。協定規定範圍外一律回報
`out_of_range`，不外插，故本批**沒有**「等失真下勝過隨機」這個讀數。

> `runs/ip2p_shading/README.md` 報的 1.62–1.65 倍是在**未淨化**那一欄、
> 用十三張的平均取得的，那組平均下 `opt_r020` 0.0390 與 `rand_r010` 0.0354
> 恰好相鄰。本批的四張共有影像是那十三張的一個偏誤子集，兩族的範圍在上面
> 分開了。兩個讀數不衝突，**但也不能互相替代**。

要補上這一格，最省的是加一個 `rand_r005`（隨機條件不做最佳化，
`run_param_pgd` 在 `if not ps` 直接返回，只花一次編輯），讓隨機那條曲線的
下界落到 0.02 以下。本批未跑。
