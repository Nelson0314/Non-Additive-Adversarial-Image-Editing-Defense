# 主線頭對頭：本方法（量化交付與否）對 DCT-Shield（論文設定與預算匹配）

> **本檔的幾何欄用的是舊參照。** 裁切／重取樣那幾欄（`crop_resize*`、
> C&R 串接 `jpeg_then_resize`）的 `effect`、空白地板與淨增益，都是以
> `LPIPS(編輯(原圖), 編輯(p(防禦圖)))` 為位移、再扣該算子那個非 0 的地板
> 算出來的。現行協定對幾何類改取 `LPIPS(編輯(p(原圖)), 編輯(p(防禦圖)))`、
> 地板由構造為 0（`docs/DECISIONS.md`「幾何類淨化算子換參照」），**兩者基準不同，
> 不可並列**。這裡的數字是記錄，原樣保留。**非幾何欄（JPEG、模糊、雜訊、
> 量化、擴散淨化等）不受影響。**

十張影像（`runs/ip2p_fair_comparison/images10.txt`），攻擊方 InstructPix2Pix，
九個淨化算子，每格三顆種子。**淨增益一律扣同影像同算子的空白地板，不用比例。**

本目錄是**數值記錄**。影像不入版控，由已記錄的參數與種子重跑。

## 十四個工作點

`ph` 是純相位、`pg` 是相位＋可學幅度增益，兩者都開加性下限 0.04。
`q` 是量化交付（`--deliver-jpeg 0.85`），`n` 是同半徑不量化，`m` 是等失真不量化。

| tag | 設定 |
|---|---|
| `ours_ph_q` / `ours_pg_q` | r = 0.9，量化交付 0.85 |
| `ours_ph_q20` / `ours_pg_q20` | r = π／2.0，量化交付 0.85（強工作點） |
| `ours_ph_n` / `ours_pg_n` | r = 0.9，不量化 |
| `ours_pg_m` | r = 2.0，不量化 |
| `dct_native` | DCT-Shield §5.4 原生，`q_alg 0.95`、`eps 1.4` |
| `dct_aj85` / `dct_aj75` | DCT-Shield §6.3 抗 JPEG，Y-only，`eps 1.0`／`0.6` |
| `dct_aj85_eps1.5` … `eps4.5` | **預算匹配消融**，`q_alg 0.85` Y-only，eps 拉高 |

**預算匹配那四個不是論文設定**（§6.3 的 eps 是 1.0），一律標「預算匹配」，
不可以拿去代表 DCT-Shield 的論文結果。

共同參數：`--loss latent_norm --steps 1000 --quantile 0 --freq-weight jpeg_luma
--freq-weight-power 0.25 --hop 8 --spectral-floor 0.04`；DCT-Shield 走它自己的
Algorithm 1 與損失，`--dct-steps 1000`。

## 三、量化交付：拿強度換存活，不是免費的改良

同半徑成對（唯一變因是量化交付）：

| 參數化 | 半徑 | 量化 | DISTS | 未淨化淨增益 | jpeg75 | 擋下 |
|---|---|---|---|---|---|---|
| 純相位 | 0.9 | 無 | 0.0497 | **0.5329** | 0.2227 | 7/10 |
| 純相位 | 0.9 | 有 | 0.0928 | 0.4657 | **0.3802** | 2/10 |
| 相位+增益 | 0.9 | 無 | 0.0813 | **0.5897** | 0.2631 | 7/10 |
| 相位+增益 | 0.9 | 有 | 0.1283 | 0.5068 | **0.4072** | 4/10 |
| 相位+增益 | 2.0 | 無 | 0.1453 | **0.6687** | 0.3594 | 8/10 |
| 相位+增益 | 2.0 | 有 | 0.1947 | 0.6273 | **0.5116** | 8/10 |

**三對全部：量化那一側未淨化更弱、失真更貴、壓縮後更強。** 換的是
未淨化的 0.04–0.08 去買 jpeg75 的 0.14–0.15。

兩個構造上的原因：可行解由連續體塌成量化格點（子集的最佳點不可能贏過母集）；
最小有效步長被量化，要讓一個係數真的改變就得跨過一整條量化邊界，到處被迫
進位使總失真上升——而那一整階的位移正是它在重壓後活下來的原因。

**內部控制**：`ours_pg_q`（DISTS 0.1283，量化）對 `ours_pg_m`（DISTS 0.1453，
不量化）——量化那一組**失真更低而 jpeg50／jpeg30 更高**（0.2635 對 0.2404、
0.1665 對 0.1364）。在方法內部，買到低品質存活的是量化交付而不是預算。

## 四、跨方法：在七軸全部更低的失真下，低品質仍然勝出

`ours_ph_q` 對 `dct_aj85`（**論文設定**）：

| | DISTS↓ | LPIPS↓ | PSNR↑ | SSIM↑ | VIFp↑ | L∞↓ | RMS↓ |
|---|---|---|---|---|---|---|---|
| `ours_ph_q` | **0.0928** | **0.4668** | **27.40** | **0.9267** | **0.3221** | **0.3608** | **0.0430** |
| `dct_aj85` | 0.1118 | 0.5530 | 24.32 | 0.8958 | 0.2658 | 0.4102 | 0.0609 |

**七項全部是本方法更不明顯**，而 jpeg50 是 0.2323 對 0.1197（1.94 倍）、
jpeg30 是 0.1072 對 0.0449（2.39 倍）；jpeg90／jpeg75 則是本方法輸
（0.82 倍／0.84 倍）。

可主張的句子：**在不高於對手的任何一項失真預算下，本方法在低品質壓縮上的
淨增益是 DCT-Shield 論文設定的 1.9–2.4 倍；在對手的設計點（q ≥ 85）則相反。**

## 五、預算匹配的對照推翻了 jpeg50 那一格（**未跑完，6/10**）

`dct_aj85_eps2.2` 的 DISTS 是 0.1962，與 `ours_pg_q20` 的 0.1947 差 0.8%，
是目前唯一的等失真對手。它跑到 6/10 影像時整批實驗被撤回。

**只用那 6 張**重算（分母是同一批影像，可比）：

| 條件 | identity | jpeg90 | jpeg75 | **jpeg50** | **jpeg30** |
|---|---|---|---|---|---|
| `ours_pg_q20` | 0.6237 | 0.5582 | **0.5051** | 0.3259 | **0.2413** |
| `dct_aj85_eps2.2` | 0.6974 | **0.6287** | 0.4879 | **0.4835** | 0.1818 |
| `dct_aj85_eps1.5` | 0.6902 | 0.5712 | 0.4809 | 0.1983 | 0.0707 |
| `dct_aj85` | 0.6671 | 0.4648 | 0.4460 | 0.1152 | 0.0376 |

四件事：

1. **jpeg50 那一格在等失真下反轉，而且不是離群值造成的**：eps2.2 在
   **6/6 張全部**贏過本方法（0.4154–0.5611 對 0.2580–0.4326），標準差
   0.0536 對 0.0661。
2. **jpeg30 仍然是本方法贏**（0.2413 對 0.1818，1.33 倍），但差距遠小於
   對論文設定的 5.4 倍。
3. **DCT-Shield 在 jpeg50 上對 eps 是單調的**：0.1152 → 0.1983 → 0.4835。
   也就是**加預算確實買得到中品質存活**。這推翻了先前由「未淨化位移隨 eps
   持平（0.7067 → 0.7166）」推出的「加預算買不到東西」——那句話只對
   未淨化那一側成立，不可外推到抗淨化。
4. 因此**「低品質壓縮的優勢與預算無關」這個主張目前只在 jpeg30 站得住**，
   jpeg50 需要看完整十張才能定案，jpeg75 是接近打平。

**證據**：`../ip2p_mainline_purify/dct_aj85_eps2.2_{color,object}.csv`（6 張）。
補完需要 4 張 × 9 算子 × 3 種子 ≈ 每格 140 秒，兩個 process 約 40 分鐘。

## 六、JPEG 以外：三個方法都沒有防禦

blur σ1 的地板是 0.1777、blur σ2 是 0.3098、crop 10% 是 0.5051、crop 15% 是
0.5812，而全體條件的淨增益分別只到 0.19／0.074／0.123／0.073。**算子自己造成
的位移是任何防禦淨增益的 1.5–8 倍**，那幾欄分得出條件高下，但都不足以擋下。

`runs/frequency_retention` 的對照指向同一件事：blur σ1 下隨機相位拿到 0.2982、
最佳化過的相位 0.3667——活下來的大部分不是最佳化的功勞。

## 七、SigLIP 擋下數與人眼判定不一致

表二的「擋下」是 SigLIP 過門檻 0.8445 的張數，是代理讀數。先前十三張的人眼
逐張判定顯示位移把「劣化」與「重畫」算成同一件事，而人眼只認後者：在
jpeg50／jpeg30 這兩格（淨增益贏 2.2–3.7 倍處）兩個方法都是 0/10 擋下，唯一
有真實擋下的是 jpeg75，而那一格本方法輸。**報告頁上的擋下欄不可當成人眼結論。**

## 八、重跑

```bash
# 防禦圖（每個工作點十張約 7 分鐘，卡號由參數給）
bash scripts/mainline_defense.sh "<卡號>" "<tag> ..."
bash scripts/mainline_matched.sh "<卡號>" "<tag> ..."   # 預算匹配那四個

# 抗淨化（每個條件約 1 小時 45 分，兩個 process；PUR 可由環境變數覆寫）
bash scripts/mainline_purify.sh "<卡號>" "<tag> ..." 
bash scripts/mainline_purify.sh "<卡號>" "floor"        # 空白地板，不可省

# 三張表與報告頁
python scripts/mainline_tables.py --defense runs/ip2p_mainline \
    --purify runs/ip2p_mainline_purify --out runs/ip2p_mainline/tables
python scripts/mainline_matrix.py --tables runs/ip2p_mainline/tables \
    --out runs/ip2p_mainline/report_matrix.html
```

**派工前一律 `bash scripts/free_cards.sh --assert "<卡號>"`**，所有派工腳本
已內建這道守門，別人的卡上有 process 就拒絕啟動（回傳 3）。
