# E31 設計規格：正對照搜尋

寫於 2026-08-02。承接 `docs/RESULTS_E29_negative.md` 的否定結果與其 §5 的
邏輯稽核。本檔取代 `docs/RESULTS_E28_chroma.md` §5 與 `docs/NEXT_SESSION.md`
（2026-08-01 版）所描述的 E30 主網格計畫——該計畫已因 E29 中止。

---

## 0. 一句話

在加性基準（site P）上，沿三個文獻指認的軸尋找**任何一個擋得下編輯的運作
點**，為整套量測裝置建立從未有過的正對照。非加性與加性的比較延後到正對照
成立之後。

---

## 1. 為什麼是這個目的

研究目標是「非加性在匹配人眼可辨失真下、於抵抗文字引導編輯上勝過加性
基準」。E29 的實測是兩臂都沒有防禦效果，而**兩個零之間的比較沒有內容**。

比這更根本的是：本專案的量測裝置（SigLIP 語意軸判準、三道保真約束、綁定者
診斷）從未在一個已知為正的樣本上被驗證過。至今 104 個 run 目錄裡沒有任何
一次觀察到防禦成功。在這種狀態下，「site C 不如 site P」與「兩者都是零」
在資料上不可分辨。

故 E31 的第一優先不是比較兩臂，而是先確認裝置能不能記錄到一個正值。

## 2. Paper survey：三個外部依據

### 2.1 E29 的否定結果已被獨立複現

*Is Perturbation-Based Image Protection Disruptive to Image Editing?*
（ICIP 2025，arXiv:2506.04394）測 PhotoGuard／Mist／Glaze，SD v1.5、五個
隨機種子，以 CLIP-S 與 PAC-S++ 的 image-text alignment 為判準。結論是保護
不阻止編輯，且**受保護影像的 prompt 對齊度反而上升**，61.82–67.79% 的影像
對齊度改善。

E29 §4.2 的 site P 為 0.1277 對未防禦的 0.1202（+0.0075），方向與量級都
落在該區間內。這使 E29 由「我們的方法失敗」升格為「已知現象的白盒複現」。

### 2.2 判準的另一半被漏掉了

*Semantic Mismatch and Perceptual Degradation*（arXiv:2512.14320）定義的
Immunization Success Rate 是一個**聯集**：

    ISR = 編輯輸出「語意不符 prompt」 OR 「明顯的感知劣化」

E25 §1.1 把判準由 `net_lpips` 改為語意軸是對的（`net_lpips` 量的是輸出
移動了多少），但只取了聯集的前半。這個取捨有後果：在 strength = 0.5 的
**全域** SDEdit 下，輸出主要由 prompt 重新生成，「語意不符」在原理上幾乎
不可達成——要達成就等於讓防禦壓過整條文字條件。文獻上真正被達成的是後半，
感知劣化；PhotoGuard 的 diffusion attack 推向灰色目標，成功的樣子正是輸出
變成糊掉的東西。**那就是 `targeted` 模式在做的事，而本專案從未跑過它。**

該文報的 baseline ISR（ε = 0.03 的 L∞ 球、100 步）：PhotoGuard-E 63–75%、
PhotoGuard-D 67–88%、SIFM 79–97%。即在合適的設定下這條線會成功。

### 2.3 領域的判準尚未收斂

2026 年 TPAMI 的 TDAE（arXiv:2512.14341）仍以 PSNR／SSIM／LPIPS **對未防禦
編輯的距離**為成功判準，即本專案 E25 與 E29 兩次判定失效的 `edit_shift`。
同期的 DANP（arXiv:2512.14333）走降低相關區域 cross-attention 的路，與本
專案的 `attn_mode="suppress"` 同一著力點。

### 2.4 預算與攻擊設定的慣例

- 失真預算：ε = 16/255 的 L∞ 球是這條線的標準。
- SDEdit 評測：PhotoGuard 用 strength 0.2／0.3。本專案用 0.5。
- 破解側（arXiv:2603.13028、2511.00143、IMPRESS、CAT）顯示即使有效的保護
  也易被淨化。這對「非加性抗淨化」是附帶價值，非本專案的必要目標。

## 3. 預算的實測修正

由 `runs/e29c_*/car_00*/defended.png` 與 `baseline_phi0.png` 實際量得
（本機，非引用文件敘述）：

| 量 | site P τ=0.10 | site C τ=0.10 | 文獻慣例 |
|---|---|---|---|
| LPIPS | 0.0856 | 0.0386 | 0.267–0.362 |
| PSNR | 29.94 dB | 29.44 dB | — |
| RMS \|δ\| | 0.0319 | 0.0337 | ε=16/255 的 PGD 近飽和時約 0.06 |
| 中位數 \|δ\| | 0.0196 | 0.0039 | — |
| L∞ | 0.373 | 0.467 | 0.063 |
| 超過 16/255 的像素比例 | 5.3% | 5.4% | 接近 100% |

**修正一項既有敘述。** `RESULTS_E29_negative.md` §5.2 與 `NEXT_SESSION.md`
§3.2 寫「失真預算比文獻低 5–8 倍」。該敘述在 LPIPS 上成立、在 RMS 上約
2 倍，但 **L∞ 反而是文獻的 6 倍**。本專案的擾動是稀疏尖峰型：95% 的像素
遠低於文獻的球，5% 遠高於。這是 `beta_linf = 0`（`objective.py` 的 L∞
hinge 關閉）的直接後果。

推論：「把預算拉到文獻區間」不是單一純量的平移。E31 必須同時記錄 LPIPS
與 RMS 兩個軸，否則與文獻的對比失真。

## 4. 判準

判準改為 ISR 式的聯集。兩者任一成立即判定為「擋下」。

### 4.1 語意失敗（沿用，不改）

沿用 E25 §1.2 的判定，逐格計算配對差
Δ = SigLIP(防禦後編輯, prompt) − SigLIP(未防禦編輯, prompt)：

    語意失敗 ⟺ mean(Δ) < 0 且 |mean(Δ)| > sd(Δ) 且 n ≥ 2

`n ≥ 2` 是必要條件（n = 1 時 sd 恆為 0，任何負值都自動成立，E25 曾因此
產生 24 格假陽性）。CLIP 不用：E25 §1.1 的 edit_effect 對照未通過。

### 4.2 感知劣化（新增）

以無參考影像品質指標量編輯輸出本身的劣化，而非它與未防禦編輯的距離：

    degrade = Q(未防禦編輯) − Q(防禦後編輯)

Q 的候選由 `pyiqa` 提供：`niqe`、`musiq`、`clipiqa`、`topiq_nr`。
**指標的選定與門檻的定值都不得憑文獻聲譽**——本專案已三次踩過這個坑
（ΔE00、NLPD、VIF）。作法沿用 E20／E28 的既有方法學：

1. 造一道**劣化階梯**：對 `runs/e29c_*/car_00*/edit_orig.png` 這類既有的
   編輯輸出施加四種已知強度的劣化——高斯模糊 σ ∈ {0.5, 1, 2, 4}、JPEG
   品質 ∈ {80, 50, 30, 10}、加性高斯雜訊 σ ∈ {0.02, 0.05, 0.10, 0.20}、
   色階量化 ∈ {64, 16, 8, 4}（四者分別是 `src/purify/ops.py` 已有的
   `gaussian_blur`、`jpeg_real`、`gaussian_noise`、`quantize_real`，不新寫）。
   四個候選指標各評一次；
2. 做人眼比對頁，由使用者判讀哪一級開始「這張圖已經不能用了」；
3. 取在該級上能與前一級分開、且對純位移不敏感的指標；門檻定在人眼判定
   的那一級。

門檻寫入 `docs/RESULTS_E31_*.md` 並記錄定錨過程，與 τ_acut = 0.04、
τ_chroma = 0.8 的處置一致。

### 4.3 兩者都要看圖

指標之間矛盾時以人眼比對頁為準（E20、E28、E29 三次先例）。每一格都產出
比對頁。

## 5. 網格

site P（加性）單臂，2 圖，12 格：

| 軸 | 值 | 理由 |
|---|---|---|
| 目標函數 | `untargeted` / `targeted`（灰圖）/ `crossattn` + `attn_mode=suppress` | 三者都已實作並有測試覆蓋；後兩者從未在真實 SD 上產過資料（E29 §5.4：59 個有記錄的 `env.json` 100% 是 `untargeted`） |
| τ_lpips | 0.10 / 0.28 | 0.10 保住與 E27–E29 的可比性；0.28 進文獻區間，用以分辨「方法無效」與「預算太小」 |
| strength | 0.5 / 0.3 | 0.5 是現行威脅模型；0.3 對齊 PhotoGuard 的 SDEdit 評測。strength 同時決定防禦訓練與攻擊，白盒下兩者必須一致，故它是格子的軸而非只是評測參數 |

共同設定沿用 E29：`guidance_scale=7.5`、`beta_linf=0`、`alpha_lpips=0`、
`margin=1.0`、`tau_acut=0.04`、`tau_chroma=0.8`、`stop_on_plateau`、
上限 150 步、SD v1.4。

> **2026-08-03 修訂：`tau_acut` 與 `tau_chroma` 兩項已被 §12 取代**，改為
> 逐預算的值。上面兩個數字保留不刪，它們是本規格撰寫時的假設，而推翻它的
> 資料在 §12。

**不改 `objective.py` 的三個既有模式。** E31 是去跑它們，不是改它們。

**`beta_linf` 維持 0**，但把擾動的 RMS 與「超過 16/255 的像素比例」寫進
`results.csv`（見 §3）。中途改約束會斷掉與 E27–E29 的對照，不做。

### 5.1 targeted 的目標影像

取 512² 的中性灰（RGB 128/255），與 PhotoGuard encoder attack 的作法一致。
`targeted` 模式的 `L_def = LPIPS(y_def, y_target)` 無 hinge——它是最小化而
非最大化，本來就有界，不需要 hinge。此點與 `untargeted` 不同，需在報告中
明確記下，因為 `margin` 對該模式不起作用。

## 8. Gate：R1 不通過就不開 R2

E29 之所以沒有變成 36 格的無效資料，是因為開跑前設了綁定者判準。E31 沿用
同一道 gate：

> **每一格的綁定者都必須是 LPIPS hinge。**

τ = 0.28 下 `local_acutance_dev`（e29c 實測 0.0185，門檻 0.04）與
`local_chroma_bias`（實測 0.6475，門檻 0.8）都可能翻上來成為綁定者。若
綁定者不是 LPIPS，那一格的實際失真預算就不是 0.28，網格會變成無效資料。

判定工具是既有的 `scripts/e27_binding_check.py`（對任意 run 目錄運作）。

不通過時的處置，依綁定者而定，**不得以放寬約束草率繞過**：

- 綁定者是 acut 或 chroma → 表示在該量級上 site P 的加性擾動已經買到了
  鈍化或色偏。這本身是一項結果（第四次「匹配失真是假的」），須先做等
  LPIPS 探針確認，再決定是放寬該道門檻還是承認 0.28 對本約束集不可達。
- 綁定者是 `color_max_dev` 之類的硬上界 → 該上界是參數化的容量，不是
  保真約束，可調。

## 9. 預期的否定結果

事先寫下，避免事後把任何結果都詮釋成正面。

1. **12 格全部不擋。** 此時「預算太小」（已含 0.28）與「strength 太高」
   （已含 0.3）兩個替代解釋都被排除，得到「白盒、stock SD、SDEdit 全域
   編輯下，加性防禦在含文獻預算與文獻 strength 的範圍內不成立」。這是可
   發表的否定結果，且非加性那一側不必再花機時。
2. **`targeted` 擋下但輸出明顯劣化。** 正對照成立。接著要處理的是定義
   問題：劣化到那個程度算不算「防禦成功」，以及在該運作點上非加性能不能
   用較低的可辨失真達成同樣的劣化——那才是原研究目標的比較。
3. **`suppress` 把注意力質量壓下去了但 SigLIP 與影像都沒動。** 表示單步
   cross-attention 上的施力傳不到採樣鏈。這不是調參能解決的，需要新的
   診斷（例如逐 timestep 量注意力質量在採樣鏈上的恢復）。
4. **τ=0.28 的格子在 gate 就被擋下。** 見 §8，該結果本身是關於約束集的
   結論，不是失敗。

## 12. 修訂（2026-08-03）：兩道次要門檻改為逐預算

本節記錄一項實驗設計的變更，以及推翻原假設的資料。原文（§5 的共同設定、
§8 的 gate）不刪改。

### 12.1 推翻原假設的量測

§8 原本預期 τ=0.28 下 `local_acutance_dev`（門檻 0.04）與 `local_chroma_bias`
（門檻 0.8）「可能翻上來成為綁定者」，並把處置留給實測。L2 的探針
（`scripts/p13_budget_probe.py`，資料在 `runs/p13_budget_probe/`）給出的答案
比預期強得多，且與防禦方法無關：

| 預算 LPIPS | 純白高斯雜訊 acut | 純白高斯雜訊 chroma | site P 解 acut | site P 解 chroma |
|---|---|---|---|---|
| 0.10 | 0.0121 | 0.2143 | 0.0232 | 0.7694 |
| 0.15 | 0.0238 | 0.3701 | **0.0440 ⚠** | **1.2526 ⚠** |
| 0.20 | **0.0414 ⚠** | 0.5867 | 0.0718 ⚠ | 1.8096 ⚠ |
| 0.28 | **0.0875 ⚠** | **1.1284 ⚠** | 0.1302 ⚠ | 2.8275 ⚠ |

關鍵是那個參照臂：**i.i.d. 白高斯雜訊、沒有任何空間結構**，是能造出來最中性
的擾動。它在 LPIPS 0.20 就超過 τ_acut、在 0.28 同時超過兩道。

也就是說現行門檻把可達的 LPIPS 上限壓在 0.15–0.20，這是門檻的性質而非最佳化
找到什麼解的性質。在該約束集下，「文獻預算下防禦會不會成立」這個問題問不出來
——R1 的 gate 會失敗，但失敗的原因與防禦無關。

原因是兩道門檻都是**絕對值**，且都在 `τ_lpips = 0.05` 的量級上定的：
τ_acut = 0.04 由 E20 以 site P 的實測（0.0089 ± 0.0030）與四臂探針定出，
τ_chroma = 0.8 由 E28 以人眼判讀色度階梯定出。預算放大 5.6 倍後，任何擾動的
局部梯度能量與色度位移都跟著放大。

### 12.2 變更

兩道次要門檻改為隨 `τ_lpips` 而定，由 `scripts/p14_budget_thresholds.py`
在每一個預算上重新定出，寫在 `runs/p14_budget_thresholds/thresholds.csv`。
E31 網格的每一格以 `--tau_acut` 與 `--tau_chroma` 傳入對應預算的值。
（`--tau_acut` 是本輪新增的 CLI 旗標；`LossConfig` 的欄位早已存在，只是
從未能由命令列指定。）

理由是這兩道門檻的職責本來就是相對的：它們不負責限制失真量——那是 τ_lpips
的事——而是**擋住最佳化去買 LPIPS 收費不足的那兩種失真**，即模糊
（E18／E19 觀察到的）與空間連貫的色偏（E27／E28 觀察到的 site C）。職責是
相對的，門檻就該是相對的。原本寫成絕對值，是因為在那之前只有一個預算。

### 12.3 定門檻的規則

沿用 E20 的多臂等 LPIPS 探針，把「預算」加成一個軸。對每一個 τ_lpips，把五個
臂（blur／noise／warp_bilinear／warp_bicubic／chroma，實作直接沿用
`scripts/p9_chroma_probe.py` 的 `make_arm` 與 `calibrate`）全部校準到該 LPIPS，
量各臂的 acut 與 chroma，再把門檻定在兩群之間：

    acut：   通過 = {noise, warp_bicubic}   擋下 = {blur, warp_bilinear}
    chroma： 通過 = {noise, warp_bicubic}   擋下 = {chroma}

臂的歸屬沿用 E20 §5.2 與 E28 §1 的既有判定，不重新裁定。

門檻在對數區間上的位置**不取幾何中點，而是沿用既有人眼定錨值所在的位置**：
先在定錨預算（0.05）上算出 τ₀ 落在 [通過側上緣, 擋下側下緣] 的哪個位置，
再在每個預算上用同一個位置取值。這樣做是為了不另立標準——τ₀ 是使用者判讀
比對頁定出來的，是此處唯一的真值，本規則只把那個判斷延伸到別的預算。

單張影像（car_00）的實測顯示 τ_chroma = 0.8 落在 pos ≈ 0.50，即幾何中點——
幾何平均在該軸上**獨立重現了 E28 的人眼定錨值**（0.802 對 0.8）。
τ_acut = 0.04 落在 pos ≈ 0.12，偏向通過側，與 E20「site P 自身的 0.0089 與
雙三次的 0.0296 都須留有餘裕」的敘述一致。兩軸的 pos 不同，故各用各的。

### 12.4 實測結果（2026-08-03，六張影像）

`runs/p14_budget_thresholds/thresholds.csv`。定錨位置：τ_acut = 0.04 落在
pos = 0.194、τ_chroma = 0.8 落在 pos = 0.756，兩者都在 [0, 1] 內。

| 預算 | τ_acut | (通過≤ / 擋下≥) | τ_chroma | (通過≤ / 擋下≥) |
|---|---|---|---|---|
| 0.05 | 0.0400 | 0.0291 / 0.1492 | 0.80 | 0.1089 / 1.5236 |
| 0.10 | 0.0598 | 0.0465 / 0.1704 | 1.30 | 0.1825 / 2.4423 |
| 0.15 | 0.0763 | 0.0624 / 0.1755 | 1.81 | 0.2526 / 3.4146 |
| 0.20 | 0.0917 | 0.0779 / 0.1803 | 2.39 | 0.3378 / 4.5043 |
| 0.28 | **0.1460** | 0.1370 / 0.1904 | **3.67** | 0.5921 / 6.6047 |

**gate 因此可以過。** p13 量到 site P 的解在 τ=0.28 是 acut 0.1302、
chroma 2.8275，兩者都在上表的門檻內（acut 用掉 89% 的餘裕）。
τ=0.28 這一臂由不可跑變成可跑。

**但 acut 軸的分離度隨預算收窄**（`runs/p14_budget_thresholds/separation.csv`，
由 `scripts/p14_separation.py` 產生）：

| 預算 | 現行歸屬的 acut 分離比 | 只用 noise 對 blur |
|---|---|---|
| 0.05 | 5.12 | 24.01 |
| 0.15 | 2.81 | 9.80 |
| 0.28 | **1.39** | 4.59 |

機制是具體的：**加性雜訊的 acut 隨振幅陡升，而幾何變形的飽和。**
由 0.05 到 0.28，`noise` 的 acut 由 0.0098 漲到 0.1370（14 倍），
`warp_bilinear` 只由 0.1492 漲到 0.1904（1.28 倍）。於是高預算下加性雜訊
本身在局部梯度能量上看起來就和模糊型失真一樣「異常」，只有真正的高斯模糊
（0.6287）還明顯分得開。chroma 軸沒有這個問題，各種歸屬下比值都維持在
11.2–18.1。

（三張影像的初測給的是 τ=0.28 → 0.1648／3.40、分離比 1.18，且看起來像
「三個臂收斂」。六張影像顯示那是樣本不足的假象——`warp_bicubic` 實為
0.1071，與 `noise` 的 0.1370 分得開。舊數字不刪除，此處記錄取代它的量測。）

這暴露了一個更一般的問題：**臂的歸屬是在 τ=0.05 上由人眼判定的**（E20 的
比對頁看的是 0.4–0.6 px 的位移），把它外推到位移數倍大的預算並不當然成立。
處置有兩種，**尚未決定，須與使用者討論**：

1. 把 acut 軸的歸屬縮到 `noise` 對 `blur`。理由是約束的職責只有一條——擋住
   買模糊——而 site S 已在死路清單上，變形臂不再是受測的參數化，只是參照。
   分離比回到 3.82–18.73。代價是門檻放寬（τ=0.28 下由 0.1648 變約 0.28）。
2. 維持現行歸屬。較保守，但 τ=0.28 的門檻只高於通過側上緣 2%，任何一張
   影像的雜訊臂略高就會被誤擋。

在決定之前，driver 用的是現行歸屬的值（較保守的那一組），不會靜默放寬。

### 12.5 這個變更可能失敗的方式

- **某個預算上兩群沒有間隔。** `pick_threshold` 此時直接拋出而非取中點：
  那表示該指標在該預算上分不出這兩群，門檻無論定在哪裡都會誤判其中一側。
  出現時該預算不可用，須在報告中列出而非降門檻繞過。
- **既有門檻不落在區間內。** `anchor_position` 此時拋出。那表示 τ₀ 本身
  已經誤判了其中一側，不可作為外推的依據，須先處理那個矛盾。
- **門檻放寬到讓兩臂不再匹配失真。** 這是本專案已踩過三次的坑。E31 的
  報告必須逐格列出 acut 與 chroma 的實測值與該預算的門檻，讓「有沒有貼著
  門檻跑」可以被檢查。
