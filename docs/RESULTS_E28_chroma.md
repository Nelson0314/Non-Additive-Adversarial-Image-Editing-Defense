**結論摘要。** E27 發現 site C 在同一個 LPIPS 下買到人眼可見的色調偏移，而
既有兩道約束構造上都擋不住。本階段找出第三道：`local_chroma_bias`，並以人眼
定出 τ = 0.8。四個「看起來理所當然」的 ΔE 候選項全部不合格，失敗的方式指出
了正確的構造——**人眼在意的是空間上連貫的色偏，不是色度誤差的量值**。

## 1. 判別：ΔE 那一族全部不合格

沿用 E20 §5.3 的等 LPIPS 判別法，五臂全部校準到 LPIPS = 0.05（n=6）：

| 指標 | 模糊 | 雜訊 | 變形-雙線性 | 變形-雙三次 | **色度** |
|---|---|---|---|---|---|
| `de76` | 1.074 | 2.594 | 1.421 | 2.082 | 2.802 |
| `de00` | 0.841 | 2.460 | 1.125 | 1.655 | 2.191 |
| `dchroma` | 0.330 | 2.443 | 0.495 | 0.730 | 2.789 |
| `local_dchroma_dev` | 0.330 | 2.443 | 0.495 | 0.730 | 2.789 |
| **`local_chroma_bias`** | 0.037 | 0.084 | 0.080 | 0.109 | **1.524** |
| `local_acutance_dev` | 0.236 | 0.010 | 0.149 | 0.029 | 0.001 |

判準一（色度 / max(雜訊, 兩個變形) > 2）與判準二（真實解 C/P > 2）：

| 指標 | 判準一 | 判準二 | |
|---|---|---|---|
| `de76` | 1.08 | 1.74 | 不通過 |
| `de00` | 0.89 | 1.22 | 不通過 |
| `dchroma` | 1.14 | 1.80 | 不通過 |
| `local_dchroma_dev` | 1.14 | 1.80 | 不通過 |
| **`local_chroma_bias`** | **13.99** | **15.87** | **通過** |

### 1.1 為什麼 ΔE 分不出來

**加性高斯雜訊的 ΔE 與明顯的色調偏移幾乎一樣高**（`dchroma` 2.44 對 2.79）。
雜訊也在每個像素上擾動 (a\*, b\*)，而 ΔE 量的正是**色度誤差的量值**。人眼對
兩者的反應差很多——使用者判讀 E27 的比對頁時看得出 site C 的色調偏移、看不出
site P 的加性擾動。

**人眼在意的是空間上連貫的色偏。** 這與 E20 的型態相同：當時 LPIPS 對模糊不
收費，也是因為它量的軸與人眼在意的軸不是同一條。**「這個指標是這一軸的標準」
不構成選用它的理由**——E20 §3.3(2) 的 NLPD 與 VIF 是同一個教訓。

### 1.2 一個實作缺陷，保留為陰性對照

`local_dchroma_dev` 與 `dchroma` 在**每一臂上數值完全相同**。原因是它逐像素
先取量值、再做區塊平均與全域平均，兩者合起來就等於全域平均——區塊結構完全
沒有作用。順序反了。

保留而不刪除：兩者數值相同這件事本身就是「先取量值再池化等於沒有池化」的
證據，刪掉會讓下一個人再推導一次。`tests/test_chroma.py::
test_逐像素取量值再池化等於沒有池化` 把它釘住。

### 1.3 正確的構造

    local_chroma_bias = mean_p ‖ mean_{i∈p} (Δa*_i, Δb*_i) ‖

**先在 32×32 區塊內對有號的色度位移取平均、再取量值。** 隨機雜訊在區塊內
相消，連貫的偏壓不會；之後才取量值，使「一處偏紅、他處偏綠」在區塊之間仍
無法互相抵銷。與 `dchroma` 的差別**只在取量值與取平均的順序**。

它對模糊只收 0.037，故不侵占鈍化約束的職責。

## 2. τ_chroma = 0.8 由人眼定錨

`scripts/p10_chroma_ladder.py` 產生一組**只有色度偏壓在變**（亮度與結構不動）
的階梯，用 site C 自己的參數化，每級以二分搜尋精確命中目標。

使用者判讀 `runs/p10_chroma_ladder/compare.html`：

> 0.3 還有 0.6 都看不出來，1.0 以上才開始有一些細微色調變化
>
> 1.0 要很仔細看才看得出來，可以直接取 0.8 或 1.0

**取 0.8 而非 1.0**：1.0 是已確認看得見的一級（即使需要仔細看），把門檻設在
該處等於允許約束放行一個可見的失真。

同一偏壓在不同影像上的 LPIPS 差很多——偏壓 4.0 時 car_00 為 0.0846、dog_00
為 0.2109，差 2.5 倍。使用者的判讀在三張圖上一致，故本階段採單一固定的 τ；
若日後出現逐圖不一致，就要改為逐圖正規化（同 E27 §5.4 記的 `max_dev` 問題）。

## 3. 新可行域的行為

以既有影像檢查（τ_chroma = 0.8、τ_acut = 0.04）：

| run | 色度通過 | 鈍化通過 | 解讀 |
|---|---|---|---|
| `e27d_P_lr0.03`（校準後的加性） | **2/2** | 2/2 | 基準可行 |
| `e27d_C_lr0.3`（校準後的色度） | **0/2** | 2/2 | 被色度擋下 |
| `e21_P_tau0.05`（25 步加性） | 6/6 | 6/6 | |
| `e23_P_s100`（100 步加性） | **4/6** | 6/6 | 兩格被擋 |
| `e21_Sbic`（變形） | **6/6** | 6/6 | 色度不罰變形 |
| `e15_S`（變形 + 模糊） | 6/6 | **0/6** | 被鈍化擋下（E20 的結果） |

**每一道約束只擋自己那一種失效，且都不循環**：site S 在色度上 6/6 通過、
site P 在鈍化上 6/6 通過。這正是 E20 §5.3 要求的性質——若一道約束會因為
「site S 是一個變形」而懲罰它，那就是循環論證。

`e23_P_s100` 有兩格被擋（最大 1.01），即**加性擾動訓練久了也會產生連貫
色偏**。約束對兩臂一視同仁，這是匹配失真所要求的，不是把基準排除。

## 4. 附帶：本機環境與一個跨機器的精度陷阱

為加速本機分析，把 `torch 2.13.0+cpu` 換成同版本的 `+cu126` build，另裝
`scikit-image`（`pyiqa` 本來就缺）。三個潛伏缺陷因此浮現：

1. 兩個測試把 CPU 影像餵給 `.to(DEV)` 的模組——先前 DEV 恰為 CPU 故沒發作。
2. 一個測試把 CUDA 張量丟給 `pytest.approx`。
3. **`torch.backends.cudnn.allow_tf32` 預設為 `True`**，Ampere 以上的卷積因此
   以約 10 bit 尾數執行。BDIA 精確反演的來回誤差由「比 DDIM 好 5 個數量級」
   退化成只好 **37 倍**。V100 沒有 TF32，故**同一份程式在不同機器上會給出
   不同精度的數字**。

第三項已改為預設關閉（`WACV_ALLOW_TF32=1` 可換回速度），精度寫入 `env.json`。
E27 在 H100 上的資料是 TF32 開啟下跑的，但它量的是 LPIPS、色度偏壓與編輯偏移，
對 1e-3 不敏感，也未使用 `--exact_inversion`，故結論不受影響。

另外 CIEDE2000 已對 `scikit-image` 交叉驗證（最大絕對差 0.0071、相對
0.016%），先前「絕對尺度未經第三方驗證」的但書撤回。

**本機不能跑主網格**：SD v1.4 光是 fp32 權重就 4.26 GB，而 RTX 2050 只有
4 GB（可用 3.46 GB）；實測峰值需 10.3 GB。算力約 H100 的 1/12。

## 5. 主網格的設定（已就緒）

四道約束的交集，全部由實測或人眼定錨：

| 約束 | τ | 來源 |
|---|---|---|
| LPIPS | 0.02 / 0.05 / 0.10 | 掃描軸 |
| 鈍化 `local_acutance_dev` | 0.04 | E20 §8.1，四個實測值夾出 |
| **色度 `local_chroma_bias`** | **0.8** | **E28 §2，人眼階梯** |
| L∞ | 關閉（`beta_linf=0`） | E13：對非加性不對等 |

其餘設定：`guidance_scale=7.5`（E26）、`alpha_lpips=0`（E27 修訂之四）、
`margin=1.0`（E27）、`stop_on_plateau`（E27）、site C lr=0.3 / site P lr=0.03
（E27 §3）、`color_max_dev=2.0`。

網格為 2 site × 3 τ × 6 圖 = 36 格。實測成本 2.5 s/step、40 s/格評測：
預期約 **2 小時**，上限 150 步用滿的最壞情況約 **4.2 小時**。

**開跑前仍須做的一件事**：以新的約束集重跑一次校準（`e27d` 那一輪是在沒有
色度約束下做的），確認 τ_lpips 仍是綁定者而非色度 hinge。若色度變成綁定者，
site C 的學習率要重新定。
