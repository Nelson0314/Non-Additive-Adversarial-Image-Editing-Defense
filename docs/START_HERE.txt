三、研究目標與主張
--------------------------------------------------------------------
白盒（攻擊方用 stock SD）、外掛模組形態下，找出非加性方法，在匹配人眼可辨
失真下勝過加性基準。

  主    非加性「更」抗淨化：淨化後的效果衰減率低於加性 baseline
  並列  防禦效果本身不輸：未淨化時的位移量不低於加性 baseline
  三    保真受控，報全部指標不挑選

**不再追求語意抵抗。** CLIP-T 掉幅照報但不作為成敗判準——四個軸全部否證
（FND-024/029/030），且 arXiv:2506.04394 獨立測到同一現象。

**判準以人眼為主、數值指標為輔。** compare.html 是主要產出物，每一格都必須
有影像可看；指標與人眼矛盾時以人眼為準並記錄。


四、內部弱 baseline（DEC-023）
--------------------------------------------------------------------
「完全原生 APA，只把 reward 換成 targeted output」。五個位置裡四個原生：

    階段一   APA 官方 LoRA（denoising MSE、AdamW 1e-4、200 步、rank=8）
    階段二   dual-path attack guidance（trajectory + step-level）
    約束     latent L-inf 球 eps_a = 0.4
    更新     L1 正規化動量 + sign，mu=0.04、N=10
    反演     DDIM，50 格排程只執行前 11 格、T_a=10、CFG=1
    reward   -||D(z_0) - y_target||^2        <- 唯一的替換

叫「弱」是因為語意抵抗接近零。**它是位置基準，不是有效的防禦。**

跑它：
    python scripts/apa_baseline.py --out runs/<批次名>         --data data/lo_aligned --images horse_00 man_00 bird_03

不給 --data 時讀 data/apa_native。--conditions 可只挑其中幾個
（apa_weak / photoguard_c / mist / dia_r）。

七、動手前必須知道的坑
--------------------------------------------------------------------
量測與方法
  * **做加性／非加性的比較時，預算指標必須先講清楚。** 2026-08-13 實測同一
    個問題在 LPIPS 與 DISTS 兩個預算軸下答案相反（勝率 10.4% 對 93.8%），
    而只有 DISTS 與人眼一致。與 FND-026 同型。
  * 未防禦的編輯必須真的成功，否則抗編輯那一欄的分母不成立。換資料集或
    prompt 後先看 edit_orig 的圖。DEC-022
  * DISTS 在 512 上會先降採樣到 256，加性與非加性的失真比較會因此翻轉。
    FND-026
  * latent 半徑不是保真約束：同一個 eps_a 在不同影像上是不同的可見失真，
    LPIPS/DISTS/SSIM 的排序都可能與人眼相反。FND-028
  * retention 的分母塌陷時不可解讀（METRICS.md 第 6 節）。
  * 任何「與原圖的距離」型 reward 在零初始化處恰為零，拿它當 DEC-021 的
    正規化常數會讓 reward 爆掉（實測 1.3e7）。clamp_min 只防除以零、
    不防「很小」。每格第一行 log 要看 reward_raw。
  * 階段二的 CFG 必須是 1.0、反演必須走淺噪聲帶（50 格排程只執行前 11 格）。
    弄錯不會報錯，只會讓失真量級整個不同。

工程
  * **本 repo 用 sparse-checkout（cone mode）。** 新增頂層目錄或新的 runs/
    子目錄前要先 `git sparse-checkout add <路徑>`，否則 git mv / git add
    會被拒絕。
  * **測試跑的期間不要改原始碼。** pytest 逐檔 import，中途改檔會讀到不一致
    的狀態，症狀是隨機幾個測試失敗而重跑就好——極容易誤判成缺陷。
  * dia_r 與 mist 必須開 use_ckpt 與 vae_ckpt，否則 OOM。
  * photoguard_c 需要 200 步/圖，實測約 1.3 分/步（4.4 小時/圖），
    要跑得排專用時段。
  * 同一個批次目錄只允許一個寫入者（.writer.lock）。要平行就用不同目錄。
  * runs/ 是唯一的證據來源，全部入版控。改 .gitignore 的 runs/ 區塊後必須用
    git status --porcelain --ignored 確認沒有結果檔被靜默排除。
