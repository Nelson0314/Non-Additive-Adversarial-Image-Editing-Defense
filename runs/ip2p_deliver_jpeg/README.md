# 量化交付：把輸出約束在 JPEG 的量化格點上

**這些數字尚未進入 `docs/RESULTS.md`**，等使用者裁定。

由 `scripts/deliver_jpeg_sweep.sh` 跑出（旗標 `--deliver-jpeg QD`）。13 張人眼
確認服從的影像，條件是現行主線 `phase_gain`（`--gain-ratio 1.0
--spectral-floor 0.04 --loss latent_norm --steps 1000 --hop 8`），與
`runs/ip2p_axis_necessity/b_pg_r20` 唯一的差別就是自壓那一步。

## 機制

DCT-Shield 抗 JPEG 的全部祕密是：它的擾動 δ **直接加在量化後的整數係數上**，
所以攻擊方以相同或更高品質重壓時，四捨五入不會把它推走。本方法的擾動是連續
值，一被重新量化就散掉。

`--deliver-jpeg QD` 做兩件事，**兩件缺一不可**：

1. 最佳化迴圈的前向 `x_def = jpeg_roundtrip_ste(render(x), QD)`（可微版，
   `round()` 反向當恆等），讓最佳化「知道」自己會被量化；
2. **交付與存檔用真實的 `jpeg_roundtrip(render(x), QD)`**，也就是**交出去的
   就是壓縮圖**。

前提是 **JPEG 幾乎冪等**：同品質重壓只改 0.02–0.17% 的係數、RMS 變化約 0.001。
交付壓縮圖等於把輸出放到量化格點上，攻擊方再壓一次接近恆等。

### 與已否決項的區別

`RESULTS.md` 有一項「針對淨化最佳化沒有改善抗淨化」（固定 JPEG75／課程排程／
多算子 EOT 三個變體全部否決）。**本項與它的差別只有一個，但那個差別是關鍵：
交付什麼。**

| | 最佳化時看到 JPEG | **交付什麼** | 狀態 |
|---|---|---|---|
| purify-aware fixed75 | ✓ | **未壓縮的圖** | 已否決 |
| DCT-Shield | ✓ | **壓縮的圖** | 對手 |
| **本項** | ✓ | **壓縮的圖** | 本檔 |

那三個變體把 JPEG 放進迴圈了卻交付未壓縮的圖，量化格點的性質完全沒有拿到。
另外，該否決的理由「JPEG 保留率已達 97.5%，沒有空間可優化」是對著**錯的對手**
（`dct_y_e14`，`q_alg 0.95`、失真只有本方法三分之一）量的，已作廢——見
`docs/PENDING.md`。

## 一、生死判準：擾動保留率

判準（事前寫定）：自壓之後擾動在原方向上的分量若沒有明顯高於 **0.22**
（隨機擾動的基準，CPU 前向量測），這條路是死的。

| tag | QD | radius | **保留率** | 餘弦 |
|---|---|---|---|---|
| `qd85` | 0.85 | 2.0 | **0.9431** | 0.9227 |
| `qd85_r15` | 0.85 | 1.5 | **0.9313** | 0.9042 |
| `qd85_r09` | 0.85 | 0.9 | **0.9007** | — |
| `qd75` | 0.75 | 2.0 | **0.8570** | 0.8601 |
| `qd75_r15` | 0.75 | 1.5 | **0.8250** | 0.8270 |
| `qd75_r09` | 0.75 | 0.9 | **0.7592** | — |

**0.76–0.94，是隨機基準的 3.5–4.3 倍。判準通過。** 最佳化確實學會把擾動放在
量化之後還活著的位置——這一項不是「JPEG 沒吃掉東西」，隨機擾動在同一個 QD 下
只剩 0.22。

## 四、人眼判定（13 張逐張看過，`sheets/edits_jpeg75.png`）

判準：**原圖還認得出來嗎**——重畫成無關場景或整張變噪都算擋下，
單純劣化不算（`docs/GOAL.md`）。看的是**經過 jpeg75 之後**的編輯輸出。

| 條件 | 擋下 | 邊緣 | 逐張 |
|---|---|---|---|
| **量化交付 QD.85 r2.0** | **5/13** | 2 | #02 太空人→粉色團塊、#06 泳者→整片花、#10 山景→浮冰、#12 樂團→無人的紅西裝、#13 記者會→整片藍布 |
| 現行主線 | **0/13** | 1 | 全部被 jpeg75 還原 |
| DCT-Shield 抗 JPEG | **1/13** | 0 | #06 泳者→整片花 |

**人眼的差距比指標更大**（5 對 0 對 1，而淨增益只差 1.14 倍）。原因是淨增益量的
是位移，位移把「劣化」與「重畫」算成同一件事；人眼只認後者。量化交付的殘留
有相當一部分是真的重畫，不是單純變糊。

**必須寫下的反例**：#01（人與盆栽）、#04（瓶子）、#05（公仔）、#07（龍）、
#08（鐵門）五張在三個條件下都沒擋下，量化交付在那幾張只是色偏加模糊——
**它不是全面有效，只是有效的那幾張活過了 JPEG。**

## 五、四個必須寫下的保留

1. **這一批不是等失真比較。** 量化交付的工作點比 DCT-Shield 貴 83%。
   `qd85_r09` 跑完才能定案。
2. **未淨化那一側是純虧損**（等失真下位移 −21%、擋下 11→3）。這個方法把
   「未淨化的強度」換成「淨化後的存活」，是一個取捨不是免費的改良。
3. **`gridpure` 那一欄沒跑**（排程取捨），要補用 `scripts/purify_gridpure.sh`。
4. **QD 是防禦方自選的參數，對手也可以調。** 我們現在贏 jpeg30 有一部分是
   因為 DCT-Shield 的 `Q_alg = 0.85` 在品質 30 之外；同樣地，攻擊方若壓到
   低於我們的 QD，我們的格點也會失效。`qd75` 那一族就是為了看這條界線，
   但它在未淨化那側更弱（擋下 6/13 對 10/13），兩者要一起讀。
