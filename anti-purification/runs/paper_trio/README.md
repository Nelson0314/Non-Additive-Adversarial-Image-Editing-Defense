# 第二層：三篇的載體與預算 ＋ 我們的無指令目標，打 IP2P

`configs/paper_baseline_trio.json`，`scripts/paper_baseline.py --objective free`。
三張人像 × 四個臂，評估 `configs/evaluate_instruction.json`（每臂 54 列），
指令完成度 `scripts/instruction_vqa.py --edits`。

## 與第一層的關係

第一層（`runs/paper_baseline/`）在三篇**自己的**受害任務上證明載體能打穿分類器
（ReColorAdv 48/48）。這一層把**載體與預算原封不動**搬到人像上，只換損失。

換損失是刻意的，也是**給這些方法最好的機會**：純粹的原樣移植在人像上沒有定義，
ResNet-50 對不屬於 ImageNet 任何類別的人像沒有信心（乾淨 margin 只有 +0.017），
用那個損失最佳化等於在雜訊上下降。`docs/reference/BIBLIOGRAPHY.md` 明寫
「換損失是消融，要分開列」——兩層就是分開列的兩層。

## 這一層最重要的發現：同一個預算，換損失就換一種產物

`trio_recoloradv_paper` 與第一層的 `recoloradv_paper` **載體、解析度、ε 全部相同**，
只有損失不同。第一層是乾淨的自然照片（ΔE00 5.86、LPIPS 0.207），這一層是滿臉
洋紅斑點（ΔE00 11.74、LPIPS 0.443）。

原因在損失的形狀：**C&W margin 在翻過決策邊界之後飽和**（`clamp_min(−kappa)`），
最佳化就停了，預算沒用完；本專案的 `enc`／`cond`／`id` 沒有飽和點，會一直推到
ε 的邊界，而 3D 查表在色彩空間裡有足夠的自由度做出逐色格的跳變，於是出現斑點。

**這解釋了為什麼本專案顏色線的產物從來不像論文的圖**——不是移植錯，是
**目標函數的形狀決定了預算怎麼被用掉**。這一點先前沒有被指出過。

## 參數化本身就是自然度保證，這件事被量到了

`trio_advcf_paper`（單調分段線性 tone curve）與 `trio_ncf_paper_person`
（單一 3×3 MK 矩陣）在同一個目標函數下**都沒有壞掉**，因為它們的參數化
在構造上做不出逐色格的跳變；`trio_recoloradv_paper`（3D 查表）有那個自由度，
就用掉了。三者的穿透率**都是 1/9**。

`docs/reference/BIBLIOGRAPHY.md` 早就寫了「自然度約束本身就是方法」。這一批是
那句話的直接量測：**保住自然度的兩個參數化沒有比會壞掉的那個弱。**
