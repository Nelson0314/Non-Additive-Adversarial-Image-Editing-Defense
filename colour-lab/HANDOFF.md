## 這條線要解決什麼

現行的顏色方法在主表十二個條件裡位移排倒數，但**抗淨化是所有條件裡最好的**
（非幾何淨化保留率 1.016–1.021，其餘方法 0.31–0.86）。抗淨化來自它是**純顏色
全域映射**：同一個 RGB 三元組在整張圖得到同一個輸出，沒有空間資訊，JPEG 與模糊
洗不掉「把這種顏色換成那種顏色」這件事本身。

**要在保住這個性質的前提下，把防禦效果拉到超過現行操作點。**

## 基準：現行操作點

一切比較都對這個基準：

| | |
|---|---|
| 載體 | AdvCF 逐通道 64 段單調分段線性 tone curve，**192 參數**，`radius 5.0` |
| 結構 | 單調、固定 0 與 1 兩端、斜率界約 [1/6, 6]，與振幅無關 |
| 約束 | `deltae_cap 16.0`（實測貼著上限，中位 **15.72**） |
| 求解 | 600 步上限、`lr 0.05`、`lr_final_ratio 0.2`、`patience 30`、`resample: true` |
| 目標 | 不含指令三項：`id 1.0`／`enc 0.5`／`cond 0.0`／`sds 1.0` |
| 保真 | PSNR 17.72、LPIPS 0.3713 |
| 位移 | ip2p **0.4295**、inpaint **0.4690** |
| 圖 | `man_00` 是整張重紅偏，膚色明顯不對 |

實測的項值：`id` ≈ 0.82、`enc` ≈ 0.64、`sds` ≈ 0.0023。
**`sds` 對分數的貢獻小到幾乎等於沒開。**

## 硬約束（使用者裁定）

1. **純顏色全域映射**：同一個 RGB 三元組在整張圖得到同一個輸出。沒有座標、
   沒有遮罩、沒有局部網路。
2. **人眼自然**：不得有異常高飽和、色斑。**由參數化的結構保證**，不是損失項也不是
   事後篩選。四道自動門檻都被鑽過（NIQE、平均 ΔE00、CVaR 尾端、臉框 ΔE00）。
3. **色偏只有兩種情形會難看**（使用者原話）：**出現高飽和色**，以及**和原膚色色差
   過大**。其他還好。這兩條是本輪最重要的設計輸入。
4. **抗淨化由載體性質保證**，不得進損失、不得進選解準則，只能事後量。
5. **防禦效果是主要目標**，不為了自然砍參數量。

**已作廢：**

- **擾動低頻不是目標**。它是這類方法的預設傾向，不是訓練目標也不是判準。
  純顏色映射也推不出低頻（`∇δ = (J_T(x) − I)·∇x`，擾動會繼承原圖的邊緣與紋理），
  但那現在只是個觀察。
- **顏色類的淨化不在本專案範圍內**（灰階、灰世界、色階拉伸、CLAHE）。
  不要列為待辦，不要當成設計的限制。

## 判定門檻

主讀數是**位移** ＝ `LPIPS(編輯(原圖), 編輯(防禦圖))`。

相對**批內**對照臂，**逐格相減後取中位**（不是兩邊各取中位再相減）：

- 配對差中位 **≥ 0.02** **且** 64 格裡改善 **≥ 42 格**，兩個都要滿足
- identity／JPEG30／blur σ=2 **各自驗收**

縮小規模時**照實報數字，不要自己換算門檻**。

# 最新方向（兩條線，都還沒有結論）

## 一、兩條全域上界（`bounded_cast_curve`）

硬約束三翻成兩條寫得進參數化的**全域常數上界**：

1. **輸出彩度有上界**：對 RGB 立方體上**每一個** `c`，`C*(T(c)) ≤ C_max`。
   是對整個定義域的上界，不是平均也不是分位數。
2. **膚色帶的位移有上界**：對落在膚色軌跡上的 `c`，`ΔE00(c, T(c)) ≤ d_max`。
   **有界，不是歸零。**

**為什麼常數界不會出斑塊**：先前 `skin_locus_curve` 用隨顏色變化的權重 `w(c)`，
斑塊大小是 `|∇w|·|F(c) − c|`。常數界沒有梯度，邊界上不會有跳變，**結構上不可能
產生斑塊**。

### 參數化

三組 `(1,1,64)` 張量 `theta_l`／`theta_a`／`theta_b`，共 **192 參數**（與基準同量）。
控制點經 `tanh/√3` 映入單位球，再用非負、總和為 1 的 cubic B-spline 權重插值：

```
T(c) = Lab⁻¹( P₀(L(c)) + ρ(L(c))·z(L(c)) ),   ‖z‖₂ ≤ 1
```

`P₀` 是固定暖色色盤，`ρ` 是解析構造的安全半徑。**樣條用 L（亮度）索引。**
色域安全半徑由 Lab→RGB 導數界推導，**沒有輸出 clamp、沒有投影、沒有界限損失**，
`project()` 是空操作。膚色帶是固定暖色軌跡周圍 **8 Lab 半徑的管帶**，
用 `ΔE00 ≤ (3/√2)‖ΔLab‖₂` 配置剩餘位移半徑。

### 兩條界互相牽制

彩度壓低，膚色就被迫位移更多（膚色本來就有彩度）：

| C_max | 12 | 16 | 20 | 24 | 28 | 32 | 40 | 48 | 64 |
|---|---|---|---|---|---|---|---|---|---|
| 最小可行 d_max | 55 | 47 | 40 | 32 | 24 | **17** | 17 | 17 | 17 |

**`C_max` 到 32 以上 `d_min` 就飽和在 17**，所以 `(32,24)` 與 `(48,24)` 逐位元相同。

### 已知風險

**ΔE00 上限 16 對這個族不一定可行。** 它的 `amplitude = 0` 是固定色盤 `P₀`，
**不是原圖**，而且相對原圖的 ΔE00 不保證單調。`immunise.fit_caps` 做幅度二分時
假設零幅度可行，所以加了零幅度可行性檢查——不可行直接拋例外，不會靜默交出
違反 cap 的解。撞到的話 log 會寫清楚，屆時改 cap 或改成帶下限的形式。

## 二、換目標函數：拿掉 `id`、打開 `out`

**`out`** ＝ `readout_terms.OutputDisplacement` ＝ `LPIPS(空指令輸出(原圖),
空指令輸出(防禦圖))`，**形狀與主讀數完全一樣**，只差指令那一格是空的
（威脅模型不准看攻擊者的句子）。它以 `−w·out` 進分數、**不過 tanh**，
LPIPS 落在 [0,1] 不會飽和。顏色線的操作點一直把它的權重設成 0。

**`id` 用 `free.use_identity: false` 整個拿掉**，不是把權重設成 0——
`FreeObjective.terms` 只在 `id0 is not None` 時算 id，而 `id0` 由 `box` 決定；
權重歸零的話那條空指令取樣鏈照跑，白付一次 UNet。

拿掉 `id` 之後剩下的 `enc`（PhotoGuard encoder attack）＋ `sds`（AdvDM／Mist
擴散損失的 SDS 梯度版，值與 `diffusion` 逐位元相同）**就是主流擴散攻擊那一族**。

**`init_jitter 0.25` 是必要的不是可選的**：`id` 拿掉之後 `enc` 與 `out` 在恆等點上
都是差向量的範數，梯度精確為零，只剩 `sds` 推得動。

# 已經量到的結構事實

## 一、振幅的來源是色度，人像上色度就是膚色

把 `-ΔE00` 當目標做梯度上升（多起點取最大，**回報的是下界估計，不是證明的天花板**），
量各族在 `man_00` 上到得了多大的振幅：

| 族 | 結構限制 | 天花板 |
|---|---|---|
| AdvCF（基準，三條曲線獨立） | 無 | **21.40** |
| 共用曲線＋有界偏移 `span 0.35` | 通道差 ≤ 0.35 盒寬 | 13.82 |
| 共用曲線＋輸出色階，`span 0` | 中間調不可能偏色 | 28.90（**解落在盒角，純綠**） |
| RGB 複合曲線 `span 0`，無色階 | 三通道同一條，不可能色偏 | 12.89 |
| HSV 明度族 | 色相與飽和度**逐位元不變** | 8.42 |

`value_curve` 八張的天花板（radius 5）：8.41／13.32／21.40／9.83／22.39／14.07／
8.61／14.34。**八張裡有五張連基準的 16 都到不了。**

ΔE00 是**逐像素平均**，人像上膚色佔多數，所以「平均色差大」就等於「膚色被移走」。

**推論（已驗證）**：任何逐通道的自由度都會被花在全域色偏上，因為色偏是把 ΔE00
做大最便宜的辦法。把逐通道的輸出色階放開，天花板從 12.89 跳到 28.90，
解直接落在盒角 `lift=[0,0.25,0]`、`drop=[0.25,0,0.25]`——純綠。

| 恆等 | 5.94／7.77／7.84／6.10 | 0.1247 | −0.2278 | **0/16** |
| 抖動 `init_jitter 0.5` | 7.92／10.09／8.14／8.08 | 0.2023 | −0.2213 | **2/16** |

**第一批的 ΔE00 下限沒有達成**：下限的 λ 長到 244.7、整批沒有找到任何可行點、
跑滿 600 步，`man_00` 仍停在 5.94，而同族純 ΔE00 上升的天花板是 12.89。
原因是**起點**——曲線對 θ 整體縮放不變，把所有參數一起推大是零效果的方向，
恆等點附近的盆地很差。第二批改用抖動起點修好了下限（四張都 ≥ 7），
**振幅漲了三成，配對差幾乎沒動**（−0.228 → −0.221）。

**所以那個瑕疵不是結論的原因：結構上禁止色偏就是會掉掉這麼多位移。**

## 色彩空間裡保護膚色（`skin_locus_curve`）— 機制成立，產物不成立

`T(c) = c + w(c)·(F(c) − c)`，`w` 只吃 CIELab 的色相角與彩度（固定膚色帶，
不看影像、沒有座標、沒有遮罩）。有一條**把像素打亂後比對**的測試釘住
「輸出只由該像素的 RGB 決定」。

**解耦確實發生**：`man_00` 全圖 ΔE00 13.72、中央臉框只有 **2.46**
（無保護 24.25／48.14）；`woman_00` 全圖 21.75（高於基準）、臉框 **1.11**。

**但圖不成立**，而且兩端都不行：

| `man_00` 的保護帶 | 全圖 ΔE00 | 臉框 ΔE00 | 看起來 |
|---|---|---|---|
| 內 25°／外 55°／彩度 [3,12] | 13.72 | **2.46** | 臉緣、頭髮、脖子出**綠色斑塊** |
| 內 25°／外 80°／彩度 [3,25] | 17.21 | 14.03 | |
| 內 25°／外 120°／彩度 [3,40] | 20.77 | 33.64 | 斑塊沒了，整張臉一層**綠霧** |

2.46 完全量不到斑塊——這是第四次「數字過關但看圖不對」。

# 規範與坑

## 可重現性

- **求解端在 900 步下跨卡不可重現**：同設定同種子的全圖 ΔE00 量到
  15.93／15.70／12.51。**每一批都要自帶對照臂**，跨批比較不成立。
- 即使同卡，`resample: true` 會讓解隨「該圖在批次裡的位置」而不同。
- **編輯端逐位元可重現**：同一格在兩張卡上四格 sha256 完全相同。
  所以批內對照不依賴同卡。

## 恆等起點的零梯度陷阱（踩過三次，形式不同）

1. **`FreeObjective` 的 `enc`／`cond`** 是差向量的範數，恆等點上是零向量，
   `torch.norm` 回傳零次梯度。`id` 權重歸零就一步都不動，交付原圖。
2. **`ChannelSpanCurveParam` 的恆等落在盒角**，`min(u, 1−u) = 0` 讓逐通道偏移的
   梯度**恰為零**，`init_jitter=0` 的設定會讓整族靜默退化成一條共用曲線，不報錯。
   曲線對 θ 整體縮放不變，所以恆等也在盒心，起點移過去就有梯度。
3. **`fit_caps` 假設 `amplitude=0` 是原圖**。色盤類載體的零幅度是固定色盤，
   二分可能收斂到仍違反 cap 的解。現在會拋例外。

**新寫一個載體時，在設定檔實際會用的起點上跑一次 backward，逐個參數張量斷言
`grad.abs().max() > 0`，並寫成測試。**

## 十個實測過的坑

1. **一個 ssh 只能派一個 `nohup setsid ... &`**，串多個只有第一個會執行。
2. **`pgrep -f` 會匹配到自己的指令字串**，等待迴圈會永遠成立。判定要看真正的
   python 行程，或改用 GPU 記憶體。
3. **`paper_baseline.py` 要整個分片跑完才寫 CSV**，看進度要**數 PNG 不要數 CSV 列**。
4. **shell 裡 `rc=$?` 前面不要放 `$(date -Is)`**，命令替換會覆蓋 `$?`。
5. **Python 寫 `.sh` 會變 CRLF**，遠端 bash 直接語法錯誤。本機寫好 scp 再
   `sed -i "s/\r$//"` 與 `bash -n` 驗。
6. **CSV 的合併鍵是 `arm`**，每個臂要給不同的 `--suffix`，否則靜默互相覆蓋。
7. **`--out` 目錄存在就拒絕啟動**的腳本，log 不要寫進輸出目錄。
8. **排程不可以在派解時挑好卡、幾小時後才拿去編輯**——那時候卡多半被別人佔走，
   六次 `edit_preflight` 全部 CUDA OOM。**每一次用卡之前重新挑。**
9. **`edit_preflight.py` 預設跑資料集全部八張**，防禦圖只有四張時要給 `--images`。
10. **遠端 heredoc 裡有 `<` 會被當成重導向**，複雜腳本本機寫好 scp。
