# 美化旋鈕的組合，與固定形狀浮水印

兩組獨立的問題共用一次派工，全部只有 `task_attr_mod_color_6205`、6000 步跑滿。
基準是 `runs/ip2p_patch_carrier/clothes_plain` 的主體區位移 **0.2732**。

## A · 美化（載體 = ATR 衣服）

| 工作點 | 旋鈕 | 主體區位移 | 佔基準 |
|---|---|---|---|
| tv03 | tv 0.3 | 0.2462 | 90% |
| tv10 | tv 1.0 | 0.2064 | 76% |
| tile_tv | 平舖 64 ＋ tv 0.3 | 0.0875 | 32% |
| pretty | 平舖 64 ＋ α 0.6 ＋ tv 0.3 | 0.0518 | 19% |

**三個旋鈕強烈次可加。** 單獨用時最便宜的是 tv，組合起來卻塌得最兇；
19% 已接近同幾何隨機的 0.0265。拉圖看到機制：tv 把那塊磚壓平，再把一塊
近乎平坦的磚重複鋪滿，圖案帶的資訊所剩無幾。`tile_tv` 與 `pretty` 同時
是外觀上最自然的兩格（柔和藍綠暈染，讀起來是印花布）。

α 與平舖的交互作用是另一回事，見 `runs/ip2p_patch_smooth/`：兩者大致可乘。

## B · 固定形狀浮水印（不管美觀與失真）

支撐是 `count` 塊固定方塊、內容仍然學。`crop_safe` 擺放把候選限制在
**裁切後仍留存的中央方框**內（`--patch-crop-keep 0.8` 對上 `crop_resize0.1`
每邊裁 10%），取最靠畫面中心者。`--radius` 是加起來的面積。

| 工作點 | 幾何 | 主體區位移 |
|---|---|---|
| sq1_a04 | 4% 一塊，crop_safe | 0.2246 |
| sq2_a04 | 4% 兩塊，crop_safe | 0.2075 |
| sq1_a02 | 2% 一塊，crop_safe | 0.1694 |
| sq2_a04_rand | 4% 兩塊，不最佳化 | 0.0265 |

- **同總面積下拆成兩塊比一塊差**（0.2075 對 0.2246）。
- 梯度買到 8.5 倍（0.2246 對 0.0265）。
- 面積是主要旋鈕：2% → 0.169、4% → 0.225，與既有的 5% → 0.224 一致。

**crop_safe 的代價與收益都量到了**：同批次的 `far` 對照見
`runs/ip2p_patch_smooth/sq1_a04_far`（0.2633，即擺在中央要付 15% 的效果），
而裁切那一欄反而更差，見 `runs/ip2p_patch_carrier_purify/`。

編輯圖與衣物載體同一個失效模式：工具箱照樣變紅、背景照樣整片紅。
