# 兩個損失是互補的，不是誰取代誰

補上缺了整個 session 的對照組。設定與 `runs/ip2p_eot_matched/eb_off` **完全
相同**——同兩張影像、radius 2.5、固定步長 0.01、8000 步、同樣的 early stop、
同一顆種子——**只換 `--loss`**，故可逐欄相比。

先前唯一的對照是 1000 步的舊資料，而且步長那時還綁在半徑上
（α = radius/(steps·0.25)，即後來修掉的缺陷）。步數與步長都不同，兩邊都不能
算數。**沒有這一格，「新損失比舊損失好」在本專案裡沒有證據——不論好或壞。**

一張影像一個 process（兩張在驅動裡是依序跑的），最後合併；每張影像的最佳化
彼此獨立，故逐位元相同而牆鐘減半。**兩個 process 不可寫同一個輸出目錄**——
每張寫檔是整份重寫 `results.csv`，並行會互相截掉。

## 未淨化：舊損失三個軸同時比較好

同一張影像（`task_attr_mod_color_11699`）：

| 條件 | DISTS | PSNR | SSIM | L∞ | 位移 |
|---|---|---|---|---|---|
| `ln_fixed`（latent_norm） | **0.1487** | **22.79** | **0.910** | 0.984 | **0.6256** |
| `eb_off`（image_guidance） | 0.1572 | 22.02 | 0.879 | 0.933 | 0.5681 |

失真低 5.4%、PSNR 高 0.77 dB、SSIM 高 0.031，而位移**高 10.1%**。防禦圖的
波紋也明顯較淡，編輯結果是重畫。兩張平均同方向（DISTS 0.1550／位移 0.6897）。

## 這證實了先前那個純 CPU 探針

`runs/phase_drift_ig/` 量到新損失在 JPEG30 之後的方向存活是 0.81–0.85，主線
相位族只有 0.34。當時標明那不是等失真的比較、要保留。抗淨化的欄位證實了同
一件事：**探針量到的差異真的轉成了淨增益的差異，順序一致。** 那個探針因此
可以當上機前的預篩。

## 結論與保留

**兩個損失分工**：舊的買未淨化的強度（而且更便宜、更不醜），新的買抗淨化，
且壓縮越兇差距越大。`GOAL.md` 的主張階層把抗淨化列為主讀數、未淨化為並列
讀數，照那個階層新損失是往主讀數走的。

**n = 2**（未淨化的逐張比較 n = 1）。要下任何結論之前兩批都該擴到十張並走
等失真校正。

**直接的下一步**：把兩個損失加起來從未試過。已實作為 `--latent-norm-weight`
（舊項先除以它在乾淨影像上的值，故權重 1 真的是等權），排在夜間隊列裡。
