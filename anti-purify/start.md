# 起點：抗淨化階段

這一份是新階段的**入口文件**，寫給接手的人與新的 session。它統整到目前為止
測過什麼、什麼成立、什麼不成立、量測要怎麼做才算數、以及機器怎麼用。

前一個階段的完整程式、文件與數值記錄在 `../non-additive-frequency/`。
本檔提到的每一個結論都能在那裡查到出處，路徑逐處標出。

## 一、專案在做什麼

**威脅模型**：攻擊方拿到一張公開的照片，用**公開權重的擴散編輯模型**照著
一句指令改圖（例如「把盆栽的顏色改成粉紅色」）。防禦方在照片發布前先對它做
一次處理，交出一張看起來一樣的圖，目的是讓攻擊方的編輯失敗。

**三個限定**：

- **白盒**：防禦方已知攻擊方的模型。這是防護擾動文獻的標準假設，也是唯一
  取得到梯度的設定。
- **外掛模組**：不改動攻擊方的模型權重。架構本身不設限。
- **匹配失真**：任何強度比較都必須先把失真對齊，否則只是在比誰付得多。

**「擋下」的定義**：模型重畫成無關的場景、或整張變成噪紋，兩者都算擋下；
原圖仍認得出來、只是變糊變髒的**單純劣化不算**。

## 二、做出來的東西

### 主方法：紋理重相位（texture rephasing）

程式在 `../non-additive-frequency/src/residual/texture_rephase.py`，
參數化與最佳化迴圈在 `src/defense/param_pgd.py`。

把影像切成重疊區塊、加窗做 FFT，在頻譜上同時做三件事，再重疊相加回像素域：

```
x_def = OLA( irfft2( (|S|·e^g + a·q(ω)·s) · e^{i(φ + θ·g_b·m_ω)} ) · w ) / OLA(w²)
```

- **θ**：相位旋轉，逐（區塊, 頻格）可學。
- **g**：可學的幅度增益。相位是週期量，θ 加到 π 就繞回去；增益是唯一能拆掉
  這個天花板的旋鈕。
- **a**：頻譜加性下限。純乘性在平坦區動不了，這一項不受原圖振幅限制。

512² 上是 32×32 區塊、hop 8、Hann 窗，4225 個區塊 × 32×17 個頻格，
約 59 萬個參數（同尺寸的加性 δ 是 78.6 萬）。

**三個由構造保證的性質**：

1. `θ = 0` 時輸出**逐位元**等於原圖（float64 誤差 5.6e-16）。`÷ OLA(w²)` 是
   Griffin & Lim (1984) 的最小平方解，依賴 NOLA 而非 COLA，換窗型或換 hop
   都不會靜默破壞這個恆等。
2. 相位乘的是模長為 1 的複數，所以只旋轉不改幅度——但**可學幅度增益開啟後
   這條不再成立**，新穎性主張因此由「只旋轉相位」改寫為**頻譜重參數化**。
3. `fx = 0` 與 `fx = N/2` 兩行的閘一律取 0，否則破壞 rfft2 的共軛對稱、
   輸出不是實數。

**兩個閘**都由原圖算一次即固定，**不參與最佳化**：紋理閘（結構張量
coherence 導出，邊緣與平坦區皆為 0）與徑向頻率閘（帶通 × ITU-T T.81 Annex K
亮度量化表的知覺定價）。

### 成立的結果：JPEG 軸上等失真勝過 DCT-Shield

`runs/ip2p_matched_headtohead/`，六個算子、三種子、兩張影像，本方法與
DCT-Shield 在同一批裡跑、同一個空白地板。

**唯一協定完全對稱的那一組**（兩邊都不做量化交付）：

| | DISTS | 未淨化 | JPEG 75 | JPEG 30 |
|---|---|---|---|---|
| `ours_pg_n` | 0.0829 | 0.537 | **0.214** | **0.061** |
| `dct_native` | 0.0804 | **0.668** | 0.063 | 0.014 |

**未淨化輸、淨化後贏**——JPEG 75 是 3.4 倍、JPEG 30 是 4.3 倍。三組配對都是
這個形狀。這是目前唯一乾淨成立的主張。

另兩組配對（`ours_ph_q` / `ours_pg_q`）我方帶 `--deliver-jpeg 0.85`，
而 DCT-Shield 論文明寫免疫圖不能存成 JPEG，**協定不對稱、JPEG 欄偏我方有利**，
不可當主證據。

### 一條可以寫下來的通則

**未淨化那一欄對強度是飽和的，抗淨化那幾欄不是。** 四個方法的未淨化位移全部
停在 0.70–0.71，而 LPIPS 在兩張不相干的自然影像之間飽和於 0.772。
DCT-Shield 失真升 27% 時未淨化只升 2.9%，JPEG 30 升 84.4%。
**失真買到的是抗淨化，不是未淨化強度**，所以「降失真」與「抗淨化」直接互斥。

各欄對失真的彈性排序：`identity < crop < blur σ1 < jpeg75 < jpeg30`。

## 三、為什麼這個方向到此為止

### 模糊：構造上的死路

高斯模糊在頻域乘的是實正數 `exp(−2π²σ²f²)`，**構造上不可能改相位**——它抽掉
的是載體。實測（殘差熱圖，`scripts/phase_shift_heatmap.py`）：模糊 σ=1 之後
擾動的能量存活率只剩 **0.169**，σ=2 剩 **0.061**。

要活過模糊只能把預算放在低頻，而低頻有兩個獨立的阻礙：

1. **人眼在低頻的敏感度高一個數量級**（r=0.15 對 r=0.9）。同樣的旋轉放在低頻
   付出的可見失真高得多。
2. **低頻帶著區塊的位置與結構**，動它在重疊相加之後會產生接縫。

實測開放低頻（`r_min` 由 0.12 降到 0.02，`runs/ip2p_weighted_lowfreq/`）：
等失真下位移由 0.707 掉到 0.601。**不是不能動，是太貴。**

### 平坦區：振幅為零的死結

相位旋轉是**乘法**：`|ΔS| = |S| · 2|sin(θ/2)|`。θ 只透過 `2|sin(θ/2)|` 進來，
最大是 2，所以一個係數能被推動的距離**上限是它自己振幅的兩倍**。

實測（盆栽人、通帶內平均 `|S|`）：最平的 40 個區塊是 0.000298，最有紋理的
40 個是 0.049733，**差 167 倍**。前者 θ = π 的推動上限是 0.000595，
在 0–1 的像素值域上**不到一個 8-bit 量化階**（1/255 = 0.0039），
存成 PNG 就被四捨五入掉。

幅度增益也救不了——它同樣是乘法，`e^g · 0` 還是 0。加性下限是唯一的出路：
它加的量由價目表決定、與 `|S|` 無關，在最平的區塊上是旋轉上限的 **37 倍**。

### 試過而沒有動到模糊的十二條路

| 路徑 | 結果 |
|---|---|
| `--floor-survival blur12`（加性項的期望存活加權） | **唯一動得了模糊 σ=2**：0.0980 → 0.1178，多付 8% 失真 |
| 存活加權加在**相位**閘上 | 模糊 σ2 比對照還低 |
| `--floor-gate complement` | 六欄全在噪聲內（最大差 1.2 個百分點） |
| 加性項硬切帶（`--floor-r-max 0.35 / 0.55`） | DISTS 0.36–0.41、PSNR 14–16，不可用 |
| `--r-max` 硬切上界 | 未淨化位移掉 53% |
| 換頻帶 1.28× | 沒動 |
| 加強度到 radius 8 | 飽和，沒動 |
| 換損失（`latent_norm` → `image_guidance`） | 模糊 σ2 −0.004 |
| 寬 EOT（含 blur） | 模糊 σ2 +0.010 |
| 高噪聲時間步窗（`--ig-t-min 800`） | 六欄裡五欄墊底 |
| 隨機化幾何 EOT | 裁切欄仍只有空白地板的 12–21% |
| 開放低頻（`r_min` 0.02） | 等失真下位移由 0.707 掉到 0.601 |

### 裁切：不是破壞，是同步失效

這一點與模糊性質完全不同，**新方向要用得上**。

實測（`runs/ip2p_residual_signature/band_transfer.csv`）：裁切之後擾動的能量
留下 **51–99%**，它對「算子自己搬過的那份擾動」的方向餘弦是 **0.995**。
**擾動原封不動地通過了裁切，只是位置被搬走，而沒有人替它對回去。**

換過參照之後（兩側吃同一個算子、地板由構造為 0），裁切是六個算子裡
**保留得最好的一欄**：`ours_pg_n` 未淨化 0.537 → 裁切 0.413（77%）。

## 四、位移場那一族（已否決，但證據要留著）

程式：`src/defense/param_pgd.py` 的 `WarpParam`／`WarpRandomParam`，
流場正則在 `src/defense/stadv_flow.py`（stAdv 的逐行移植）。

**它不加任何東西，只把像素搬家**：學一個 `(1,2,512,512)` 的流場 `f`，
輸出的每個像素去 `(y,x) + f(y,x)` 那個位置取色，用雙線性四鄰居內插。
直接後果是**平坦區搬多遠都沒用**——鄰居跟原地同色。這與相位方法「平坦區
動不了」是同一個症狀、不同的原因。

三件已定案的事：

1. **四個半徑全部 `early_stop` 收斂**，所以「輸」不是訓練不足。
2. **與同失真的全隨機對照在可比較的範圍內打平**。全隨機掃描只涵蓋
   DISTS 0.009–0.161；stAdv 五個點裡四個落在**範圍外，不可外插**。唯一落在
   範圍內的 `sa_t001` 位移 0.0774，同失真隨機內插 0.0677，差 +0.0098（噪聲內）。
3. **抗淨化其實比相位族強，但不划算**。`sa_t000` 的模糊 σ=2 淨增益 0.261 對
   相位族的 0.098（2.7 倍），代價是 1.70 倍的失真；壓到等失真的 `sa_r04`
   六欄全部低於相位族。

**τ 不可沿用原文的 0.05**：原文的 `L_adv` 是分類器 logits 上的 Carlini-Wagner
損失，尺度與擴散損失完全不同。實測 τ=0.05 時位移 0.0007、PSNR 67，
攻擊被壓成零。`L_flow` 根號內的 `eps` 是本專案加的（原文沒有），否則全零起點
第一步就拿到 NaN。

## 五、量測協定（**這一節不隨方向改變，新階段照用**）

### 五條不可省的規則

1. **等失真對齊不可省，而且不可外插。** 兩個方法的強度參數單位不同，沒有任何
   一個軸天然對齊。作法是各自掃三到四個強度得到 (失真, 效果) 曲線，在對方曲線
   上線性內插出失真相同之處再比。**落在掃描範圍外一律回報 `out_of_range`。**
   程式：`scripts/tradeoff_curve.py`。
2. **兩個失真軸都要報**（等 DISTS 與等 LPIPS）。實測兩者對同一組影像的判定
   經常相反，只在單一軸上成立的結論不算數。
3. **空白地板不可省。** 淨化算子自己就會把編輯推開；不扣掉它，「淨化後位移
   較大」無法排除「該算子本來就把編輯推得比較開」這個平庸解釋。
4. **只報兩個絕對值**：`總增益 = effect(p)`、`淨增益 = effect(p) − 空白地板`。
   **不換算成佔某個範圍的百分比**——比例讀數在分母塌陷或參照改變時不可解讀。
   LPIPS 飽和於 **0.772**（`runs/readout_ceiling/`，45 對的中位數），該值只作
   飽和參考，**不進任何算式**。
5. **幾何類算子換參照，其餘不換。**

```
幾何類：  effect(p) = LPIPS( 編輯(p(原圖)), 編輯(p(防禦圖)) )   地板 ≡ 0
其餘：    effect(p) = LPIPS( 編輯(原圖),    編輯(p(防禦圖)) )   照舊扣地板
```

幾何類是 `src/purify/ops.py` 的 `GEOMETRIC_KINDS`（`crop_resize`、
`resample_roundtrip`、`resize_only`、`shift_only`、`jpeg_then_resize`），
判定走 `Purifier.kind` **不是標籤字串**。CSV 逐列有 `reference` 欄。
理由：`crop_resize` 是繞中心的純放大 1.2488×，改的是取景，舊參照下地板 0.5506
而 LPIPS 只飽和到 0.772，讀數被取景差異吃光。

> **既有 `runs/` 裡所有裁切欄的數字都是舊參照量的**，各 README 檔頭都有註記。
> 要新數字必須重跑。

### 擋下與否用眼睛判，不用代理讀數

**SigLIP 代理已實測失效**——它把「人還在、只是被蓋上紋理」也標成 blocked。
CLIP 的門檻 0.8445 只作為粗略代理。主讀數是位移（LPIPS），
人眼判定是**指標矛盾時的裁定者**，不進主表。

### 攻擊模型

`src/models/ip2p.py`，InstructPix2Pix。三個推論參數**論文未載、是本專案指定**，
改動會讓新舊批次不可比：`steps=100`、`s_T=7.5`、`s_I=1.5`、`seed=20260812`。

兩個補錯了也不會報錯的地方（已由測試釘住）：拼進 UNet 的影像 latent
**不乘** `scaling_factor`；載成一般 SD 1.5（UNet 4 通道）時影像條件會**靜默
失效**，`_check_channels()` 會拒絕繼續。

SDEdit 那條線（`src/models/sd.py`）已凍結，結果留在 `runs/sdedit_*`。
**兩者在運算上不是介面差異**：SDEdit 的原圖只以被噪聲稀釋的殘影進入，
IP2P 是直接拼接，依賴前者的機制解釋在 IP2P 上不成立。

### 已實作的對照組

| 方法 | 是什麼 | 狀態 |
|---|---|---|
| **DCT-Shield**（ICCV 2025 Highlight，arXiv:2504.17894） | 在**量化後**的 JPEG DCT 係數上加 δ，`ε ≥ 1` 個量化階 | **重現成功**。官方 repo 是空的，由論文與補充材料 Algorithm 1 逐行重寫 |
| **AdvDrop** | 對 DCT 係數施加可學習的量化，用丟資訊來攻擊 | 部分（九量中六） |
| **DJSMA** | DCT 反對角帶上的貪婪 JSMA | 診斷通過，正式批未跑。**嵌入與萃取兩階段從未實作**——脆弱浮水印若要做，那一格是現成的 |

DCT-Shield 有四件必須寫進報表的事：`ε ≥ 1` 是抗 JPEG 的必要條件不是調參建議；
抗 JPEG 的保證是**單向**的（`Q_alg = q` 只擋得住品質 `q' ≥ q` 的壓縮）；
`δ = 0` 時輸出不是原圖而是 `Q_alg` 品質的壓縮圖；**免疫影像不能存成 JPEG**。

### 淨化側（攻擊方）

DiffPure、GrIDPure、IMPRESS 已實作為算子。另有 **FreqPure**（高頻保留式擴散
淨化）被標為「對本方法最尖銳的針對性威脅，必須測」，以及一篇從頻域分析淨化的
論文指出**破壞程度隨頻率單調遞增**——那正好解釋模糊那一欄為什麼守不住。

## 七、討論過但沒有實作的方向

### 7.1 半解析度參數化（IAM，arXiv:2402.16586）

每步先雙線性降到半解析度、在該解析度上走 sign 梯度、再升回原尺寸，使擾動
**天生沒有高頻**。專案筆記標為「**唯一指向 blur 欄的機制**」。

沒有可借的損失（Eq.2 就是特徵距離）、Algorithm 1 缺 ε 投影與 clamp，
所以價值全在那個參數化。**還沒有逐行對照過原始碼。**

### 7.2 多品質集成的抗 JPEG（NIPS 2017 MLSec Workshop）

可微分 JPEG 的原始出處（`round` 近似為 `⌊x⌉+(x−⌊x⌉)³`）。核心已實作
（本專案改用直通估計，前向更忠實），但**它真正的貢獻尚未採用**：
對 `q ∈ {25, 50, 75, ∞}` 以損失大小加權合併梯度。單一品質會過度特化。

### 7.3 集中式擾動（可學的空間包絡）

**想法**：把擾動集中在畫面的一個位置、幅度很大，只要淨化之後那塊還在就有效。

已寫成原型（`--floor-envelope`，K 個高斯凸包 × 徑向低通，五個純量與
`theta`／`gain`／`a` 走同一條 PGD，總量正規化使「集中」等價於「把價目從別處
收回來堆到凸包底下」），`tests/test_floor_envelope.py` 58 條測試，
**但從未跑過任何 GPU 工作**。

> **使用者已裁定：不接受「往現行架構再加旗標」這種做法，要做就當成獨立的
> 新方法重新設計。** 上述旗標定位為原型與可行性驗證，不是交付路徑。

機制上要注意：**模糊那一側這個方向是逆風的**——空間上壓得越窄頻譜攤得越寬，
單位預算下被模糊拿走的更多。它真正可能有用的是**裁切**（靠中心的活得下來）。

### 7.4 脆弱浮水印（主動式感知雜湊）

**它換掉的是問題本身**：不再要求「讓攻擊方編不出東西」，而是「讓攻擊方編得
出來，但編過的事實藏不住」。嵌進去的東西不需要在攻擊方那一端起作用，
只需要在**我方的讀出端**還讀得回來。

**難的不是脆弱那一半**——已有文獻量到 SD v1.5 再生把三個主流浮水印的位元
正確率由 99.8% 打到 7.4%／12.8%／24.5%，guided removal 更打到 0.0%，
而影像品質仍有 PSNR 31.8。難的是**「被 JPEG 與模糊之後不崩潰」**。

**關鍵在於它解得開裁切那個結**：`reference/SURVEY_NOISE_RESISTANCE.md` 判定
穩健浮水印工具箱有一半（幾何不變域、嵌入模板 ＋ 解碼端估幾何、自同步、
展頻的處理增益）建立在我方控制解碼器上，而防護擾動沒有那個東西。
**一旦承認讀出端存在，那四項全部回來可用**——而那正是裁切欄輸掉的原因
（擾動原封不動通過了，只是沒有人替它對回去）。

**要先裁定的**：`GOAL.md` 的目標要不要由「阻止編輯成功」擴成「阻止 ＋ 可舉證」。
四種部署假設裡**作者自持解碼器**對本專案改動最小——解碼端不必在散布時存在，
只要在爭議舉證時存在。

**前例查證的結論**（三條，都與交接文件先前的說法不同）：

1. 「沒有人把脆弱浮水印與防護擾動放在同一張圖上」**不成立**。ASFW
   （*Expert Systems with Applications*）標題就是 *Adversarial Semi-Fragile
   Watermarking*，動機寫的就是「對抗擾動易被有損壓縮打掉」；Dual Defense
   （IEEE TIFS 2024，[有原始碼](https://github.com/Xming-zzz/DualDefense)）
   同樣。ACM Computing Surveys 2025 已把「防護擾動」與「浮水印」寫成同一份
   taxonomy 的兩支。**仍成立的窄版本**：那些工作的威脅模型全部是人臉深偽，
   查不到在擴散指令式編輯／inpainting 下、且用抗淨化協定評測的。
2. **Watermark Anything 不是脆弱浮水印**，是穩健且可定位的浮水印。它的價值在
   **權重公開**，可以直接當解碼端。
3. **最小可跑版本不需要訓練**：DCT 域的量化索引調變，逐圖封閉式計算。底層
   已經有了（`src/baselines/jpeg_codec.py` 的 libjpeg 量化表、區塊 DCT、
   直通估計），而 DJSMA 的嵌入／萃取兩階段正好是現成的缺口。
   **從零訓練編碼解碼器做不到**——WAM 用 MS-COCO 118000 張、8×V100 兩天；
   EditGuard 用 COCO 30000 張、250000 次迭代。本專案的資料集差三個數量級。

### 7.5 EditShield（缺口）

ECCV 2024，攻擊模型與本專案**完全相同**，而且它處理裁切的方式正是我們試過
又失敗的那一種（EOT）。我們在 `runs/ip2p_eot_geom_purify/` 量到隨機化幾何 EOT
的裁切欄仍只有空白地板的 12–21%，卻沒有一個外部方法可以對照「別人做同一件事
拿到多少」。**已查證設定**：預算 4/255、EOT 三個變換是高斯平滑（kernel 5、
sigma 1.5）、旋轉 5°、中心裁切。**官方程式碼未查證，移植時必須標「摘要重建」
或逐行對照後改標。**

兩件必須寫進報表的事：它的評測**沒有扣空白地板**，直接引用它報的數字與我們的
淨增益不可比；它的 EOT 含旋轉而我們的九個算子沒有旋轉。

## 八、專案規定（**這一節優先於本檔其餘所有內容**）

### 訓練方法的實驗：不設判準

對任何要實驗的訓練方法（新的損失、新的參數化、新的最佳化方式），**不得自訂
任何用來判斷「這個方法有沒有效」的判準**，包含事前登記的通過門檻、倍率下限、
「不通過就不必再走」這類把後續工作擋掉的規則。

要做的只有三件事：

1. **把訓練跑到收斂。** 收斂與否用一個**與訓練目標無關的固定量測**判定
   （固定的一組取樣、定期評估、記下曲線），不是用逐步損失看起來平不平。
   隨機目標的逐步損失本來就會抖，那不是收斂訊號。
2. **忠實回報數據。** 所有量測欄位照報，不挑選、不省略。
3. **忠實回報影像。** 防禦圖、淨化圖、編輯圖都要留下並呈現。

**有沒有效果由使用者判斷。** 助手的工作到「數據與圖擺出來」為止。

量測協定本身不受此條影響且仍然必須遵守——那些是**如何量得準**，不是**如何
判斷有沒有效**。

### 工作要求

- 一律用**繁體中文**回答，客觀學術語氣；程式碼關鍵字、函式名、套件名維持
  英文。**commit message 用英文。**
- 動手前先驗證假設（讀檔、跑指令），不要憑記憶猜 API。
- 架構或實驗設計**先提計劃討論再寫程式**。
- 修改論文方法要記 before/after：具體行號、原貌、原因。
- 宣告完成前必須實際跑過並看到成功輸出；失敗就直說失敗。
- **禁止用 try/except 或條件跳過來掩蓋症狀**，要找根本原因。
- **未經明確授權不得把分支併入 main。**
- 環境問題直接修掉，不用寫進報告。
- 需要提問時上限 2 題，每題附上推薦答案；次要細節用合理預設。

### 命名

**目錄、檔案、實驗組、文件一律不含日期、流水號或順序詞**，要一眼看出在做什麼。

| 不可以 | 應該寫成 |
|---|---|
| `runs/s0817`、`runs/a5_gain` | `runs/sdedit_mainline`、`runs/phase_gain_sweep` |
| `SURVEY_2026-08-18.md` | `SURVEY_FREQUENCY.md` |
| 「第二輪的結果」「本輪」 | 「等失真錨點上的頭對頭結果」 |

**文件內容不得有時間相依性。** 不寫「本輪」「先前」「稍後會補」，只寫現況、
理由、以及查閱路徑。

### 移植他人的方法

- **逐行對照公開原始碼，不照摘要寫。** 查不到原始碼時明確標為「摘要重建」，
  並在模組 docstring 寫清楚差別。
- 查不到的參數設為必填或標 `modified_from_paper`，**不要填看起來合理的預設**。
- 跑 baseline 時**用它自己的損失**；換成本專案的損失是消融，要分開列。
- 每個未載的參數都要成為 CSV 的**欄位**，不是註解。

### 資料保全

`runs/` 保存**數值記錄**：CSV / JSON / log / txt 一律入版控。

**影像與 HTML 不入版控。** 防禦圖能由已記錄的參數與種子重跑出來；量測結果
不可重現，一律保留。

改動 `.gitignore` 的 `runs/` 區塊時，必須用 `git status --porcelain --ignored`
確認沒有結果檔被排除。曾因寫成 `runs/*/**` 而靜默漏掉 143 個結果檔。

**密碼與 token 不得寫入任何入庫檔案。**

### 六個必須知道的坑

1. **先 `source ~/env.sh`，再 `cd` 到 repo。** `env.sh` 最後一行會把工作目錄
   換到舊的 `~/WACV`，順序相反時所有相對路徑指向錯的樹，**而且不會報錯**。

2. **卡是多人共用的，不可以把工作送到別人正在用的卡上。**
   派工前一律跑 `bash scripts/free_cards.sh` 取空卡號：

   ```
   bash scripts/free_cards.sh --verbose     # 看每張卡是誰的
   DEVS=$(bash scripts/free_cards.sh)       # 直接拿去餵派工腳本
   ```

   **不要自己讀 `nvidia-smi --query-gpu=memory.used`**——它只給總量，看不出
   那些記憶體是誰的。要看誰佔的得用 `--query-compute-apps=gpu_uuid,pid`。

   **檢查要擋在派工前面，不是印出來就算。** 所有派工腳本都內建
   `free_cards.sh --assert "${DEVS[*]}" || exit 3`，指定的卡有別人就拒絕啟動；
   手動送單一 process 時要自己先 `--assert`。沒有空卡就等，不要擠。

   判定「空」的兩個條件：別人的 compute app 實際佔用不超過 512 MiB，
   且扣掉之後已用記憶體低於 1024 MiB。（門檻不是零是因為有人會在八張卡上各留
   一個約 256 MiB 的 CUDA context，那不是在算。不確定時把門檻**調小**。）

3. **`pkill -f` 的樣式會匹配到自己的 ssh 連線**並截斷輸出。用 `ps` 取 PID 再
   逐一 kill。

4. **兩個 process 不可寫同一個輸出目錄。** 每張影像寫檔是整份重寫 CSV。

5. **每卡最多 2 個 process。** 疊到 3 個實測整批 OOM。

6. **遠端沒有 GitHub 憑證**，`git push` 推不上去。遠端產生的 CSV 要用
   `tar`／`scp` 抓回本機再從本機提交。遠端還有 **sparse-checkout 白名單**，
   新增 `runs/` 子目錄後要先 `git sparse-checkout add` 才看得到——**實際踩過**：
   CSV 明明在版控裡卻不存在於磁碟，七個 process 全部 `FileNotFoundError`。

### 機時的實測成本

`results.csv` 的 `total_seconds` 是**每張影像**的秒數，不是整批的。
（先前有人在這裡差了 10 倍。）

| 量 | 實測 |
|---|---|
| 一次 IP2P 編輯（100 步、512²） | ≈ 17.3 s |
| PGD 一步（相位參數化） | ≈ 0.37 s／步／影像 |
| 防禦端訓練 6000 步、兩張圖 | ≈ 3.5 GPU-h |
| 抗淨化一格（6 算子 × 3 種子 ＋ 幾何參照 = 24 次編輯） | 獨佔一卡 ≈ 14 min；每卡兩個 process ≈ 29 min |
| 七個條件的抗淨化批次，一卡一個 | 牆鐘 ≈ 40 min |

幾何類換參照之後成本 **+14%**（每個幾何算子各自要一份 `編輯(p(原圖))`，
不能跨算子共用）。
