# 衣物貼片：載體、判準、以及目前的結論

這一條線問「衣物上的圖案能不能構成防禦」。載體是印在人像衣物上的局部貼片，
支撐事前固定，**支撐外逐位元不變、臉從不被碰**，所以發布圖身分恆為 1.0000。

合成式四個載體共用：

    x_θ = (1 − M)·x + M·clamp(patch ⊙ S_x + H_x, 0, 1)

`M` 事前固定，`S_x`（明暗）與 `H_x`（織紋殘差）由原圖算一次凍結，
所以圖案跟著布料的摺痕走，看起來像印上去而不是貼一張紙。

## 結論

**一、防禦沒有成立。** 在八張人像 × 四類會重畫人的指令 × 兩顆種子（47 格有分母）
上，最佳化臂垮 **1/47**、不最佳化臂垮 **2/47**，四十四格的身分變化在 **±0.03**
之內——與未防禦編輯沒有可分辨的差別。

**二、最佳化買不到東西。** 二十六個臂、五個目標函數、五種支撐形狀、面積 2.3%–20.5%
全部落在單一條遞減的代價→位移曲線上，效率最高的幾格是**不最佳化**的臂。
失真對齊的對照（同樣 ΔE00 40.08，抽的對解的）是 **0.2307 對 0.2152**——抽的高 7%。

**三、唯一動得了判準的是貼片被讀成物件，而不是最佳化。** 在單張人像上，
不具物件語意的幾何印花原樣貼上時 `add_hat` 身分 0.955；換成笑臉／人臉／半身／拼貼
之後六個臂全部落在 −0.18 到 0.12，**不需要最佳化**。逐張看圖：貼片在編輯結果裡
變成畫面裡真的存在的東西（手裡拿的草帽、旁邊站著的另一個人），模型順著這個線索
把整個人重畫。

**四、那個效果的可複製性低。** 同一格換一個面積（0.12 → 0.065）方向就翻面：
`geom_rand` 由 0.955 變 −0.03、`geom_opt` 由 −0.12 變 0.951。所以「最佳化讓幾何
印花長出物件語意」**不能算已確立**。

**五、範圍限制是結構性的。** 判準是「這個指令會不會重畫人」，不是「指令要什麼
物件」。下雪、夜晚、油畫、加一隻狗這四類只改全域光影或人以外的東西，九個臂 ×
四類共三十六格身分 0.90–0.98，紋風不動。

**六、語意與低階干擾互斥。** 四個把低階目標推到底的臂（不受限、只獎勵遠場、
ε 放寬）代理分數推到 −235% 至 −747%，那四類一樣不動，而且把已經拿到的
`beach` 效果（0.679）弄丟回 0.94–0.97。最佳化的自由度一放寬就把目標圖的語意磨掉。

**七、這個機制與「免疫」不是同一件事。** 它靠的是讓模型誤讀畫面內容，不是讓擾動
抵抗淨化。對知道有貼片的攻擊者，把貼片裁掉或塗掉就沒了。垮的也一律是身分腿——
每一格的帽子都仍然戴上去了，所以是**誤導**而不是阻斷。

## 四個載體

| 模組 | 參數化 | 自然度靠什麼 |
|---|---|---|
| `material_patch.MaterialPatchParam` | 色盤權重場，顏色鎖在衣物色盤的凸包內 | 凸包（低彩度衣物推不出振幅） |
| `patch_canvas.PatchCanvasParam` | 獨立 RGB 畫布，`ε` 綁相對圖樣的 L∞ | **失敗**：六臂 drift 全部頂滿 0.345、變成螢光彩虹 |
| `print_patch.GeometricPrintParam` | 固定幾何基底的係數 ＋ CIELab 色盤 | **可行域的邊界**（見下） |
| `target_patch.TargetImagePatch` | 從一張目標圖出發，`bounded` 有界／`free` 無界 | 起點的結構（`ε` 不是保證） |

### 幾何印花的參數化

    score_k(u,v) = b_k + Σ_j A[k,j]·φ_j(u,v)
    w            = softmax(score / τ)
    pattern      = Σ_k w_k · c_k

`φ_j` 是 **31 個固定的低階幾何場**（3 週期 × 2 相位的徑向餘弦、4 方位 × 3 週期 ×
2 相位的平面波、1 個常數場）。**基底不學**——讓頻率可學等於把逐點散斑放回可行域。

學的是 K=3 色時的 **105 個數字**：`A`（3×31 基底權重）、`b`（3 偏置）、
`pl`／`pc`／`ph`（各 3，CIELab 的明度／彩度／色相）。對照自由畫布的 12288 個。
彩度走 `chroma_max·sigmoid`，所以螢光色是**越不過的邊界**而不是懲罰項；
亮度不設限，因為黑白高對比的印花在現實裡正常，且對 VAE 是比高彩度更強的輸入。

**這個生成函數沒有文獻出處，是本專案自造的**，不像顏色載體那三支（NCF、
ReColorAdv、AdvCF）有論文可對照。要投稿必須先補文獻查核。

## 五種支撐與面積天花板

安全區（衣物 ∩ 排除臉框 ∩ 侵蝕）是一條細帶，所以形狀決定面積：

| 支撐 | 形狀 | 可達面積 |
|---|---|---|
| `disc` / `square` 單塊 | 完整的圓／方 | 0.023–0.123（依人像） |
| `lattice`（12–88% 裁切框內） | 規則圓點 | 0.064，**矩形硬邊明顯** |
| `lattice`（不設裁切框） | 規則圓點 | 0.138 |
| `full` | 整件衣物 | 0.205 |
| `ring` | 主體外緣環帶 ∩ 衣物 | 0.067–0.172 |

不設裁切框放棄了「攻擊者每邊裁 10% 也裁不到貼片」那個性質，**代價未量**
（只跑過 `identity` 一道淨化）。

環帶是位置檢定：同樣 ΔE00 28，集中在主體邊界（每單位失真位移 0.00557）**輸給**
攤在整件衣物（0.00597）。**覆蓋率是唯一還有斜率的旋鈕**，把預算搬到物件會長出來
的地方買不到東西。

## 目標函數

`outside_terms.PrintObjective._compose`，越小越好，四項都在空文字條件下算：

    score = −0.5·tanh(enc) − 1.0·tanh(cond) + 1.0·id − 40.0·outside

| 項 | 定義 | 在貼片上的表現 |
|---|---|---|
| `enc` | 潛圖差的加權範數比，可支撐加權 | 推得動，但 `tanh′` 在 1.168 處只剩 **0.322**（68% 梯度被吃掉） |
| `cond` | 4 個時刻上 UNet 的 ε 相對差 | 近零 |
| `id` | `null_edit` 臉框的 ArcFace 餘弦 | **結構上凍結**：孤立成唯一項、250 步只動 0.003 |
| `outside` | 支撐外輸出位移，近鄰／遠場／臉框分帶 | 線性進分數不經 `tanh`，推得動 3.8 倍 |

**ArcFace 餘弦是平的目標**：換成獎勵臉框帶的 RGB 位移，同樣步數把 `id` 動 0.030
（十倍）。ArcFace 對「衣服換了圖案」本來就設計成不變。

求解走 `immunise.optimise_carrier`：Adam、lr 0.05、120–250 步，選點用固定抽樣的
`eval_score` 而不是逐步分數；`project()` 在幾何印花上是 no-op（值域由 sigmoid 與
softmax 保證）。

## 讀數上的四個陷阱

1. **`edit_lpips` 量的是污染不是阻斷。** 位移最大的格是貼片顏色被吸收進生成物件
   造成的。拿它當防禦強度的代理會讀錯。
2. **VQA 會在低對比的帽子上翻轉。** 判 yes 與判 no 的兩張影像可以看起來幾乎一樣。
   逐張看圖才算數。
3. **印人臉上去會自欺。** 若最大臉框變成印的那一張，發布圖本身就已經不是同一個人。
   已逐格檢查：發布圖臉框與原臉 IoU 0.953–0.965，編輯後九臂 × 六類全部 ≥ 0.5。
4. **未防禦編輯常常自己就換人。** 64 格裡 17 格沒有分母。不成立的格不列入。

## 規模

**n 很小。** 最大的一批是八張人像 × 四類 × 兩顆種子（47 格有分母），
其餘多數結論來自一張人像、一顆種子。一道淨化（`identity`），`crop_resize`
等其餘三道未跑。自然度一律由使用者看圖判定。
