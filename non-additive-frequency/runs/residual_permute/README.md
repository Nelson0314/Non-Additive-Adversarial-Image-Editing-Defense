> C&R 串接 `jpeg_then_resize`）的 `effect`、空白地板與淨增益，都是以
> `LPIPS(編輯(原圖), 編輯(p(防禦圖)))` 為位移、再扣該算子那個非 0 的地板

## 這一格在判什麼

`docs/reference/SURVEY_ARCHITECTURE.md` 第三節的 **H1**：

> DCT-Shield 的效果是**統計驅動**的、本方法的是**實現驅動**的。

H1 是「它裁切保留 98.2%、我們 13%」目前唯一的機制解釋，也是候選一（統計驅動
的擾動）的前提。該節指定的判定實驗是：取已存的防禦圖抽出殘差，做一次 32×32
區塊隨機置換後加回原圖，量效果。**預期 DCT-Shield 幾乎不掉、本方法掉光；
若兩者都掉光，H1 錯。**

區塊置換保留與破壞的東西分得很乾淨：每個區塊的內容**逐位元不變**（功率譜、
頻帶分布、區塊內的相位關係全部保留），只有區塊之間的相對位置被打亂。

## 判定

**H1 錯。** 預測的是「它幾乎不掉、我們掉光」，實測是**兩個都掉到約 64%，
而且掉得一樣多**。效果既不是純統計驅動（它掉了三分之一），也不是純實現驅動
（我們留了三分之二）。

**後果：**

1. **候選一的前提垮了。** 「把擾動改成平穩隨機場就能免疫裁切」建立在
   「DCT-Shield 的效果不依賴實現」上，而它依賴的程度與我們相同。
2. **「98.2% 對 13%」需要別的解釋。** 本輪已排除三個：
   - **對準內容**：兩個方法都對準（ρ 0.89 對 0.80–0.84），分不開
     （`runs/residual_texture_alignment/`）。
   - **裁切吃掉的能量**：我們丟得**比它少**（0.23–0.26 對 0.33–0.34），
     方向相反（同上）。
   - **實現特定**：本檔，兩者相同。
   剩下沒被排除的是 H2（比值被分母支配，`RESULTS.md` 已量到 r = −0.83／−0.900）
   與 H3（放大把 DCT-Shield 的近 Nyquist 能量搬回編碼器敏感的帶，
   `crop_decomposition.csv` 有直接支持但未量化）。**H3 是目前最值得追的一個。**

## 三個必須寫下的保留

1. **n = 5，只有 color 分片。** 兩個條件差 0.0011、逐圖又貼著走，方向不太可能
   翻轉，但 13 張才算數。補跑：`bash scripts/residual_permute.sh "<兩張卡>" "scene object"`。
2. **置換不是等失真的。** 置換後 DISTS 多數下降（`ours_add` 最多由 0.2121 掉到
   0.1592），也就是**置換後的影像比較不明顯**。兩個方法同向，故不影響「誰掉得多」
   的比較，但「掉了 36%」這個絕對值含一部分失真下降的貢獻。RMS 幾乎不變
   （只有 clamp 造成的小幅下降），逐列記在 `rms_def`／`rms_perm`。
3. **只用了一個置換種子**（`permute_seed=0`）。逐圖的離散度（0.46–0.77）遠大於
   兩個條件之間的差距，所以結論看的是條件間的差，不是單張的值。
