## 4. 兩組實驗

依 `DESIGN_2026-08-05.md` §2.0a（使用者 2026-08-06 定案）並行兩組，不是二選一。

| | **b3（主）** | **v14（對照）** |
|---|---|---|
| 模型 | SDXL 1.0 base | `CompVis/stable-diffusion-v1-4` |
| 解析度 / 精度 | 1024² / bf16 | 512² / fp32 |
| 立論 | 最後一代帶 cross-attention 的 SD | **Mist 與 DIA 的原生模型**，且為指導者協定所指定 |
| 段 3 成本 | 單卡約 20 h | 單卡約 5 h（像素數 1/4） |

`shard.sh` 現行旗標（b3 用）：

```
--purify-mode rotate --attn-timesteps 2    # N1 的記憶體限制，見 shard.sh 內的實測表
--warp-max-disp 8.0                        # 讓 τ=0.35 這個報告點可達
--shared-tokens 76                         # SDXL 的 decoy token 位置
--exact-inversion --t-max 200              # 生成路徑的重建下限
--probe-steps 60                           # 12 步對位移場沒有鑑別力
```

v14 的差異：`--wrapper sd --resolution 512 --precision fp32 --shared-tokens 0`
（BOS，PromptFlare 原作的選擇）、`--purify-mode all`（512² 無記憶體壓力）、
**不帶 `--t-max`**（fp32 下 BDIA 精確，該參數無關）。

## 7. 尚未解決的事

### 7.1 待裁決（需要使用者）

* **`tau_acut = 0.04` 與 `tau_chroma = 0.8`**。兩者是在 τ_lpips=0.05 上由人眼
  定出的絕對值。實測顯示它們目前對兩類位置都沒有在做被設計要做的事：
  生成路徑的鈍化發生在 φ 動作**之前**（`tau_acut` 管不到），而位移場是
  **變銳利**（比值 1.023→1.075）而非變模糊，卻被對稱的 `|r−1|` 同樣處罰。
  程式的 preflight 每次都會警告。詳見 `RESULTS_2026-08-06` §5、§10.3。

### 7.2 已知但暫不處理

* **N1 在兩個模型上都失效，方式不同**（使用者已裁定兩組都跑完，當可遷移性
  的結果寫）。SDXL 上 decoy token 只拿到 1.6% 的注意力質量（`1−mass` = 0.984），
  SD v1.4 上拿到 93.9%（0.061）——**同一個機制差十六倍**。前者是拿不到著力點，
  後者可能是飽和，兩端都失效。結構原因：SDXL 第一個 down block 無 cross-attention，
  最細的 attention 格涵蓋 16 個影像像素，而 `max_disp` 是 8.0 px。
* **cat_02 的純 VAE 來回就要 LPIPS 0.2130**，佔 τ=0.2 預算的全部。這是該影像
  紋理的性質，對任何走生成路徑的位置都成立，屬適用範圍限制，不是缺陷。
* **位移場在 τ≥0.2 已頂死 `max_disp`**（disp_max 固定在 8√2 = 11.31 px）。
  射線縮放在該點以上不再是縮放射線。訓練點已因此降到 0.2，但 τ=0.35 仍是
  報告點，其數值要標註這個限制。

## 8. 例行操作

### 8.1 段 0 之後的分片

```bash
ssh -p 10101 …            # 上機
source ~/env.sh && cd ~/WACV
BATCH=b3 bash scripts/shard.sh fanout bird_03 cat_02 dog_03   # 每張圖一張卡

```

`--conditions` 可只跑部分條件（例：`--conditions N2 N3`），用於補跑而不重跑
baseline。φ=0 的共用對照格不受影響。

### 8.2 證據回收

產物寫在版控範圍外（`~/wacv_runs`），因為 2026-08-06 發生過 `git pull`
把實驗正在寫的目錄刪掉（sparse-checkout + skip-worktree，見 `shard.sh` 的
`RUNS` 註解）。回收是明確的一步：

```bash
ssh … 'cd ~/wacv_runs && tar czf ~/done.tgz b2_bird_03 b2_cat_02 …'
scp -P 10101 …:done.tgz .   &&   tar xzf done.tgz -C runs/
git add -A runs/ && git status --porcelain --ignored runs/ | grep '^!!'   # 必查
```

**最後那一行是 `CLAUDE.md` 要求的**：確認沒有結果檔被 `.gitignore` 靜默排除。
正常情況下只該看到舊實驗 e15／e21 的 48 個 `residual.npy`（刻意排除，可由 φ 重算）。

### 8.3 遠端 `git pull` 卡住時

`runs/` 底下若有與版控不同的檔案會讓 pull abort。先備份再還原工作區：

```bash
cp -a runs/<目錄> ~/pull_backup/$(date +%Y%m%d-%H%M%S)/ && git checkout -- runs/<目錄>
```

### 8.4 `.writer.lock` 殘留

行程被 kill 後鎖檔會留下，下一次啟動以 `WriterLockHeld` 拒絕。鎖檔的說明
要求**先確認行程確實結束**再手動刪除，不自動判定：

```bash
ps -p <鎖檔裡的 pid> || rm -f ~/wacv_runs/<批次>/.writer.lock
```
