# 讓訊號活過失真：穩健浮水印的工具箱，與它對本專案適用的那一半

**這一份不是判準來源。** 判準見 [../DECISIONS.md](../DECISIONS.md)，測得的事實見
[../RESULTS.md](../RESULTS.md)。本頁回答一個問題：

> 「讓一個人為訊號活過壓縮、模糊、裁切」這件事，在別的領域已經被做了二十年。
> 那套工具箱有多少能搬到本專案？

先講結論，因為它決定後面每一條的讀法：**那套工具箱的一半是為了一個我們沒有
的東西而存在的——解碼器。** 能搬的是「訓練時把失真放進前向」那一半，而那一半
本專案已經試過兩次（見第二節的對照表）。**不能搬的是全部與同步、模板、不變域、
處理增益有關的東西**，而那正是文獻上對付裁切與模糊的主力。

已覆蓋的部分不在此重複：抗 JPEG 的擾動最佳化技巧見
[SURVEY_FREQUENCY.md](SURVEY_FREQUENCY.md) §1.13–1.15，淨化側的方法見同檔
第二節與 [AUDIT_PURIFIERS.md](AUDIT_PURIFIERS.md)，三份抗淨化檢定協定見
[ROBUSTNESS_TESTS.md](ROBUSTNESS_TESTS.md)。

## 第一節 穩健浮水印的工具箱

### 1.1 基本架構：編碼器–雜訊層–解碼器（END）

深度浮水印的標準骨架是三段：編碼器把訊息嵌進影像、**雜訊層**在訓練時對含浮水印
的影像施加失真、解碼器從失真後的影像把訊息讀回來。整條鏈端到端訓練，於是
「活過失真」變成損失函數的一部分。

這個骨架與本專案的**階段二**（`runs/ip2p_stage2/`）在形式上同構：我們也是把
可微分的淨化算子放進前向。差別在**目標**——它們要的是解碼器讀得回訊息，我們要
的是攻擊方的編輯模型失手。

### 1.2 不可微失真的三種處理法

雜訊層必須可微，梯度才過得去；但真實世界的失真（真的 JPEG、真的重取樣）不可微。
文獻給了三個答案：

| 作法 | 出處 | 機制 |
|---|---|---|
| **兩階段可分離訓練（TSDL）** | Liu et al., ACM MM 2019 | 第一階段編碼器與解碼器一起訓練、**不加雜訊**；第二階段凍結編碼器，**只訓練解碼器**，此時雜訊層不必可微，可以用真的失真 |
| **Forward ASL** | 同一條線的後續 | 把失真當成加性雜訊：前向用 `T(x)`，反向只走 `x`，也就是 `x + (T(x) − x).detach()` |
| **雙解碼器（END²）** | [arXiv:2412.09960](https://arxiv.org/abs/2412.09960) | 兩個結構相同的解碼器，教師讀乾淨圖、學生讀失真圖；**梯度只走教師那一支**，兩者以中間向量的餘弦相似度對齊 |

**與本專案的關係**：Forward ASL 就是我們在 `jpeg_codec.quantize_ste` 用的直通
估計（BPDA）的另一種寫法，前向值相同、反向規則相同。TSDL 與 END² 都需要一個
「可以單獨再訓練的解碼器」，本專案沒有。

### 1.3 MBRS：真實與模擬的 JPEG 交替

[arXiv:2108.08211](https://arxiv.org/abs/2108.08211)（ACM MM 2021）。每一個
mini-batch **隨機選一個**雜訊層：真的 JPEG、模擬的 JPEG、或不加失真。報告在
品質 Q=50 下位元錯誤率低於 0.01%、PSNR 高於 36。

**與本專案的關係**：兩點。其一，「隨機選一個」與本專案階段二的算子輪替同型，
而我們用的是**每輪洗牌後依序走完**，覆蓋比隨機抽更均勻。其二，該篇強調
**真的 JPEG 必須出現在訓練裡**，只用可微的近似會過度特化——這一點本專案已經
滿足：`jpeg_roundtrip_ste` 的**前向值逐位元等於真的 JPEG**，只有反向是近似。

### 1.4 幾何攻擊：四條路，全部依賴解碼端

裁切、縮放、旋轉會破壞**同步**——解碼器不知道浮水印被搬到哪裡去了。文獻上的
四條路是：

1. **幾何不變域**：Fourier–Mellin／log-polar／polar harmonic transform。已知
   限制是它對**裁切與局部幾何失真本質上脆弱**，而且 log-polar 重取樣本身會
   造成畫質損失。
2. **額外嵌入模板**：另外嵌一個已知圖樣，解碼器先用它估出幾何變換再反轉。
3. **自同步**：例如 SSyncOA（[arXiv:2405.03458](https://arxiv.org/abs/2405.03458)）
   把浮水印對齊到**物件**，正規化質心、主方向、最小外接正方形三個不變量，於是
   平移／旋轉／縮放被吸收掉。
4. **以影像特徵同步**：用特徵點決定嵌入位置。

**四條全部有一個共同前提：解碼端可以先做一次對齊，再讀訊息。** 第 3 條看似
「自同步」，實際上仍要在解碼端把物件切出來、算出那三個不變量。

### 1.5 處理增益：穩健性的另一半來自哪裡

浮水印的穩健性有一半不是來自嵌入的位置，是來自**把 1 bit 攤在幾萬個像素上**。
解碼端做相關運算時，訊號同調相加、雜訊隨機相消，訊雜比按 √N 放大。這就是
spread spectrum 的處理增益。

**本專案沒有這一項，而且不可能有**：我們的「讀出端」是攻擊方的擴散模型，它不會
為我們做相關運算。

## 第二節 逐條對照：哪一半能搬

| 文獻上的工具 | 本專案能不能用 | 理由 |
|---|---|---|
| END 骨架（失真進前向） | **能**，已用 | 階段二就是這個；已否決的 `--purify-aware` 也是 |
| Forward ASL／BPDA | **能**，已用 | `quantize_ste` 就是；前向逐位元等於真失真 |
| MBRS 的真實／模擬交替 | **能**，已滿足 | 我們的前向值就是真的 JPEG |
| MBRS 的「隨機選一個」 | **能**，已用且更嚴 | 階段二用洗牌輪替，短期覆蓋比隨機抽均勻 |
| TSDL 兩階段 | **不能** | 需要一個可以單獨再訓練的解碼器 |
| END² 雙解碼器 | **不能** | 同上 |
| 幾何不變域（Fourier–Mellin） | **不能**（已實測） | 本專案的 log-periodic 候選就是這一條：對 s=1.2488 的方向存活 0.9726，但 1.15 與 1.30 已歸零——**寬度為零的窄峰**，退化成對單一算子 co-adapt |
| 嵌入模板 ＋ 解碼端估幾何 | **不能** | 攻擊方不會替我們估幾何 |
| 自同步（物件對齊） | **不能** | 需要解碼端切物件 |
| 處理增益（spread spectrum） | **不能** | 沒有做相關運算的讀出端 |

**這張表本身就是一個可寫的結論**：本專案在裁切那一欄輸，不是因為沒想到方法，
而是因為**文獻上對付幾何攻擊的四條路全部要求一個我方控制的解碼端**，而防護
擾動這個威脅模型裡沒有那個東西。`runs/ip2p_residual_signature/band_transfer.csv`
量到的正是這個處境：裁切後殘差對**原格點**的餘弦是 0.000，但對**算子自己搬過
的同一擾動**是 0.995–0.996——**擾動原封不動地通過了，只是沒有人替它對回去**。

## 第三節 頻率側：外部結論與本專案量測一致

- **對抗擾動集中在中高頻**，而基於對抗訓練的防禦之所以看起來穩健，有一部分
  正是依賴「對抗擾動是高頻的」這個前提（[arXiv:1906.08988](https://arxiv.org/abs/1906.08988)
  的 Fourier 視角；另見低頻擾動的有效性研究）。
- **高斯濾波之所以是常見防禦，就是因為它移除高頻紋理而保留全域結構。**

本專案的量測與此一致而且更具體（`runs/phase_drift_diagnosis`）：高斯模糊是
**零相位濾波器**，頻域乘的是實正數，**在原理上動不了相位**；實測相位保留
ρ = 0.967 而殘差能量只剩 8.9%，純低通模型能解釋 97% 的衰減。**擾動不是被破壞，
是被靜音。**

**後果**：模糊那一欄要贏，只有把能量往低頻搬一條路；而本專案已經測過放行低頻
（`r_min` 調低），未淨化與抗淨化兩邊都較差，且跨頻帶的效率差三個數量級。
**這是取捨不是調參**，與外部文獻的方向一致（低頻擾動有效，但可見度代價高）。

## 第四節 這一輪查證得到的四個可動項

排序依「能改變結論的程度」，不是成本。

### 4.1 把「訓練用的失真強度」當成一條軸掃，而不是取一個值

MBRS 的作法是隨機選，但本專案已經有一個更強的實測：**降低交付品質 QD 會換掉
抗淨化曲線的形狀**——QD 由 0.85 降到 0.45，jpeg90 掉 24%、jpeg75 掉 35%，
而 **jpeg30 漲 68%**。這與「訓練分布要對齊攻擊分布」的文獻共識一致。

**未做的是把這條軸與階段二合起來掃**：現在 QD 是交付端的旋鈕、階段二是訓練端的
旋鈕，兩者從未同時動過。

### 4.2 多品質集成損失仍然沒跑

[SURVEY_FREQUENCY.md](SURVEY_FREQUENCY.md) §1.15（Shin & Song）的核心結論是
**單一品質會過度特化**，而我們的 `--deliver-jpeg 0.85` 正是單一品質；症狀在資料
上看得到（jpeg75 的 0.4370 掉到 jpeg30 的 0.2087）。集成只能放在**損失**上，
交付仍是單一格點——放到交付上就是已否決的 `--purify-aware`。零件已實作
（`purify_aware.make_eot_jpeg_transform`），從未接上交付。

### 4.3 裁切那一欄：文獻沒有給我們可用的解

第二節的表已經說明理由。**建議把它寫成一節誠實的負面結果**，而不是再花機時：
四條路全部依賴解碼端，而 `band_transfer.csv` 已經把「擾動沒壞、只是沒人對回去」
釘死。這比「我們試了很多方法都不行」是更強的陳述。

### 4.4 模糊那一欄：可贏空間可以先算出來，不必上機

`m_ω`（我們的頻率閘）與 `H(ω)`（高斯模糊的頻率響應）都是**已知的曲線**，乘積的
極大值可以直接解。把「最佳搬移位置的存活能量 × 該頻帶的既有效率讀數」算出來，
就得到那一欄的**淨增益上界**。若上界低於該欄逐圖的離散度，該欄同樣結案。
**純 CPU、半天。**

## 第五節 結論

1. **穩健浮水印的工具箱有一半不適用於防護擾動**，因為它的穩健性建立在一個我方
   控制的解碼器上（同步、模板、不變域、處理增益）。這解釋了為什麼裁切那一欄
   在本專案怎麼做都輸，而在浮水印文獻裡是解得掉的問題。
2. **能搬的那一半（雜訊層進前向）本專案已經做過兩次**，而且現行的階段二在
   覆蓋均勻度上比 MBRS 的隨機抽更嚴格。
3. **模糊那一欄的失效是零相位濾波器造成的靜音**，與外部文獻對「高斯濾波為何
   是有效防禦」的解釋是同一件事。往低頻搬是唯一的路，而那條路的代價已量過。
4. **還沒動而值得動的只剩兩項**：多品質集成損失（4.2）、以及交付品質與階段二
   兩條軸的聯合掃描（4.1）。其餘兩項（4.3、4.4）是**用分析取代機時**的收尾工作。
