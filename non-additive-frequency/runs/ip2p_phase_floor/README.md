# 純相位 ＋ 加性下限：強度旋鈕換成 `--spectral-floor`

**這些數字尚未進入 `docs/RESULTS.md`**，等使用者裁定。

相位封頂在 π，所以 `phase` 這一支的半徑掃到 3.1416 就到頂，失真也停在那裡。
加法項的強度不隨半徑變，故要把純相位那一支推到失真帶上緣，只能推 `floor`。
**強度旗鈕因此是 `--spectral-floor` 不是 radius**，分析時要給
`matched_distortion_table.py --strength spectral_floor`。

13 張人眼確認服從的影像，`--conditions phase --gain-ratio 0 --radius 3.1416`，
其餘旗標與含加性主線相同。驅動 `scripts/phase_floor_sweep.sh`。

| floor | fDISTS | fPSNR | 位移 | 擋下 |
|---|---|---|---|---|
| 0.04（來自 `ip2p_axis_necessity/b_ph_rpi`） | **0.1286** | **25.36** | 0.7011 | 12/13 |
| 0.05 | 0.1383 | 24.54 | 0.7068 | 12/13 |
| 0.06 | 0.1482 | 23.86 | 0.7020 | 12/13 |
| 0.08 | 0.1649 | 22.52 | 0.7038 | 13/13 |
| 0.10 | 0.1818 | 21.36 | 0.7043 | 12/13 |

**位移在 0.7011–0.7068 之間完全不動，而失真漲 41%、PSNR 掉 4.0 dB。**

兩件事：

1. **`spectral_floor` 在 0.04 已經在拐點上或過了**，往上加是純付出。這一批
   原本的目的是「把純相位推到帶上緣好與相位＋增益比」，結果是**推不上去**
   ——不是因為推不動失真，是因為位移早就飽和了。
2. 這批同時證明了**主讀數本身在 0.70 附近飽和**（全部 52 個 13 張工作點的
   位移最大值是 0.7078，前十名擠在 1.2% 的區間內）。詳見
   `docs/PENDING.md` 第〇節——**該區間的位移比較與擋下數比較都不可解讀**。

**這批留下的問題**：既然 0.04 以上沒有用，那 0.04 以下呢？`ip2p_floor_only`
（相位與幅度都不動、只留下限，掃 0.02–0.20）與這一批合起來才答得完整。
