# 色彩網格的空間解析度掃描：容量不是瓶頸

`scripts/colour_grid_round.sh`。**半徑固定 0.60、只動 `G`**（雙邊網格的空間
解析度）。六張影像 × 三類指令、6000 步，其餘與 `runs/ip2p_colour_budget` 逐項
相同，故 `G = 16` 那一點直接用該批的 `r06`，不重跑。

問的是：`runs/ip2p_colour_budget` 已經證實半徑不是槓桿，那麼**容量**是嗎？
`ip2p_color_hunt` 曾量到 8×8 → 16×16 讓位移由 0.4072 升到 0.5441。

`G` 同時決定三件事：容量（12·D·G²）、頻帶（`f_n ≈ G/H`，決定抗重取樣）、
以及產物外觀（`G = 1` 是全域常數映射＝真正的「換色」，`G = 16` 是色塊）。

## 結果

| `G` | 容量 | 身分降幅 | 成功 |
|---|---|---|---|
| 1（全域常數） | 192 | **−0.014** | 1/15 |
| 4 | 3 072 | −0.004 | 0/10 |
| 16（＝`r06`） | 49 152 | +0.015 | 3/15 |
| 隨機 `G = 1` | — | −0.022 | 0/12 |

**容量增加 256 倍，降幅只從 −0.014 走到 +0.015——全部在雜訊裡。**
沒有峰值；`G = 1` 與 `G = 4` 甚至是負的（防禦後的身分比未防禦的編輯還高）。

## 這一批判定了一個事先登記的預測

`docs/DIRECTION.md` 在開跑前寫下三種情形與各自的結論：

| 若量到 | 則 |
|---|---|
| `G=1` 與 `G=16` 接近 | 容量不是瓶頸 → 多尺度疊加不會有用 |
| `G` 越大降幅越高 | 效果綁在頻率上 → 疊加只是把容量堆在沒用的頻帶 |
| `G=4` 附近有峰值 | 存在甜蜜點 → 疊加值得做 |

**前兩種同時成立**（既接近又單調），故依當時的判準：
**多尺度疊加不必做**，不要再把容量堆到低頻上。
