# 臉框內的自然度：把局部形變壓回仿射

派工 `scripts/immunise_field.py`，設定 `configs/immunise_field_affine.json`，
鏈式腳本 `scripts/affine_chain.sh`。自變數只有**臉框內的自然度約束**，
載體、目標函數、求解、評估全部與 `runs/field_ladder/` 相同。

## 圖上看到什麼

`runs/field_ladder/` 的 `flow_16` 在 `task_env_weather_114555` 上把鼻子局部
拉長。那不是「另一張臉」，是 warp 的痕跡。同一檔在 `task_attr_mod_color_123744`
與 `task_env_weather_126577` 上沒有這個問題——差別在臉佔畫面的比例。

原因在參數化：`flow_*` 的三道約束裡沒有一道管臉框**內**的形狀。16×16 控制網格
在 512 px 上是 32 px 間距，一個臉框裡有五六個自由的控制點，足夠做出局部隆起。
`flow_rigid` 只作用在臉框外。

## 假設

**人眼判定不自然的是局部形變，不是整體形變。** 臉整體被壓扁、拉長或旋轉，
讀起來只是另一個人（而觀看者手上沒有原圖）；鼻子被單獨拉長讀起來是壞掉的。
這兩件事在數學上分得開：前者是仿射，後者是仿射以外的殘差。
`tests/test_field_carriers.py` 的 `test_局部隆起的殘差遠大於整體形變的殘差`
把這個分辨力釘住——同樣 8 px 的最大位移，整體拉伸的殘差 < 1e-3，
局部隆起 > 10 倍。

所以要補的不是更小的預算，而是一道**把臉框內壓回近仿射**的約束，
同時讓仿射那一段走得更遠。

## 兩條路徑

| 路徑 | 變體 | 怎麼做到近仿射 |
|---|---|---|
| 約束 | `face_rigid_08` / `_16` / `_32` | 16×16 網格不變，加第四道 `flow_face_rigid`：臉框內位移對最佳全域仿射的殘差 CVaR99 ≤ 0.75／1.0／1.5 px |
| 參數化 | `coarse_16` / `_32` | 改用 6×6 網格（512 px 上控制點間距 85 px），臉框裡只有兩三個控制點，近仿射是結構保證，不設 `face_rigid` |

臉框預算隨之開大到 8／16／32 px：被限制的是形變的**種類**而不是**幅度**。

兩條路徑測同一個假設。它們的失效方式不同：約束那一條可能在可行域裡找不到點
（`free_feasible_step` 會是 −1），參數化那一條可能連仿射都做不出足夠的變化
（`flow_px_max` 會遠低於上限）。逐列都報得出來。

## 怎麼讀

`cap_reached` 逐列列出四道約束各自達到多少、上限是多少，順序與 `cap_names`
相同。`flow_face_rigid` 貼住上限而 `flow_face` 沒有，代表綁住解的是自然度
那一道，不是幅度——`runs/field_ladder/` 的高檔位就是這個形狀（貼住的是
`flow_rigid` 0.4977/0.5，而不是臉框預算）。

自然度仍然由人眼判定。`scripts/field_readout.py` 的 `subject_id_defended`
只是把「防禦圖本身還是不是這個人」量出來，不是自然度的門檻——
三道自動門檻都已經被最佳化鑽過。
