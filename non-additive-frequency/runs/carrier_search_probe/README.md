# 在判準上直接搜尋載體結構

派工 `scripts/carrier_search.py`，設定 `configs/carrier_search_probe.json`。
自變數是**載體的結構**，由 (1+9) 演化策略在真判準上搜尋，每個候選點跑一次真的
InstructPix2Pix 編輯。

## 為什麼有這一支

`runs/color_scaleup_search/`（1440 列）量到全域仿射的顏色載體在 ΔE00 6.3 的
工作點上，主體身分降幅是 −0.002 到 0.0043；衣物格的防禦後編輯圖與未防禦的
編輯圖幾乎逐像素相同。那一族的天花板已經量到。

這一支把三件事一起換掉：載體的容量（空間變化的顏色場、可搜尋的帶寬）、
分工（整圖濾鏡與衣物、臉三段同時作用）、以及目標函數（見下）。

## 目標函數

逐格用**同一格未防禦的攻擊**當分母，把條件正規化到 [0,1]，1.0 表示「這個條件
跟沒有防禦時一樣完好」，再取軟極小：

```
id_norm  = 主體人臉餘弦(編輯後) ÷ 未防禦的同一個量
use_norm = NIQE(未防禦編輯) ÷ NIQE(防禦後編輯)
L        = softmin(id_norm, use_norm)
```

**指令那一項照算照報，但不在目標函數裡。** 三種寫法（方向分數、終點對齊、
對齊增益）都在圖上被推翻過：搜到的點被判成「指令沒完成」，而防禦後的編輯圖上
衣服確實換成指令要的顏色、人也認得出來。CLIP 在這個粒度的增益只有 1% 上下，
與防禦自己造成的位移同量級。量不準的項不可以主導連言。

身分讀數用 `metrics.identity.anchored_identity`：在**原圖主體框的固定座標**上
裁編輯輸出取嵌入，偵測器不參與。先前的版本在偵測不到臉時把身分記成 0.0，而
0.0 幾乎是餘弦能拿到的最好值，等於獎勵搜尋去把顏色推到偵測器失手。

## 約束

| 約束 | 值 | 理由 |
|---|---|---|
| 全圖 ΔE00 | ≤ 16 | 無上限時搜尋把色差推到 28–52，產物是螢光假色 |
| 臉上 ΔE00 | ≤ 16 | 全圖上限會被面積稀釋：臉佔約 5%，臉推成螢光粉綠、全圖仍只有 13.6 |
| 防禦圖 NIQE | ≤ 原圖的 1.4 倍 | 只剩兩項的目標可以靠把載體輸出弄爛得分 |
| 高頻 | 不設限 | `hf_ratio_rgb_total` 逐列量、逐列報，但不擋候選點 |

## 種子

搜尋只看 `search_seeds`（11001），回報只看 `report_seeds`（17001/27001/47001），
程式檢查兩組不相交。`runs/color_scaleup_search/` 的 `search` 臂兩者同為 17001，
那些數字是 in-sample。

## 三個臂

`searched` 搜到的載體、`start` 現行的全域仿射（原地對照）、`undefended` 未防禦。
每臂每個回報種子一列。

## 批次

| 目錄 | 設定 | 結果（`searched` 中位） |
|---|---|---|
| `carrier_search_fixed` | 無 ΔE00 上限 | criterion 0.134、身分 0.109、ΔE00 28–52，產物螢光假色 |
| `carrier_search_de16` | 全圖 ≤ 16，兩段 | criterion 0.960、身分 0.905 |
| `carrier_search_face` | 全圖 ≤ 16，三段（臉沿用衣物配色） | criterion 0.946、身分 0.901 |
| `carrier_search_palette` | 全圖 ≤ 16，三段＋真實膚色配色 | criterion 0.916、身分 0.879 |
| `carrier_search_facecap` | 再加臉上 ≤ 16 | 見該目錄 |

`carrier_search_palette` 的 9 個穿透案例逐張看過，全部是臉上局部超標換來的，
所以才有 `facecap` 那一批。

## 代理與判準的秩相關

每個候選點的 VAE latent 位移與高頻比一併寫進 `search_trace.csv`。判準修好之後
量到 latent 位移與判準的秩相關是 **−0.63／−0.58**（720 個候選點）；在壞掉的
判準上量到的是 +0.04／−0.28。可微代理那條路因此有依據，但尚未接上。
