# 隨機化幾何 EOT：未淨化的代價很高，抗淨化的收益未量

**尚未進入 `docs/RESULTS.md`**，且**這一批只有一半**——未淨化的讀數齊了，
但它存在的理由（抗裁切）**還沒跑**，不可據此下裁決。

`--purify-aware eot_geometry`：每步抽一個裁切比例（0 / 0.05 / 0.10 / 0.15），
偏移置中（評測算子是中心裁切，其幾何是以中心為不動點的純放大、淨平移為零，
見 `runs/ip2p_residual_signature/README.md`）。其餘旗標與 `b_ph_*` 完全相同，
故兩者可直接對照。13 張，驅動 `scripts/eot_geometry_sweep.sh`。

等失真對照（`scripts/matched_distortion_table.py`，`--group-by purify_aware`）：

| 錨點 DISTS | 有幾何 EOT | 無（`b_ph_*`） |
|---|---|---|
| 0.0900 | 位移 0.5132、PSNR 27.25、擋下 3.6/13 | 位移 **0.6414**、PSNR 27.16、擋下 **9.4/13** |
| 0.1280 | 位移 0.5747、PSNR 25.44、擋下 4.8/13 | 位移 **0.7002**、PSNR 25.38、擋下 **12.0/13** |

**未淨化的位移掉 18–20%、擋下率掉超過一半，而失真沒有變便宜。**

這與 `RESULTS.md`「針對淨化最佳化沒有改善抗淨化」記下的型態一致（該處三個
變體「未淨化強度掉 10–25%」），這一支掉得更多。

**但那條裁決不能直接套用在這裡**：先前那三個變體（固定 JPEG75、課程排程、
多算子 EOT）都不是為了幾何而設，而本支是；且本支是在
`band_transfer.csv` 量出「裁切是把擾動搬走、不是拿掉能量」之後才設計的。
**判準是抗淨化的淨增益，那一格還沒跑。**

要它有意義，必須付得起這個未淨化的代價——也就是 `crop_resize0.1` 的淨增益
要從 +0.0360 升到足以補回位移掉的 18%。**跑 `phase_retention.py` 之前不要
下結論。**
