色相扭曲與局部重繪

三個方向都來自第一輪逐張看圖看到的具體問題。

色相

ab_warp：分預算的軸換成色相

curve_dual_chroma 的產物自然，但防禦只與主表打平。瓶頸在載體： 逐 RGB 通道的曲線分不開膚色與背景，兩者在通道值上大量重疊， 壓低膚色就等於壓低所有共用那幾段通道值的顏色。man_00 整圖 只到 ΔE00 7.44 而上限是 16，就是這件事。

映射改到 CIELAB 的 (a,b) 平面：7×7 個錨點的 RBF 位移場 ＋ 單調亮度曲線。膚色在那個平面上是一塊緊緻區域，臉那道上限只釘住它附近的 錨點。映射仍然全域，接縫在構造上不存在。

已跑完的四張：整圖 ΔE00 11.77／7.79／14.30／13.98， man_00 從 7.44 到 11.77。切到「色度平面」那一層可以看到位移場 本身避開了哪一塊。

身分

style_affine：photorealism prior

每個視窗解一個 3×3 矩陣加位移，使 A·x + b 最接近 SDEdit 的 輸出，再把 A、b 平滑後套回原圖。輸出因此被限制成 輸入的局部仿射函數——邊只能是輸入的邊乘一個係數，不會長出新結構。 這是 photorealistic style transfer 那一族的標準答案。

先前的單通道 guided filter 只約束了一個純量，跨通道的色彩混合仍自由， 髮際對亮天空還有殘留輝光。三通道一起解才是那一族真正在用的形式。

正則化階梯（身分餘弦／整圖 ΔE00，三張）： 24/0.005 → 0.679／10.4、 32/0.02 → 0.702／10.7、 48/0.05 → 0.762／11.4。 兩個方向同時變好，交付取 48/0.05。

身分

兩個 inpaint_*：受保護的那一塊不送進模型

身分不是被「保住」，是根本沒有被碰過。kept_bitexact_frac 逐張驗證保留區真的逐位元相同，八張全部 1.0， 身分餘弦 0.9988–1.0000。 那一欄不是 1.0 就代表合成寫錯了，它存在就是為了讓那件事有症狀。

其中一個預期會在 inpaint 場景上失效，而那是設計的一部分。 inpainting 受害模型重繪的區域正好就是主體之外——也就是 inpaint_bg 改動的那一塊，會被整個蓋掉。這與主表的 diffvax 是同一個幾何關係（inpaint 主體內位移 0.0348）。 inpaint_outside_face 改的是主體內的頭髮與衣服， 受害模型會保留那一塊。

切到「pipeline 原輸出」那一層可以看到合成前的樣子， 「保留場」那一層是白＝逐位元保留原圖。

這一頁不能照字面讀的地方

四件事。

三種預算混在同一排

三個 curve_* 與 ab_warp、style_affine 綁在整圖 ΔE00 ≤ 16／臉框 ≤ 8；兩個 inpaint_* 沒有任何失真上限（重繪區是生成的，ΔE00 對它沒有意義）。 inpaint_outside_face 的整圖 ΔE00 是 24.8–34.1、PSNR 7.1–10.1， 那不是「失真控制得差」，是它根本不在同一種預算裡。

ΔE00 臉框對兩個 inpaint_* 沒有意義

它們的臉框 ΔE00 是 0.003–0.96，低得像沒動——因為臉真的沒動， 那個值只是 PNG 量化的殘差。用它跟其他臂的 8.0 比大小是錯的。

還沒有任何防禦強度的數字

位移（LPIPS(編輯(原圖), 編輯(防禦圖))）與保留率都還沒算， 因為編輯與淨化那兩層還在跑。防禦圖好看不等於防禦有效， 本專案已經量到過兩者脫鉤。
