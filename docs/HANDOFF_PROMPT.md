## 現況：第一次乾淨的實測，結果是否定的

E25／E26 修好攻擊端（原本沒有 classifier-free guidance）與判準（原本用

**在試過的每一個運作點上，防禦都沒有阻止文字編輯達成 prompt。** 加性

## 兩個結構性問題

兩項都寫在 `RESULTS_E25-E26.md` §6 的待決清單上，而後續三個實驗
（E27、E28、E29）處理的都是清單上的其他項目。這是本階段要面對的核心。

### 一、目標函數最大化的量，已被判定不對應防禦成功

`objective.py:348-352` 的 `untargeted` 模式是

    L_def = mean_i max(0, margin − LPIPS(y_def_i, y_orig_i))

即最大化「防禦圖被編輯的結果」與「原圖被編輯的結果」的 LPIPS 距離。那正是
`edit_shift`，而 E25 §1.2 已證實它與編輯是否失敗不對應（726 格語意失敗 0 格）。
判準在 E25 之後改成了語意軸，**目標函數沒有跟著改**。

兩張都服從 prompt 的擴散輸出，彼此的 LPIPS 距離本來就可以很大。把它推到
0.42–0.47 不需要讓任何一張停止服從 prompt。

`runs/` 的 59 個有記錄的 `env.json` 全部是 `untargeted`。另外兩個模式
（`targeted`、`crossattn` 的 `attn_mode="suppress"`）都已實作、有測試覆蓋、
在 tiny-SD 上跑通，但**從未在真實 SD 上產生過任何資料**。

### 二、失真預算比文獻低 5–8 倍

本專案運作點 `defimg_lpips` = 0.036–0.086。DCT-Shield（ICCV 2025）自報 0.267，
PhotoGuard／MIST／AdvDM／SDS／DiffusionGuard 為 0.284–0.362。

現有資料**無法分辨**「這個方法無效」與「任何方法在這個預算下都無效」。

注意研究目標的原文是「在**匹配人眼可辨失真**下勝過加性基準」——是**匹配可辨**，
不是不可見。把兩臂一起放到文獻的預算區間並不違反目標，只要兩臂仍然匹配。
現行的 τ ≤ 0.10 是專案自己選的，不是目標強加的。

## 候選方向（不是清單，是起點）

以下每一條都要你自己查證與比較，不要照單全收：

1. **換目標函數。** `targeted`（往固定目標推）與 `suppress`（壓低內容 token
   的注意力質量）都已可用。後者是三者中唯一直接對著「讓編輯不服從 prompt」。
   要問的是：這兩個目標在真實 SD 上有沒有效？哪一個的梯度訊號較強？
2. **把失真預算拉到文獻區間再比一次。** 這會同時回答「方法無效」與「預算太小」
   哪一個成立。成本低——網格照跑，只改 τ。
3. **重新檢查威脅模型與攻擊設定。** 現行是 SDEdit、strength=0.5、n_edit=10。
   文獻的防禦多半針對 inpainting 或 img2img 的其他設定。攻擊設定選得對不對，
   會決定防禦有沒有著力點。
4. **非加性的其他參數化。** site C（色度矩陣場）的綁定者恆為色度 hinge，
   是參數化的固有性質（六個學習率跨 3 倍範圍，結論不變）。若要繼續走非加性，
   需要一個作用機制不與單一保真約束重疊的形式。

## 這個專案最重要的幾條經驗

- **「匹配失真」已經三次被證明是假的**：site S 買模糊（LPIPS 對模糊不收費）、
  site C 買色調偏移（鈍化約束只看亮度）。每一次都是最佳化找到了約束集的盲區。
  每引入一個新參數化，先用等 LPIPS 多臂探針量出現行約束對它收不收費，
  再放進網格（作法見 `scripts/p9_chroma_probe.py`）。
- **不得憑文獻聲譽選指標。** ΔE00 是色差的國際標準，實測在等 LPIPS 下完全
  分不出加性雜訊與可見色偏。NLPD 與 VIF 也是同樣被推翻的前例。
- **指標之間出現矛盾時，把影像做成比對頁給人眼判斷。** τ_acut 與 τ_chroma
  兩個門檻都是這樣定出來的。E29 的否定結果也是先由影像確認、再由 SigLIP 佐證。
- **綁定者診斷是常設步驟。** `scripts/e27_binding_check.py` 對任意 run 目錄
  運作。已經踩過四個假的綁定者，每一個都會讓整批網格變成無效資料。
- **推翻自己先前的判斷時，把錯誤的假設與推翻它的資料一起留在文件裡**，
  不要改寫成正確版本。
