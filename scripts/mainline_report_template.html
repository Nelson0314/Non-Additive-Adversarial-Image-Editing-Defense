__EDIT__

語意指標比對的是什麼

兩張編輯輸出之間的影像—影像餘弦，完全沒有用到文字。

edit_clip_sim = cos( CLIP_image(未防禦的編輯), CLIP_image(防禦後的編輯) ) edit_siglip_sim = cos( SigLIP_image(同上兩張) )

模型是 openai/clip-vit-base-patch32 與 google/siglip-base-patch16-224。 數值越低代表防禦越成功——內容被換掉了。

影像對文字那條路已經棄用：OmniEdit 給的是指令不是 描述，那條路徑在本專案的服從率驗收上近乎隨機（25 張只有 15/25 為正）。 所以這兩欄不是拿編輯指令當文字端算出來的。

抗淨化的淨增益

扣掉空白地板 · 九個算子 · 綠色是該欄最好的一格

__GAIN__

為什麼是淨增益不是比例

淨化算子自己就會把編輯推開。不扣掉那個空白地板， 「淨化後位移較大」無法排除「該算子本來就把編輯推得比較開」這個平庸解釋。

而比例（保留率）在分母塌陷時不可解讀——本專案量到保留率與分母的相關係數 是 −0.83／−0.900。本批有多個弱工作點，分母塌陷不是理論上的顧慮。

人眼判定：淨增益的倍數不等於防禦成功

逐張看過原生 512 的大圖 · 判準：原圖還認得出來嗎

__VERDICT__
淨化條件淨增益擋下邊緣 逐張
 這是本次實驗最重要的一件事。重壓縮（jpeg50／jpeg30）上本方法的淨增益 贏 2.2–3.7 倍，但那個區間兩邊都是 0/10——編輯全部執行成功、場景全部可辨， 差的只是劣化程度。唯一還有真正擋下的是 jpeg75，而那一格本方法輸 （淨增益 0.4072 對 0.4533，擋下 0 對 2）。位移這個讀數把「變糊」與「重畫」算成 同一件事，在強淨化後兩邊都只剩劣化，倍數差是在雜訊層級上比出來的。

判準

模型把圖重畫成無關的場景、或整張變成噪紋，都算擋下；原圖仍認得 出來、只是變糊變髒的單純劣化不算——攻擊方還是拿得到可用的東西。
