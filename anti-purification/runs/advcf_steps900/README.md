# 收斂檢查：步數 300 → 900

`configs/advcf_steps900.json`，`scripts/paper_baseline.py --objective free`。
評估 `configs/evaluate_pilot.json`。五組，每組 32 列。**只有一個自變數：steps。**

## 為什麼跑

`free_curve`（固定驗證抽樣上的收斂曲線）顯示 **300 步不是收斂點**：

| 組別 | 後三分之一的分數變化 | 末段斜率／100 步 |
|---|---|---|
| `advdm_w10` | −0.045 | −0.060 |
| `pilot_out_fixed` | −0.061 | −0.081 |
| `pilot_advdm` | −0.021 | −0.028 |
| `pilot_free` | ＋0.031 | ＋0.042 |
| `sds_advdm` | ＋0.017 | ＋0.022 |

前三組在第 300 步還在降，後兩組末段在震盪上升。所以現行排名有一部分
可能只是「誰在 300 步內走得比較快」。

`check_every` 維持 10、`probe_every` 25 → 50。`lr_final_ratio` 的餘弦退火
`T_max` 跟著 steps 走，所以 900 步版學習率降得比較慢——這是「跑更久」本身的
一部分，不是額外變因。

`advdm_w10` 的 PSNR 從 17.52 升到 20.25——找到一個代價更低的解，但推得更少。

## 三件量到的事

**一、「跑更久會更好」不成立。** 五組裡只有 `sds_advdm` 四道全面變好
（+0.013 到 +0.030），`advdm_w10` 四道有三道變差（identity −0.0385、
crop −0.0486、CLIP +0.0220），而它正是 300 步末段降得最陡的那一組。

**二、代理分數與編輯位移再次脫鉤，而且方向與先前相反。**
`advdm_w10` 的代理分數從 300 步到 900 步繼續降，編輯位移卻掉了 9%。
先前 `runs/advcf_term_scale/` 量到的是「項的值沒動但效果變好」。
**兩個方向都出現過，所以求解端的分數不能用來預測編輯端。**

**三、排名會隨步數翻。** 300 步第一名 `advdm_w10`（0.4169），
900 步第一名 `sds_advdm`（0.4107），差 0.006——遠小於批內重跑帶。

**逐圖的變化幅度大於臂間差距**：`pilot_free` 在 `task_env_weather_121086`
單張上是 +9.5%，兩張圖的中位數是 −1.2%，第二張把它抵銷掉了。
單圖數字不可當結論。
