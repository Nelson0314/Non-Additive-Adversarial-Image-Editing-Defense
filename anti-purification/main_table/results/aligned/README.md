# 等失真臂：十個 baseline 縮到同一個 LPIPS 錨點

`results/` 的 `defence_<方法>.csv` 是**各篇原生預算**下的求解結果。這個子目錄是
另一組臂：把同樣十個方法的 eps 縮到防禦圖失真對上同一個錨點，其餘設定不動。

**錨點**：`colour_curve_ours` 在原生設定下的八張平均 `fid_lpips` ＝ **0.3344**。
錨的選法沒有判定成分——它是本專案自己的方法在主表上的操作點，取它當錨是為了
讓其餘十列落到同一個失真水準，不是主張 LPIPS 比其他失真指標更適合當預算軸。

## 為什麼要有這一組

原生預算下十二列的防禦圖失真 `fid_lpips` 從 0.0426 到 0.6661，**差十五倍**，
而位移排名與失真排名幾乎同序。在那個狀態下，一列的位移比另一列高，讀不出是
「防禦較有效」還是「擾動較大」。`BASELINE_PROVENANCE.md` 已記載原生預算差到
2.6 倍且束縛種類不同，這一組是把該檔 §「已實作、已審計，但不在主表的方法」
之外的另一半補上：同一個失真水準下的十列。

## 旋鈕與它的副作用

`code/defence_run.py --eps-scale <倍率>` 把該篇的原生 `eps` 乘上倍率，
**`step_size` 同倍率縮放**以維持 `step_size / eps`——只縮 `eps` 會讓第一步就撞上
投影邊界、有效步數變少，量到的就不只是預算的效果。倍率不等於 1 時該列強制標
`modified_from_paper=True`，原生值留在 `eps_native` 欄，倍率留在 `eps_scale` 欄。

**這一組的每一列都不是那篇論文的設定，論文的任何保證都不適用。** 其中
`dct_shield` 與 `dct_shield_y` 的 `eps` 已降到 1 以下，論文 §4.2 的抗 JPEG 條件
明確失效（擾動不足以造成一個量化級的改變），`modification_note` 逐列寫明。

倍率跨了十三倍（`dct_shield_y` 0.073 到 `dia_r` 0.969）——**各篇的原生 eps 完全
不在同一個尺度上**，這一欄本身就是一個讀數。

對同目錄的防禦圖與 `__orig.png` 逐張算、八張平均；其餘四欄取自 `fid_*`。

## 兩個沒有對齊點的條件

| 條件 | 為什麼 |
|---|---|
| `colour_curve_ours` | **錨本身**，定義上不動。 |
| `diffvax` | **前饋式免疫**，一個訓練好的 UNet++ 前向一次就吐出擾動，沒有迭代、沒有預算旋鈕；`BaselineSpec` 的 `eps`／`steps`／`step_size` 在它身上都沒有對應值。`--eps-scale` 給了非 1 的值會直接停住而不是靜默忽略。它的原生失真是 LPIPS 0.0426，本來就遠低於錨點；要移動它只能換權重或改輸出層，那是另一件事。 |

## 錨住一個指標不會把其餘的錨住

同一批影像上，LPIPS 收斂到 1.11 倍之內時，其餘三個失真指標仍然是散的：

| 指標 | 全距 | 倍率 |
|---|---|---|
| LPIPS（錨點） | 0.3082–0.3425 | 1.11× |
| ΔE00 | 0.539–1.598 | 2.96× |
| PSNR | 38.74–47.07 dB | 8.33 dB |
| rms | 0.00443–0.01182 | 2.67× |

`mist`（LPIPS 0.3149、PSNR 45.82）與 `dct_shield_y`（LPIPS 0.3164、PSNR 38.74）
的 LPIPS 差 0.5%，PSNR 差 8 dB。`lab/` 線從 ΔE00 錨（緊到 1.009×）量到同一件事，
PSNR 仍差 8.98 dB、L∞ 差 6.21 倍。**錨得更緊沒有讓其餘指標收斂**，所以引用這一組
時要指名是等 LPIPS 的失真，並把其餘三欄一起報。

## 倍率是怎麼定出來的

三步，總計約六卡時，比直接掃四點 × 八張（約十三卡時）省。

1. **粗掃**：八個便宜條件在 `man_00` 一張上跑 `eps_scale ∈ {0.05, 0.1, 0.25, 0.5}`，
   得各自的 `eps → LPIPS` 曲線。單張只用來取斜率，不取絕對值。
2. **內插**：目標先用該條件「`man_00` ÷ 八張平均」的比值換算到單張尺度（比值落在
   0.95–1.08），再在 `log(LPIPS)`–`log(scale)` 上線性內插。**十個條件的目標都落在
   掃描到的區間內，沒有一個用到外插。**
3. **確定點**：用內插出的倍率跑滿八張。落點在錨的 −7.8% 到 +2.4%。

`photoguard` 兩臂另外處理：6,400 s/張，是其餘條件的四十到八十倍，所以粗掃只取
兩點（`photoguard_c` 0.25／0.5、`photoguard_linf` 0.075／0.15）。後者的 0.0857 與
`mist` 的 0.093 相近，與預期一致——兩者同樣是 L∞ 16/255、同樣 sign 更新、
原生 LPIPS 也相近。

`photoguard_c` 值得單獨記一筆：它的 PSNR 在固定 `maxnorm` 下與影像無關
（八張全距 0.006 dB，閉式 `rms = maxnorm / (2·√(3·512·512))`），**但 LPIPS 不是**
——原生設定下八張的 LPIPS 全距 0.120。所以它的對齊點仍然要跑滿八張，
不能靠閉式或單張代表。

## 這一組還沒有的東西

**編輯端沒有重跑。** 這裡只有防禦圖對原圖的失真，沒有位移、沒有保留率。
要得到「同一失真水準下的防禦效果」還需要對這十組防禦圖重跑
`edit_displacement`（768 格）與 `edit_purified` ＋ `edit_retention`（5,376 格）。
在那之前，**這一組不能拿來比防禦效果**，它目前只說明一件事：各篇原生 eps 不在
同一個尺度上，以及把它們拉到同一個 LPIPS 需要多大的倍率。
