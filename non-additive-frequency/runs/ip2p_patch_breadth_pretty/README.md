# 十二張擴增影像加上美觀花紋

與 `runs/ip2p_patch_breadth/plain_*` 只差內容旋鈕，其餘設定完全相同。

## `tile_a`（平舖 64 ＋ α 0.6），十二張

| | 中位數 |
|---|---|
| plain（未美化） | 0.4266 |
| **tile_a** | **0.2348** |
| tile_a ÷ plain | **0.73** |
| tile_a ÷ 同幾何隨機 | 2.15 |

**美化的代價一致地推廣了**：瑪利歐一張上是 0.74，十二張的中位數 0.73。
梯度相對隨機的優勢由 3.60 降到 2.15。

逐圖的 `tile_a ÷ plain` 落在 0.37–1.16，兩張超過 1（玩具卡車 1.16、
坐墊 1.06）——美化在那兩張上沒有代價。

## 看圖看到的：美化只在淺色衣服上有效

`env_weather_193600`（淺藍毛衣）、`obj_add_362298`（灰上衣）、
`obj_remove_704852`（藍睡衣）讀起來確實像印花衣服——規則的重複、原本的
褶皺從半透明底下透出來。

但**深色衣服上仍然像雜訊**：`attr_mod_color_42929`（黑上衣）、
`obj_swap_rand_mask_417469`（深綠格紋襯衫）上，高飽和的彩色花紋與衣服本身
的暗色對比太強，平舖與半透明都救不了。

原因是**花紋的色彩完全自由、不跟著衣服走**。`--patch-tint`
（`runs/ip2p_patch_tint_colour/`）就是針對這一點，且代價更低（87% 對 73%）。

另記：`obj_swap_rand_mask_401099`（披薩）的 `tile_a` 編輯結果是**乾淨成功的
編輯**——那張本來就是「隨機 ≥ 最佳化」的兩張不可解讀影像之一，美化之後
防禦形同失效。

## 沒做的

`tv10` 那一組**已取消**：tint 在每一個軸上都贏過它（87% 對 76%，外觀更好），
再跑它的邊際價值太低。`tint30` 的十二張正在補（先送六張 `task_attr_*`，
其餘等卡）。
