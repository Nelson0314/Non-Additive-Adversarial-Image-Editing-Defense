--------------------------------------------------------------------
白盒（攻擊方用 stock SD）、外掛模組形態下，找出非加性方法，在匹配人眼可辨
失真下勝過加性基準。

  主    非加性「更」抗淨化：淨化後的效果衰減率低於加性 baseline
        -> **已成立**（FND-033），含 C&R 串接
  並列  防禦效果本身不輸：未淨化時的位移量不低於加性 baseline

**不再追求語意抵抗。** CLIP-T 掉幅照報但不作為成敗判準（FND-024/029/030，

**判準以人眼為主、數值指標為輔。** compare.html 是主要產出物，每一格都必須

五、site F 是什麼（一段）
--------------------------------------------------------------------
    x_def = OLA( irfft2( rfft2(w*P_b) * exp(i*g_b*m_w*theta_b) )*w ) / OLA(w^2)

把影像切成 32x32 重疊區塊、加 Hann 窗做 FFT，只把**相位**轉一個角度，幅度
譜逐位保留，再重疊相加回去。theta 是唯一的參數；紋理度閘 g_b（結構張量
coherence）與徑向頻率閘 m_w 由原圖算一次即固定。theta=0 時輸出逐位元等於
原圖。文獻依據是 Random Phase Noise（Galerne et al., IEEE TIP 2011）。

定案參數：block=32、r_min=0.12、紋理閘分位數 0.5。

七、動手前必須知道的坑
--------------------------------------------------------------------
量測與方法
  * **沒有任何單一指標可以當兩個家族的共用預算軸。** 使用者裁定的兩條門檻
    （phase 1.30 / add 1.2/255）在十六項指標上沒有一項落在同一個值：DISTS 差
    4.5 倍、GMSD 35 倍、最接近的 LPIPS 也差 1.28 倍。每個條件跑自己的可接受
    上限。FND-035
  * 做加性/非加性比較時，預算指標必須先講清楚。同一個問題在不同預算軸下
    答案會相反。FND-026 / FND-034
  * 未防禦的編輯必須真的成功，否則抗編輯那一欄的分母不成立。DEC-022
  * retention 的分母塌陷時不可解讀（METRICS.md 第 6 節）。phase_rand 的
    retention 1.4-3.4 是分母只有三分之一造成的假象，不是它比較強。FND-033
  * latent 半徑不是保真約束。FND-028
  * 階段二的 CFG 必須是 1.0、反演必須走淺噪聲帶（50 格排程只執行前 11 格）。

工程
  * **本 repo 用 sparse-checkout（cone mode）。** 新增頂層目錄或新的 runs/
    子目錄前要先 `git sparse-checkout add <路徑>`，否則 git add 會被拒絕。
  * **測試跑的期間不要改原始碼。** 症狀是隨機幾個測試失敗而重跑就好。
  * dia_r 與 mist 必須開 use_ckpt 與 vae_ckpt，否則 OOM。
  * photoguard_c 需要 200 步/圖，實測約 1.3 分/步（4.4 小時/圖）。
  * 同一個批次目錄只允許一個寫入者——**不是鎖，是覆寫語意**：write_csv 每次
    呼叫都整份重寫 results.csv。要平行就用不同 --out，再用 merge_runs.py 併。
  * runs/ 是唯一的證據來源，全部入版控。改 .gitignore 的 runs/ 區塊後必須用
    git status --porcelain --ignored 確認沒有結果檔被靜默排除。
