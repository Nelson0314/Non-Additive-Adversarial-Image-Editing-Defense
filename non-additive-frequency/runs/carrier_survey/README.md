# 衣物載體能用在多少張影像上

三份 CSV，全部在 CPU 上跑、不需要 GPU。

## `clothes_survey.csv` — 未守門的 ATR 衣物面積（147 張）

`clothes` ≥ 0.01 有 102 張（69.4%）、≥ 0.05 有 86 張。

**這份是上界，不是候選池。** 拉圖之後看到大量偽陽性：ATR 沒有「這張圖裡
沒有人」這個輸出，它一定會把某些像素分到某一類，於是毛皮、菌傘、皮膚都被
標成 Upper-clothes。

## `clothes_survey2.csv` — 加上有人守門之後（147 張）

逐圖多記一欄 `face`，門檻可事後重掃。臉的面積在兩群之間差一個數量級：

| | clothes | face |
|---|---|---|
| 貓 | 0.5311 | 0.0002 |
| 蘑菇 | 0.3490 | 0.0000 |
| 手掌 | 0.2929 | 0.0000 |
| 真人（六張） | 0.2858–0.4802 | 0.0225–0.1800 |

`MIN_FACE = 0.01` 取在中間。**兩個已知判錯**：太空人（頭盔遮臉，face 0.0030）
被誤擋，猴子（face 0.0290）擋不掉。

守門後：147 張裡 **49 張有人**（33.3%）；`clothes` ≥ 0.05 由 86 降到 **47**。

依任務（守門後且 clothes ≥ 0.05）：`attr_mod_color` 13/30、`env_weather` 10/28、
`obj_swap_rand_mask` 8/16、`obj_remove` 7/30、`obj_add` 5/29、
`obj_swap_joint_mask` 4/14。

## `scaleup_candidates.csv` — 逐張量到的合法載體面積

衣物載體**結構上要求受保護主體與穿衣服的人是分開的兩個東西**——人被登記成
主體時，衣服全部落在受保護核心內，合法載體是 0（`task_attr_mod_color_11699`
就是這個情形）。故候選再過一道人眼篩選：畫面裡要有一個與人分開的物件。

主體名詞看圖登記在 `data/carrier_catalogue.yaml`，**不是從攻擊指令推的**。

十四張登記，十二張可用，合法載體 0.0589–0.3182（瑪利歐是 0.0861，多數比它大）。
兩張不可用的理由：`picture frame` 的 CLIPSeg 遮罩面積 0.999（畫框環繞整張圖），
`backpack` 的合法載體只有 0.0096。
