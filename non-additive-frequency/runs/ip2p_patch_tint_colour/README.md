## B · `--patch-tint`：目前最便宜的美化旋鈕

    λ · mean_over_support( ( blur_σ(c) − blur_σ(x) )² )，σ = 16

與既有旋鈕的代價比較（都以 plain 為 100%）：

| 旋鈕 | 保留 |
|---|---|
| tint λ=3.0 | **87%** |
| α 0.6 單獨 | 90%（瑪利歐一張） |
| 平舖 64 單獨 | 86%（瑪利歐一張） |
| tv λ=1.0 | 76% |
| 平舖 ＋ α | 74% |
| tv λ=2.0 | 56% |
| 平舖 ＋ tv 0.3 | 32% |

**λ 從 0.3 拉到 3.0 只掉三個百分點**（90% → 87%），幾乎不必調。機制如設計：
tv 罰掉支撐內所有局部變化、花紋一起被壓平；tint 只罰低頻，花紋的高頻結構
完整保留，被拉住的只有局部色調。由
`tests/test_patch_tint_and_colour_carrier.py` 的「棋盤式零均值高頻擾動幾乎
不動、同幅度常數色偏上升 20 倍以上」釘住這個差別。

**看圖確認它做到了要做的事**：和服由滿版彩虹雜訊變成米白底加紅粉花斑
（和服原本的配色）；Shrek 的灰背心由彩虹噪點變成黃綠色斑點（與膚色同調）；
盾牌的黑袖子由彩虹變成暗色斑點、融進黑衣服。

## C · 色彩重映射施加在衣服上：不成立

`apply_where = 載體 ∧ 主體補集`，主體仍逐位元不動。

- 鋼琴與盾牌上只有 plain 的 **12–14%**。
- 和服上的 0.62 看似漂亮，但**同半徑隨機色彩場就有 0.5637**——最佳化只買到
  1.11 倍。那個數字不是防禦學來的，是「把一件大面積和服整個改色」本身就讓
  IP2P 產不出原場景。

外觀上這一族確實最像真衣服（布料垂墜與織紋完整，因為它是既有像素的平滑
重映射而不是貼上去的內容），但效果撐不起來。

## 一個提出後被自己的量測推翻的假設

先看到「和服 0.6219 / 盾牌 0.0644，而載體面積 0.368 對 0.329」，提出
**衣服底色決定這一族有沒有施力點**（仿射重映射在輸入接近零處沒有乘性施力）。
兩個量測都不支持，記在 `runs/carrier_survey/`：

- `colour_headroom.csv`：載體區的 RGB 施力空間確實由亮度幾乎完全決定
  （Pearson r = **+0.968**，n=12；面積只有 +0.515）。**但它從最暗到最亮只差
  1.47 倍，而效果差 9.7 倍。**
- `latent_headroom.csv`：用攻擊模型自己的 VAE 量 `‖Δz‖/‖z‖`。主體 token 那
  一欄在十二張上只落在 0.194–0.417（2.1 倍），與亮度只有 +0.396，
  **與載體面積幾乎無關（+0.074）**。三個有效果數的影像裡，它把鋼琴與盾牌
  排反了。

**底色不是那個原因**，該假設收回。`ColorGridParam` 的 docstring 本來就寫著
它有偏移項、正是為了讓暗部推得動，那個機制早已被構造修掉。

兩件本身有價值的量測留下來：**隨機色彩場光是加在衣服上就把受保護主體的
latent token 推動 19–50%**（花紋碰不到主體，這是 VAE 編碼器的長程作用）；
而**那個推動量與載體面積無關**——與補丁族相反，補丁族的面積是主要旋鈕。
