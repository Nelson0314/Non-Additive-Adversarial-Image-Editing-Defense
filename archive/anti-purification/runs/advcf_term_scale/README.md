# 把每一項調到真的推得動載體的尺度再比

`configs/advcf_term_scale.json`，`scripts/paper_baseline.py --objective free`。
評估 `configs/evaluate_pilot.json`，與 `runs/advcf_pilot_eval/` 同一份。

**規模：兩張人像 × 兩類指令 × 一顆種子 = 4 格，每臂 32 列。**
分母是 `runs/advcf_pilot/pilot_free` 與各自對應的 pilot 臂，同設定同影像同種子。

## 為什麼跑

`runs/advcf_texture_sds/term_gradient_scale_converged.csv` 在 `tex_mist` 的收斂解
上逐項反傳，有效梯度範數是：

| 項（權重） | 收斂點 ‖g‖ | 對 `id` 的比 |
|---|---|---|
| `id`（1） | 0.379 | 1.00 |
| `enc`（0.5） | 0.178 | 0.47 |
| `out`（2） | 0.113 | 0.30 |
| `out_target`（2） | 0.092 | 0.24 |
| `sds`（1） | 0.073 | 0.19 |
| `cond`（1） | 0.072 | 0.19 |
| `diffusion_target`（1） | 0.038 | 0.10 |
| `diffusion`（1） | 0.036 | 0.10 |
| `enc_target`（1） | 0.020 | **0.05** |

**主流那一族在權重 1.0 下只有身分項的十分之一到二十分之一。** 所以
「這個目標函數沒有用」與「它的梯度比別項小一個數量級」在先前的讀數上長得
一模一樣。這一批把它們各自乘到與 `id` 同一個量級再跑，回答的是前者還是後者。

權重由收斂點的原始梯度範數反推：`diffusion` 0.0357 × 10 ≈ 0.357、
`diffusion_target` 0.0379 × 10 ≈ 0.379、`out_target` 0.046 × 8 ≈ 0.368，
都對到 `id` 的 0.379。

## `enc_target` 有兩個問題疊在一起

**一是量綱。** `‖z − z_target‖ / ‖z_target‖` 的分母跟著目標圖換，所以換一張
目標就換一個量綱：中性灰上收在 1.259／1.291、高頻紋理上收在 1.559／1.740。
兩張目標的數值**不可並列**。

**二是飽和。** 它以 `+w·tanh(·)` 進分數，而 `tanh′` 在 1.7 只剩 **0.12**——
87% 的梯度被吃掉，而紋理目標把它推得更深。

`MainstreamTerms(enc_target_norm='start')` 把分母換成原圖到目標的距離
`‖z_x − z_target‖`：起點恆為 1.0、與目標尺度無關。兩個 photoguard 臂都用它
配權重 8.0，**差別只有目標那一張圖**，所以它們是本專案第一次在同一個量綱上
比中性灰與高頻紋理。

## 隨機對照

`runs/advcf_pilot/` 沒有隨機對照，所以那一批 +3.7% 的領先沒有雜訊地板。
`rand_a`／`rand_b` 抽同一族的單調分段線性曲線（`ColorCurveLowFreqRandom`，
五個餘弦分量、半徑 80），**完全不經最佳化**，只二分幅度把 ΔE00 對到同一個
錨點。對抗臂比它多推開的那一段才歸得到最佳化頭上。

## 四件編輯端的事

**一、`advdm_w10` 是這個比較裡最強的一臂。** LPIPS 0.4175（對分母 +5.9%、對
同設定不同權重的 `pilot_advdm` **+11.8%**），CLIP 0.8380 遠低於次低的 0.8842，
crop 那一道 0.4812 也是最高。**AdvDM 的無目標擴散損失在這個載體上有效，
先前看起來無效是因為權重 1.0 下它的梯度只有身分項的十分之一。**

**二、代理項的值與效果脫鉤。** `advdm_w10` 的 `free_term_diffusion` 是
0.00124／0.00183，與 `pilot_advdm` 的 0.00124／0.00242 **一樣或更差**，
而編輯端是 +11.8%。加權改變的是解落在哪裡，不是那一項被推上去。
**所以「這一項的值沒動」不可以當成「這一項推不動載體」的證據**，


**三、隨機對照給出地板，而最佳化明確在地板之上。** `rand_a` 0.2588、
`rand_b` 0.2974，而最佳化臂在同一個 ΔE00 16 錨點上是 0.39–0.42，
**高出 32% 到 61%**。這與貼片線相反（那裡失真對齊的隨機抽樣贏過最佳化）。
`runs/advcf_pilot/` 當時「+3.7% 撐不住結論」那句話仍然成立——臂**之間**的
差距小於雜訊，但**最佳化對隨機**的差距大得多。

**四、紋理目標在同尺度下輸給中性灰。** `photoguard_tex_scaled` 0.3246 對
`photoguard_grey_scaled` 0.3954，兩臂只差目標那一張圖。求解端也同向
（`enc_target` 0.896／0.832 對 0.845／0.823）。機制說得通：全域單調 tone curve
能做的正是「把所有色調往中間壓」，**中性灰落在它的可達集合裡，高頻雜訊不在**。
**「Mist 用高頻紋理所以我們也該用」在這個載體上不成立**——決定哪張目標有用的
是載體的可達集合，不是文獻的選擇。

**五、targeted `out` 死了。** `out_target_w8` 0.2773 **低於隨機地板的
`rand_b` 0.2974**，是全批最差。加權（2 → 8）讓它更差（`tex_out_target` 是
0.3598）。LPIPS 對一張高頻雜訊目標接近上限、幾乎沒有斜率，加權只是把求解
拖進一個更差的角落。

## 三件求解端就看得出來的事

**一、起點正規化把 `enc_target` 救回了響應區。** `photoguard_grey_scaled` 的
這一項從起點的 1.0 被推到 0.845／0.823——**真的靠近目標了 16–18%**，而
`tanh′` 從 0.12 回到 0.53，梯度拿回 4.4 倍。預算也重新用滿（ΔE00 15.3–15.6），
不再像 `tex_photoguard` 只花到 9.11。**先前 PhotoGuard 這條臂受限於量綱與飽和，
不是方法本身。**

**二、`out_target` 加權沒用，因為目標不在載體的可達集合裡。** 權重 2 → 8，
項只動 1.6%（0.815 → 0.802），而解反而**少花了預算**（第一張 ΔE00 從 14.66
掉到 11.62、選點提早到第 120 步）。LPIPS 對一張高頻雜訊目標接近上限，單調
分段線性曲線再怎麼推也靠近不了——加權只是把求解拖進一個更差的角落。
與 `enc_target` 是同一個病的兩種形式：**一個是函數形狀飽和，一個是目標根本
不可達。**

**三、ΔE00 不是一個夠緊的等失真錨點。** 同一個錨點上，隨機曲線的知覺失真
明顯低於最佳化解：`rand_a` 的防禦圖 LPIPS 是 0.182／0.252、PSNR 25.26／24.35，
而 `mist_tex_w10` 是 0.360／0.341、PSNR 17.94／18.76。**最佳化推開編輯輸出的
那一段，有一部分是靠花掉 ΔE00 量不到的知覺預算換來的。** 這影響先前所有
「等失真錨點」上的臂間比較怎麼讀——`runs/advcf_anchor/`、`runs/advcf_pilot/`
與本批都一樣。

## 誠實區

- **4 格、單種子。** 先前量到批內重跑帶要九顆種子才穩下來。
- **`out_target_w8` 與 `tex_photoguard` 的 ΔE00 只有 11.6／9.1**，它們**不在**
  與其他臂相同的等失真錨點上，絕對值不可並列。
- **`advdm_w10` 是這一批唯一超出分母的臂，而它與分母的差距（+5.9%）
  仍然落在先前量到的批內重跑帶附近。** 要當結論需要九顆種子的複驗。
- **`advdm_w10` 的求解有一段跑在被別人疊用的卡上**（卡 6 同時有另一個使用者
  的 8.4 GB 行程），所以它的秒／圖不可與別臂並列。數值結果不受影響。
- 一個排程失誤：`photoguard_tex_scaled` 一度有兩個行程寫同一個輸出目錄
  （`paper_baseline` 的「輸出目錄非空就拒絕」守門看的是非空，而求解要跑八分半
  才寫第一張圖，這中間有一個空窗）。已在任何檔案寫出前殺掉其中一個，
  目錄當時是空的，**沒有結果被覆蓋**。
