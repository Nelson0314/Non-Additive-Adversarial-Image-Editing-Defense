# 色彩載體的抗淨化：沒有東西可以保留

`scripts/colour_purify_round.sh`（由 `chain_colour_purify.sh` 接在預算掃描
之後）。**與補丁族同一支 `purify_identity.py`、同一組十二個算子、
共用同一個空白地板**（`runs/ip2p_purify_identity` 的 `floor` 臂），
故兩張表可以並列。

存在的理由：`runs/ip2p_color_capacity_purify` 曾報「十個算子全部保留 93–116%」，
但那是**位移讀數**、全圖載體、半徑 0.10。而 `docs/DEFECTS.md` 記過位移在抗淨化
上會給出過度樂觀的圖（補丁族位移保留 21–81%，身分只有 1–101%）。

## 結果（身分讀數，中位降幅）

| 算子 | `r06`（半徑 0.6） | `r20`（半徑 2.0） | **隨機 `r20_rand`** |
|---|---|---|---|
| 無淨化 | +0.014 | +0.081 | −0.015 |
| `quantize8` | +0.068 | +0.130 | **+0.105** |
| `blur1.5` | +0.015 | +0.011 | **+0.027** |
| `resize_only` | +0.011 | +0.138（n=5） | −0.000 |
| `rotate10` | +0.021 | +0.013 | −0.003 |
| `crop_resize0.1` | +0.002 | +0.006 | −0.004 |
| `jpeg90` | −0.009 | −0.003 | −0.008 |
| `jpeg75` | −0.001 | +0.010 | −0.006 |
| `adverse_cleaner` | +0.009 | −0.003 | −0.015 |

**全部落在雜訊裡，而且隨機臂在好幾欄上更高。**

`quantize8` 那一欄的 +0.068～+0.130 是**量化本身破壞了編輯**——補丁族的空白
地板在該欄就有 +0.055——不是防禦。

## 為什麼「保留率」在這裡沒有意義

保留率的分母是未淨化時的效果，而色彩載體未淨化時就只有 +0.014
（隨機是 −0.015）。**分母在雜訊裡，比值不可解讀。**

`ip2p_color_capacity_purify` 的 93–116% 因此是位移讀數的假象：
位移量的是「兩張編輯輸出差多少」，而色彩映射本來就會讓輸出差很多，
與有沒有防禦無關。
